# Phase 16 — UI Design Contract

> Visual and interaction contract for the admin mode (`?admin=1`) of the React dashboard. Generated by bm-ui-researcher (--auto, non-interactive), verified by bm-ui-checker. Assumptions are marked `[assumed]` and listed at the end.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not applicable: the project uses the company `kone-design-system` component library with Tailwind; no `components.json`) |
| Preset | not applicable |
| Component library | `kone-design-system` (file tarball dependency): use `Button`, `ButtonGroup`, `Badge`, `Banner`, `Checkbox`, `Snackbar`/`Message`, `Divider`, `Tooltip`. No new UI package. |
| Icon library | the design system's icon font classes (`icon-*`, rendered as `<span className="icon-… " aria-hidden />`, as in `StateBadge.tsx`) |
| Font | Inter (`--font-family-base`: "Inter", "Helvetica Neue", Arial, sans-serif) |

Rules: all colors come from the existing Tailwind token classes (`bg-surface`, `bg-subtle`, `text-fg-primary`, `text-brand`, `bg-warning-light`, `danger` via `Button`/`Badge` props). No hard-coded hex in new components except the vis-network canvas selection overlay (canvas cannot read CSS variables; reuse the hexes already in `index.css`: brand `#1450f5`, danger `#e5252a`).

## Spacing Scale

Declared values (multiples of 4), expressed as Tailwind classes:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`p-1`, `gap-1`) | Icon gaps, badge inset next to a tree row label |
| sm | 8px (`p-2`, `gap-2`) | Gap between action-bar buttons, dialog host-list row padding |
| md | 16px (`p-4`, `gap-4`) | Action bar padding, dialog body padding |
| lg | 24px (`p-6`) | Dialog section padding |
| xl | 32px | Not used in this phase |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions: banner and action bar use fixed heights of 40px and 56px respectively (multiples of 4); the dialog host list is capped at `max-h-60` (240px) and scrolls.

## Typography

Sizes are the design system tokens already in use (`text-xs/sm/base/lg`). Exactly four sizes, two weights (400 regular, 600 semibold).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (dialog text, host names, ack text) | 14px (`text-base`) | 400 | 1.5 |
| Label (button labels, badge text, count chips, banner text) | 13px (`text-sm`) | 600 | 1.5 |
| Caption (faked badge, helper/footnote text, selection count in tree) | 12px (`text-xs`) | 400 | 1.5 |
| Heading (dialog title) | 20px (`text-xl`) | 600 | 1.2 |

Host names and IPs in the confirm dialog list use the same body size, no monospace.

## Color

Existing neutral/brand palette of the light theme (Phase 11.1); the dark theme follows via the same tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg-canvas-default` / `--color-bg-surface-default` (white in light theme) | Page, map, dialog surface |
| Secondary (30%) | `--color-bg-surface-subtle-default` (`bg-subtle`) | Admin action bar, tree rows on hover, dialog host-list well |
| Accent (10%) | brand blue `--color-brand-default` (`#1450f5`) | See reserved list |
| Warning surface | `--color-warning-light` / `--color-warning-default` (orange) | The ADMIN MODE banner only |
| Destructive | danger red (`Button color="danger"`, `#e5252a`) | DOWN and UNREACHABLE confirm buttons, Restore all confirm button |

Accent reserved for (brand blue only):
1. Selected-host ring on the topology map (3px border) and selected tree row highlight (left 4px bar plus `bg-brand-light`)
2. Primary confirm button when action is UP or Restore selected
3. Keyboard focus ring (`shadow-focus`)

Rules:
- Faked badge is NOT accent and NOT danger: neutral outline `Badge` with the label `FAKED`, so it never competes with the real state badge (which stays in the existing success/danger colors).
- Warning orange is used only on the persistent ADMIN MODE banner, so the admin view is unmistakably different from a normal dashboard without recoloring the map or incident list (the demo audience may see this screen; the banner is the only extra chrome).
- State colors for fake results are the existing `stateMapping.ts` colors: no new state color.

## Layout and Interaction Contract

### Admin entry and exclusivity
- Admin mode is active only when `?admin=1` is present at page load (read once at startup, per research Pattern 5). Without it, none of the admin UI exists in the DOM and no extra pane or control renders.
- Admin mode and topology edit mode are mutually exclusive. The topology edit toggle is disabled with tooltip "Unavailable in admin mode" while `?admin=1`. [assumed: admin wins; simplest non-conflicting choice]

### Banner (D-14)
- Full-width strip above the three-pane layout, 40px high, `bg-warning-light`, `text-fg-primary`, 13px semibold, with a warning icon (`icon-warning` class, aria-hidden). Rendered with the design system `Banner` (status warning) if its API allows a non-dismissible variant; otherwise a styled `div role="status"`.
- Text: `ADMIN MODE - {N} hosts faked` (N = size of `admin/faked`); singular `ADMIN MODE - 1 host faked`; when 0: `ADMIN MODE - no hosts faked`.
- Persistent: not dismissible, `position: sticky; top: 0`, always visible in admin view only.

### Selection (ctrl+click, map and tree)
- (amended 2026-10-02, gap closure 16-10) In admin mode a plain click on a map node or tree host row selects exactly that host (it replaces the selection) and never navigates or opens host details; no host details pane is shown in admin mode, even with `?host=` in the URL. Ctrl/Cmd+click toggles a host in the selection set. (amended 2026-10-02, quick 261002-nbm) A plain click on empty map canvas (not on a node or edge) clears the selection; ctrl/cmd+click on empty canvas and a click on an edge change nothing. Escape and Clear selection also clear it. Outside admin mode clicks behave as before.
- Map: selected nodes get a 3px brand ring and stay selected across data refreshes. Faked hosts show a small `FAKED` caption badge under the node label (admin view only).
- Tree: host rows show a `Checkbox` (16px) in admin mode (visible only in admin mode) that mirrors selection; ctrl+click on the row also toggles. Faked hosts show the `FAKED` badge (12px) right after the state badge.
- Folder rows: a tri-state `Checkbox` (checked, unchecked, indeterminate) selects or deselects all hosts whose folder equals or is under that folder (subfolders included, per research Open Question 3). Label tooltip: "Select all hosts in this folder". Next to the folder name a muted `{k}/{n} selected` caption (12px) appears when k > 0.
- The unmanaged switch row/node is selectable like any host but has no special action (D-03). The selection set is the single source: map and tree reflect it identically.

### Admin action bar
- Placement: docked bar at the bottom of the viewport spanning the layout (56px high, `bg-subtle`, top border, `p-4`, `gap-2`), visible in admin mode only, always rendered (so layout does not jump).
- Left: selection summary `{N} selected` (13px semibold) and a text `Button` (variant ghost) `Clear selection` followed by `Select all` (amended 2026-10-02, gap closure 16-10: selects exactly the hosts the dashboard currently lists, replacing the selection, so hidden hosts are never selected; disabled when nothing is listed or all listed hosts are already selected). When N = 0 the summary reads `No hosts selected` and the four action buttons are disabled.
- Center, a `ButtonGroup` in this order: `Set UP`, `Set DOWN`, `Set UNREACHABLE`, `Restore selected`.
- Right: `Restore all` (secondary variant, always enabled when `admin/faked` is non-empty; independent of selection) and the last-ack indicator (see below).
- Keyboard: buttons are tab-reachable in the order above; no global shortcuts (avoid accidental fakes during a demo). [assumed]

### Confirm dialog (D-13)
- Every action opens a modal dialog (focus trapped, Escape and scrim click = cancel, initial focus on Cancel). Nothing is sent before confirm.
- Content: title (20px semibold), one sentence of effect, then the exact host list in a scrollable well (`bg-subtle`, `max-h-60`, one host per row, 14px) headed `{N} hosts`.
- Effect sentences:
  - UP: `Mark these hosts and their PING service as UP. Active checks stay disabled until you restore them.`
  - DOWN: `Mark these hosts DOWN. Managed hosts below them become UNREACHABLE; hosts behind an unmanaged switch are not changed unless selected.`
  - UNREACHABLE: `Mark these hosts UNREACHABLE. Active checks stay disabled until you restore them.`
  - Restore selected / Restore all: `Return {N hosts} to the demo baseline: UP with PING OK. The host check is re-enabled, the PING check stays disabled.` / Restore all: `Return all {n} faked hosts to the demo baseline: UP with PING OK.` (amended 2026-10-02, gap closure 16-10)
- When a DOWN cascade applies, the list is split into `Selected ({a})` and `Also set UNREACHABLE ({b})` sections, computed in the browser from the same rule as the poller (the poller remains authoritative and its ack lists what it actually applied). [assumed]
- Buttons: `Cancel` (secondary, left) and the confirm button (right) labelled with the action, e.g. `Set 3 hosts DOWN`. Confirm color: danger for DOWN, UNREACHABLE, Restore all; brand (primary) for UP and Restore selected. No extra warning text about notifications (D-14).
- While waiting for the ack the confirm button shows a spinner state and is disabled; the dialog closes on ack.

### Ack and result feedback (D-08)
- Result shown by a `Snackbar` (bottom-left, above the action bar, auto-hide after 6s; errors stay until dismissed):
  - Success: `Sent: {N} hosts set {UP|DOWN|UNREACHABLE}` or `Sent: {N} hosts restored`. Wording is "Sent", never "confirmed" (Livestatus gives no confirmation; truth appears on the next poll).
  - Failure: `Could not apply: {reason from ack}. Nothing changed. Try again in a few seconds.`
  - No ack within 15 seconds: `No answer from the poller. Check that it is running, then try again.`
- The action bar's right side keeps a compact last-result line (12px, muted): `Last: {action} {N} hosts, {hh:mm:ss}`.

### Accessibility
- Banner has `role="status"`; Snackbar uses `aria-live="polite"` (errors `assertive`).
- Selected state is never color-only: map selected nodes get ring plus a checkmark glyph in the label; tree rows show the checkbox.
- Dialog: `role="dialog" aria-modal="true"`, labelled by the title; targets at least 32px high.
- FAKED badge text is the signal; color is neutral.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (action bar) | `Set DOWN` (with siblings `Set UP`, `Set UNREACHABLE`, `Restore selected`) |
| Confirm CTA | `Set {N} hosts DOWN` / `Set {N} hosts UP` / `Set {N} hosts UNREACHABLE` / `Restore {N} hosts` / `Restore all {N} faked hosts` |
| Empty state heading (nothing selected) | `No hosts selected` |
| Empty state body | `Click a host on the map or in the tree to select it, Ctrl+click to add more, or tick a folder, then choose an action.` (amended 2026-10-02, gap closure 16-10) |
| Empty faked state (Restore all disabled) | `No hosts are faked` (tooltip on disabled Restore all) |
| Error state | `Could not apply: {reason}. Nothing changed. Try again in a few seconds.` |
| Admin config unreachable | `Admin login unavailable. Reload the page, or check that the dashboard container has the admin password configured.` (Banner, danger status, replaces the ADMIN MODE banner; action bar disabled) |
| Banner | `ADMIN MODE - {N} hosts faked` |
| Faked badge | `FAKED` |
| Destructive confirmation | `Set DOWN`: `Mark {N} hosts DOWN. Managed hosts below them become UNREACHABLE.` followed by the host list; confirm button `Set {N} hosts DOWN`. `Restore all`: `Return all {N} faked hosts to the demo baseline: UP with PING OK.` (amended 2026-10-02, gap closure 16-10) |

Destructive actions in this phase: Set DOWN, Set UNREACHABLE, Restore all (each via the confirm dialog above; no typed confirmation).

## Assumptions (auto mode, to confirm in checker or UAT)

1. Admin wins over topology edit mode (edit toggle disabled in admin).
2. Escape clears selection; no other shortcuts.
3. Browser previews the cascade in the dialog; poller stays authoritative.
4. Folder checkbox includes subfolders (research Open Question 3 recommendation).
5. Open Question 1 (wsadmin reads `lan/#`) is assumed yes so the admin page shows normal data; the UI contract needs no second connection.
6. `Banner`/`Snackbar` props of `kone-design-system` may differ from the usage above; executor falls back to a styled element with the same tokens if so.
7. A small icon class for warning (`icon-warning`) must exist in the design-system icon font; the executor verifies the name and picks the nearest existing one.
