<objective>
Implement DASH-16: in the existing edit mode, an operator sets a host's criticality tier, per-service criticality, and depends-on links, written as Checkmk host labels through the same scoped credential and single Apply flow as DASH-12 (D-05, D-06, D-07, D-08).

Purpose: capture business knowledge Checkmk cannot infer; it then flows back to all viewers via the poller (plan 14-07).
Output: label write helpers in checkmkWrite.ts, a CriticalityEditor panel, host selection from the map in edit mode, IndexRoute wiring.

Decisions settled here:
- UI-SPEC "Set button" ambiguity: there is NO per-field Set/Save button. Every Select/MultiSelect change auto-writes immediately (optimistic local state), exactly like a map drag auto-writes; the one primary action remains "Apply changes". UI-SPEC accent use (b) therefore does not occur in this panel.
- Panel placement: a sibling mounted by IndexRoute directly below TopologyToolbar inside the existing touch-tracked wrapper, shown only while `editMode && isTopologyEditingConfigured()` (UI-SPEC allowed either placement; this keeps TopologyToolbar untouched). No second switch, no second pending counter, no second Apply button (D-06/D-07).
- Host selection: map-node click while in edit mode (new `onSelectHost` prop) plus a "Device" Select inside the panel. Tree rows are NOT repurposed in edit mode — they are navigation links (DASH-11) and dimming links (DASH-15); the panel's own device picker covers selection without changing that behaviour.
- Per-service rows list the host's service descriptions from the store's `services[host]` (the same rows the details page shows) plus any service already present in the host's service_criticality label, so a stale entry can still be cleared. Options: Default (removes the entry), Low, Medium, High, Critical.
</objective>
