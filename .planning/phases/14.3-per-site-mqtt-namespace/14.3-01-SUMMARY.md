# Phase 14.3 Plan 01: Poller per-site MQTT namespace Summary

Poller publishes, subscribes and registers its Last Will exclusively under `sites/<CMK_SITE_ID>/`, with `set_site_id()`/`site_topic()`/`relative_topic()` helpers and strict site-id validation.

## What changed
- `set_site_id` validates with `fullmatch` on `[A-Za-z][A-Za-z0-9_]{0,15}`; `site_topic` raises RuntimeError if unset (no unprefixed publish possible); `relative_topic` strips only this site's prefix.
- All topic builders, publishers, will_set, admin subscribe/match and `reconcile_state` subscriptions go through `site_topic()`. `reconcile_state.on_message` parses against the relative topic and ignores unprefixed topics (legacy branch is Plan 04).
- `main()` exits 2 with a CMK_SITE_ID error on invalid id; logs a WARNING when CMK_SITE_ID is unset (falls back to dmc).
- Tests: autouse `_site_id` fixture, new prefix/validation/main tests, existing topic assertions updated hit by hit (`lan/rogue` device-id lines untouched, count 4). Smoke script gained `--site-id` and `set_site_id` before any check.
