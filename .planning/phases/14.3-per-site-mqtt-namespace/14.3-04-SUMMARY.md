# Phase 14.3 Plan 04: Legacy retained topic sweep Summary

After the upgrade the poller clears every non-empty retained pre-14.3 `lan/*` topic and the legacy `admin/faked` exactly once, behind the existing `allow_stale_sweep` gate, and seeds `admin_faked` from the legacy payload when the new one is absent.

## What changed
- `PollerState.legacy_retained_topics` added.
- `reconcile_state` subscribes `lan/#` and exact `admin/faked` (never `admin/#`) before the topology subscribe; unprefixed retained non-empty messages are recorded; `admin_faked` prefers the new-namespace payload, falls back to the legacy one (INFO log).
- `publish_raw_tombstone` refuses `sites/` topics; `run_cycle` sweeps the set sorted inside `if allow_stale_sweep:` then resets it, with no events.
- Tests: `_make_message` gained `retain=True`; 10 new tests cover collection, retain/empty filtering, isolation from site state, subscribe order, admin_faked precedence/fallback, sweep once, gate off, raw tombstone refusal, no events.
