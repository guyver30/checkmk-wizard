# Phase 14.3: Code Review Report

**Reviewed:** 2026-10-04
**Depth:** standard
**Files Reviewed:** 20
**Status:** issues_found

## Summary

The per-site namespace change is sound. Site id validation is consistent across the layers: the shell script (charset check, then shape check, both before `sed`), the Python poller (`fullmatch`), and the TS `runtimeConfig` regex. The prefix match keeps its trailing slash, so site `dmc` cannot match `dmcx`. The ACL render fails closed. The legacy sweep refuses `sites/` topics. `should_publish` starts with `_last_published=None`, so the faked map seeded from the legacy topic is republished into the new namespace before the legacy topic is cleared. I found no BLOCKER-level defects. The remaining issues are about the temporary legacy grants and the sweep's blast radius. I did not run the tests or the convention checker.

## Warnings

### WR-01: Temporary legacy poller ACL grants have no removal mechanism

**File:** `deploy/mosquitto.acl.template:355-358`
**Issue:** The poller keeps `readwrite lan/#` and `readwrite admin/#` indefinitely. The only trigger for removing them is a TODO comment. The poller's own credential can therefore still read and write the old shared namespace, and `admin/#` includes the legacy `admin/cmd`. This weakens the per-site isolation the phase was meant to deliver. `check_poller_legacy_write` in the smoke test asserts that the grant exists, so removing it later breaks the smoke test unless that check is updated at the same time.
**Fix:** Track the removal as a dated roadmap or todo item. Better, gate the legacy lines behind a render-time flag (for example `LEGACY_SWEEP=1` in `deploy/.env`) so the default rendering is narrow. If you do that, make `check_poller_legacy_write` conditional on the same flag.

### WR-02: Legacy sweep tombstones every retained `lan/*` topic on a shared broker

**File:** `scripts/mqtt_poller.py:4114-4119, 4372-4382`
**Issue:** The poller subscribes to `lan/#` and clears every non-empty retained legacy topic once, with no ownership check. If another, not-yet-upgraded site's poller still publishes un-namespaced topics to the same broker (the multi-site scenario this phase targets), the upgraded poller silently wipes that site's retained state. The old poller republishes only on change, so the data stays missing until the next change. The log line also reports `len(state.legacy_retained_topics)` as "Cleared" even when `publish_raw_tombstone` swallowed a failure, which is misleading.
**Fix:** Document that the cutover must be done for all sites on a broker at once. Optionally add an env opt-in (`MQTT_SWEEP_LEGACY=1`) so the destructive sweep is not automatic. Have `publish_raw_tombstone` return a bool and log the count of actual successes.

### WR-03: Legacy `admin/faked` is accepted from an unauthenticated-namespace source

**File:** `scripts/mqtt_poller.py:4116-4118, 4207-4213`
**Issue:** When the new-namespace `admin/faked` is absent, the poller seeds its fake-state ledger from the legacy un-namespaced `admin/faked` payload. This topic is writable by any client that holds a legacy grant. After this phase only the poller has one, so the exposure is low. However, the seed comes from a topic that is documented as stale and about to be deleted. If it is stale, it can resurrect fake host states that were already cleared. The effect is limited to the ledger-mode path (`use_ledger`).
**Fix:** Seed from the legacy topic only on the first post-upgrade start, which is when `legacy_retained_topics` was non-empty and the new topic was absent. That is already the effective behavior. Add a test that a second start, after the sweep, does not re-seed. Consider also bounding the seed's age using the payload `timestamp`.

## Info

### IN-01: Dead or contradictory CMK_SITE_ID warning

**File:** `scripts/mqtt_poller.py:4757-4766`
**Issue:** `compose.yaml` always injects `CMK_SITE_ID=${CMK_SITE_ID:-dmc}`, so the "not set; using default" warning can never fire in the compose deployment. It only fires in ad-hoc runs. Also, `configure_logging` runs after it, so the warning goes through the logging last-resort handler.
**Fix:** Move the check after `configure_logging`, or drop it.

### IN-02: Equality between a relative suffix and a legacy full topic is implicit

**File:** `scripts/mqtt_poller.py:4108-4118`
**Issue:** `msg.topic == TOPIC_ADMIN_FAKED` is used as the legacy full-topic comparison. It works only because the relative suffix and the legacy topic are the same string. A comment notes this, but renaming the constant would silently change the legacy match.
**Fix:** Add a separate `LEGACY_TOPIC_ADMIN_FAKED = "admin/faked"` constant.
