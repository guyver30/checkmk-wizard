# Phase 14.3: Per-site MQTT Namespace - Context

**Gathered:** 2026-10-04
**Status:** Ready for planning
**Source:** Conversation decisions (user agreed to all defaults, "go straight to plan"); no discuss-phase run

<domain>
## Phase Boundary

Move every MQTT topic the poller, dashboard and admin mode use under a per-site prefix `sites/<site_id>/`, so many sites can share one cloud broker. Runs BEFORE Phase 14.2 (numbered 14.3 only because the insert workflow takes the next free decimal). Rationale: docs/MQTT-CONTRACT-WALKTHROUGH.md Part 4 says renaming topics later is painful; the rest of the transport work (per-event messages, last_check dedup, gzip, aggregation, status-by-exception, bridging) stays in a later separate phase and is OUT of scope here.

Out of scope: per-site broker users, bridging, history-over-MQTT, any payload change.
</domain>

<decisions>
## Implementation Decisions (locked)

### Topic shape
- Every existing topic keeps its suffix and gains the prefix: `sites/<site_id>/lan/devices/{id}/status`, `.../services`, `.../history`, `.../service_history`, `sites/<site_id>/lan/devices/topology`, `sites/<site_id>/lan/events/recent`, `sites/<site_id>/lan/incidents/{incident_id}/status`, `sites/<site_id>/lan/poller/status` (including the poller's Last Will).
- Admin topics: `sites/<site_id>/admin/cmd`, `sites/<site_id>/admin/ack`, `sites/<site_id>/admin/faked`.
- Phase 14.2's new needs topic will be `sites/<site_id>/lan/needs/{need_id}/status` (14.2 must build on this; record it in 14.2 CONTEXT later).
- Payloads are unchanged.

### site_id
- `site_id` is exactly the Checkmk site id. The poller reads it from its existing site setting (planner: confirm the exact env var, believed `CMK_SITE_ID`, in scripts/mqtt_poller.py and deploy/compose + deploy/.env.example). The dashboard gets it at runtime from its `/config.json` (served by nginx from deploy/.env), never hard-coded in the bundle.
- The dashboard subscribes to ONE site's subtree.
- Validate site_id as safe for a topic level (no `/`, `+`, `#`, whitespace); fail loudly at poller startup if invalid.

### ACLs (deploy/mosquitto.acl)
- `wsreader` reads `sites/<site_id>/lan/#` (replacing `lan/#`); `wsadmin` reads `sites/<site_id>/lan/#` and `sites/<site_id>/admin/ack|faked`, writes `sites/<site_id>/admin/cmd`; the poller user keeps write on its site subtree and read on `sites/<site_id>/admin/cmd`. Broker config stays per-deployment (one site per deployment); per-site users are a cloud-phase concern. Planner: mosquitto ACL files can use `%u`-style patterns but the site id is deployment config, so decide how the ACL gets the site id (template at deploy time vs wildcard `sites/+/...`) and justify.

### Migration
- On startup the poller's existing stale-retained sweep (quick 260925-b81) must ALSO clear the old un-namespaced retained `lan/*` (and `admin/*`) topics once, gated on the same trustworthy-Checkmk-answer rule, so nothing is orphaned on the broker after upgrade. Document that an old dashboard image will show nothing after the poller upgrade (deploy both together, full `podman compose down && up -d` — NEVER restart a single container on dmc-server).

### Unique site names
- Not enforceable by the wizard (no central registry). Add a warning in the wizard's site-name prompt and a docs note that the site name becomes the MQTT namespace and must be globally unique across every site feeding one broker. Real enforcement is a cloud-phase concern.

### Defaults chosen after research (2026-10-04, from 14.3-RESEARCH.md A1-A5; user may overrule at plan review)
- A1: poller uses a module-level `set_site_id()` + one `topic()` helper (no touching ~40 publish_* call sites); dashboard strips the `sites/<id>/` prefix once in `mqttClient.ts` so store code and store tests stay unchanged.
- A2: keep the `dmc` default for `CMK_SITE_ID` but log a loud startup warning when the env var is unset.
- A3: strict site-id regex `^[A-Za-z][A-Za-z0-9_]{0,15}$` (same as `runtimeConfig.ts`, `init-env.sh`, `wizard._SITE_NAME_RE`), `fullmatch` in the poller.
- A4: cutover state: seed the poller's `admin_faked` from the legacy retained `admin/faked` before clearing it (so injected fake states are not orphaned); topology/events/history/incidents are NOT carried over (they are rebuilt from Checkmk on the first cycles). Document "run Restore All before upgrading" as the operator's belt-and-braces step.
- A5: ACL is rendered at mosquitto container start from `deploy/mosquitto.acl.template` using `CMK_SITE_ID` (add it to the mosquitto service env; guard with the regex before `sed`). The poller keeps TEMPORARY `readwrite lan/#` and `readwrite admin/#` grants so the legacy tombstones are not silently dropped by the broker; mark them with a removal TODO, to be dropped in a later phase. A live `smoke_test_broker.py` run against the rendered ACL is a required verification step (human checkpoint).
- Trap: tests use `lan/rogue` as an unsafe device id (tests/test_mqtt_poller.py ~78, 2171, 2175, 2318); do not blanket-replace `lan/`.
- An `omd mv` site rename now changes the namespace and orphans the old subtree: document it.

### Claude's Discretion

- Test strategy: update tests/test_mqtt_poller.py, scripts/smoke_test_poller.py, scripts/smoke_test_broker.py, dashboard vitest suites that assert topic strings.

</decisions>
