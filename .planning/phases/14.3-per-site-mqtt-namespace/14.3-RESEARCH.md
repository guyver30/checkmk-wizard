## Summary

The change is mechanical but wide: the poller builds topics in ONE place (module constants at `scripts/mqtt_poller.py:116-123` and five `*_topic()` helpers at `:699-716`), but topic strings are also hand-parsed in `reconcile_state` (`:4037-4066`) and subscribed by literal in `:4093-4100`. The dashboard has the same shape: literals in `mqttClient.ts:40-48` and `useAppStore.ts:234,243,259` plus positional `parts[1..3]` parsing. The cleanest dashboard design is to strip the `sites/<id>/` prefix once in `mqttClient.ts` before dispatching to the stores, so the two stores and roughly 90 store/component test assertions stay unchanged.

The site id is already available everywhere: `CMK_SITE_ID` (default `dmc`) feeds `PollerConfig.cmk_site_id` (`mqtt_poller.py:401,493`), the dashboard's `/config.json` key `checkmkSite` (already regex-validated client-side with `^[A-Za-z][A-Za-z0-9_]{0,15}$`, `runtimeConfig.ts:25`), and `deploy/init-env.sh:69-86` already enforces the same regex on `CMK_SITE_ID`. That regex excludes `/ + #` and whitespace, so a poller startup check with the same regex satisfies the "topic-safe" decision.

Mosquitto ACL files do NOT support env var expansion or templating (only `%u` and `%c`, which do not carry a site id). Recommendation: generate the ACL at container start from a template, in the mosquitto service's existing shell entrypoint that already generates the passwd file. See "ACL" below.

**Primary recommendation:** one process = one site, so add a small module-level topic builder to the poller (set once from validated `CMK_SITE_ID`), strip the prefix once in the dashboard's `mqttClient.ts`, template the ACL in the mosquitto entrypoint, and extend the existing sweep with a legacy-topic collector in `reconcile_state`/`run_cycle`.

## ACL: options and recommendation

Verified against the Mosquitto docs (mosquitto.org/man/mosquitto-conf-5.html): ACL lines are `user <name>` then `topic [read|write|readwrite|deny] <topic>`; `pattern` lines support only `%c` (client id) and `%u` (username), which must be the only text on their topic level; `+` and `#` work as in subscriptions; no environment-variable expansion or templating is documented. [CITED: mosquitto.org/man/mosquitto-conf-5.html]

| Option | Verdict |
|--------|---------|
| `%u` pattern | Not applicable: usernames are `poller`/`wsreader`/`wsadmin`, not site ids. |
| Wildcard `sites/+/lan/#` | Works with zero deploy changes, but any dashboard user could read any site's subtree on a shared broker; since broker config is per-deployment (one site per deployment) there is nothing else on the broker today, so the leak is theoretical now. |
| Render ACL at container start (recommended) | `deploy/compose.yaml`'s mosquitto entrypoint is already `/bin/sh -c` and already generates `mosquitto.passwd` (`:105-113`) with `umask 077`, `chown mosquitto:mosquitto`, `chmod 0700`. Add `CMK_SITE_ID` to the service `environment:`, rename the repo file to `deploy/mosquitto.acl.template` using a placeholder token such as `@SITE_ID@`, mount it read-only at a different path (e.g. `/mosquitto/acl.template`), and `sed "s/@SITE_ID@/$$CMK_SITE_ID/g"` it into `/mosquitto/config/mosquitto.acl` with the same chown/chmod. `mosquitto.conf:19` (`acl_file /mosquitto/config/mosquitto.acl`) stays unchanged. Safe for sed because init-env.sh's regex allows only `[A-Za-z0-9_]`; also validate in the entrypoint (`case`/grep) and fail the container start if invalid. |

Justification: exact grants match the locked decision text, the broker already follows a "generate secrets/config in the entrypoint" pattern, and per-site users later reuse the same mechanism. Compose gotcha: in compose YAML a literal `$` for the shell must be `$$` (as the existing entrypoint does). Because the `:ro,z` bind mount of the old `mosquitto.acl` at `/mosquitto/config/mosquitto.acl` would collide with the generated file, the volume line at `compose.yaml:120` must be replaced, not kept.

Rendered ACL (with `S` = site id):
```
user poller
topic readwrite sites/S/#
# TEMPORARY legacy grants so the poller can clear pre-14.3 retained topics (see Migration):
topic readwrite lan/#
topic readwrite admin/#

user wsreader
topic read sites/S/lan/#

user wsadmin
topic read sites/S/lan/#
topic read sites/S/admin/ack
topic read sites/S/admin/faked
topic write sites/S/admin/cmd
```
IMPORTANT: the current poller grant is `readwrite #`. Narrowing it to the site subtree as the CONTEXT says would stop the poller from tombstoning legacy topics (an unauthorized publish is silently dropped by Mosquitto for MQTT 3.1.1 clients; `wait_for_publish` would not error). So either keep the legacy `lan/#` and `admin/#` grants in this phase and remove them in a later cleanup, or keep `readwrite #`. Recommend the explicit legacy lines with a removal comment. The poller also needs read on `sites/S/admin/cmd` (covered by `readwrite sites/S/#`). Poller user is also used by the short-lived `reconcile_state` client (`config.mqtt_username`), so reads for the legacy subscribe are needed there too.

Existing ACL semantic to preserve: `wsreader` must not see admin topics. `read sites/S/lan/#` does not match `sites/S/admin/...`. `smoke_test_broker.py` already tests wsreader/wsadmin denials and must be updated to the prefixed topics.

## The existing stale sweep (quick 260925-b81) and how to extend it

How it works today:
1. `reconcile_state(config)` (`mqtt_poller.py:3976`) opens a short-lived client (no Will), subscribes wildcards, with `lan/devices/topology` LAST as a barrier, waits up to `reconcile_timeout_seconds` (default 5.0, `:77`) for topology, and collects into `PollerState.retained_ids` the id of every host that has a NON-EMPTY retained `status|history|services|service_history` (4-segment topics only, `is_publishable_device_id`) and open incident ids into `previous_incidents`.
2. `run_cycle(..., allow_stale_sweep)` (`:4255-4271`): when true, tombstones `retained_ids - current_ids - previous_ids` via `publish_tombstone`, emits no "removed" event, then sets `retained_ids = set()` (once per process). When false, the set is left for a later cycle.
3. Gate (`run_forever :4572-4587`, `--once :4772-4779`): `bool(snapshots) or (rest_ok and not host_config)`; a `LivestatusError` skips the cycle entirely.

Extension (recommended):
- Add `PollerState.legacy_retained_topics: set[str]` (default empty set, appended field). In `reconcile_state`, additionally subscribe `lan/#` and the exact topic `admin/faked` (NOT `admin/#`, to avoid receiving live `admin/cmd`), BEFORE the topology subscribe so the barrier still covers them. In `on_message`, record a topic when `msg.retain` is true and the payload is non-empty and the topic is either `admin/faked` or starts with `lan/`. Check `msg.retain` explicitly (a live non-retained message must never be recorded). `admin/cmd` and `admin/ack` are not retained, so only `admin/faked` needs clearing among admin topics.
- In `run_cycle`'s `if allow_stale_sweep:` block, after the device sweep, tombstone every topic in `legacy_retained_topics` (zero-length retained publish, qos 1, `wait_for_publish`, same try/except as `publish_tombstone`) and then empty the set. No live-id subtraction: the whole legacy namespace is stale by definition. Add a small `publish_raw_tombstone(client, topic)`; do not reuse `publish_tombstone`, which builds prefixed topics.
- Legacy topology and poller status are covered by `lan/#` (`lan/devices/topology`, `lan/poller/status`, `lan/events/recent`).
- Same gate, so no new gating logic and no new call-site wiring in `run_forever`/`--once`.
- Cost on first start after upgrade: the new namespace has no topology yet, so `topology_received.wait` runs to the full 5 s timeout once. Harmless (existing cold-start path); mention in docs.
- Must-seed concern (see Pitfall 3): the legacy `admin/faked` (and optionally legacy topology/events/history) should seed state BEFORE being cleared.

Test strategy for the sweep (CONTEXT asks for a fake broker): reuse `_make_message` and the mock-client pattern from the existing tests (`tests/test_mqtt_poller.py:3942-4122`): feed `reconcile_state` retained legacy messages (including one non-retained, one empty payload, one `admin/cmd` not subscribed) and assert `state.legacy_retained_topics`; run `run_cycle` with `allow_stale_sweep=True/False` and assert the exact `publish(topic, payload=None, retain=True, qos=1)` calls, set emptied only when the gate is on, never touching `sites/<id>/...`. Also assert the subscribe order (legacy before topology, mirroring `:3988-3991`). `smoke_test_poller.py` can gain a live check that a seeded `lan/smoketest` retained topic disappears (needs the temporary legacy ACL grant).

## Architecture Patterns

### Recommended structure (small)
```
scripts/mqtt_poller.py          # + SITE prefix setter/validator, topic() helper, legacy sweep
deploy/mosquitto.acl.template   # renamed from mosquitto.acl, @SITE_ID@ placeholder
dashboard-react/src/lib/topics.ts   # sitePrefix/stripPrefix/subscribe lists (new)
```

### Pattern: validate site id once, fail loudly
```python
_SITE_ID_RE = re.compile(r"^[A-Za-z][A-Za-z0-9_]{0,15}$")  # same rule as wizard._SITE_NAME_RE and init-env.sh
def set_site_id(site_id: str) -> None:
    if not _SITE_ID_RE.fullmatch(site_id):
        raise SystemExit(f"Invalid CMK_SITE_ID {site_id!r}: cannot be used as an MQTT topic level")
    global _PREFIX
    _PREFIX = f"sites/{site_id}/"
```
(Use `fullmatch`: `$` matches before a trailing newline.) A looser "topic-safe" rule (anything without `/ + #` whitespace, control chars) is also compliant with CONTEXT, but the stricter Checkmk rule is what `deploy/dashboard-nginx.conf` and `runtimeConfig.ts` already enforce, so one rule everywhere is simplest. [ASSUMED: planner may prefer the looser rule.]

### Pattern: strip once on the dashboard
```ts
client.on("message", (topic, payload) => {
  const rel = stripPrefix(getRuntimeConfig().checkmkSite, topic); // null when not under sites/<id>/
  if (rel === null) return;
  if (rel.startsWith("admin/")) { useAdminStore.getState().handleAdminMessage(rel, payload); return; }
  useAppStore.getState().handleMessage(rel, payload);
});
```
Publish: `client.publish(prefix + ADMIN_TOPIC_CMD, ...)`.

### Anti-patterns
- Building `f"sites/{id}/..."` strings inline in more than one place.
- Subscribing `sites/+/#` on the dashboard (violates "ONE site's subtree"; also fails under the templated ACL).
- Subscribing `admin/#` in the legacy sweep (receives live `admin/cmd`).

## Common Pitfalls

### Pitfall 1: Poller ACL narrowed before the sweep can run
Narrowing `readwrite #` to `sites/S/#` makes the legacy tombstone publishes silently dropped. Keep temporary legacy grants (above) or the sweep appears to work in tests (mock client) but orphans messages live. Verify with `smoke_test_poller.py`/`smoke_test_broker.py` against a real broker.

### Pitfall 2: Positional topic parsing
`reconcile_state` (`:4037-4066`) and `useAppStore.handleMessage` index `parts[0..3]`. Prefixing without stripping shifts everything by 2 and fails silently (messages ignored). Strip the prefix first on both sides, or use a helper that returns the relative topic. Tests: assert a device topic round-trips through reconcile.

### Pitfall 3: State loss at cutover
`reconcile_state` seeds topology, events, history, service_history and `admin_faked` from the broker's retained topics. On first start the new namespace is empty: previous topology (so first cycle may generate "added" events for every host depending on current cold-start behavior), the bounded event feed, per-host history and, notably, `admin/faked` (fake host states already injected into Checkmk via external commands would no longer be tracked by the poller, so `restore_all` would not know about them). Mitigation options: (a) accept and document (ClickHouse holds durable history; admin mode is for demos), tell the operator to run Restore All before upgrading; (b) in `reconcile_state`, if the new `sites/S/...` topic is absent, fall back to the legacy payload for `admin/faked` (cheap: one extra topic, already subscribed for the sweep) and optionally topology/events. Recommend (b) for `admin/faked` only and (a) for the rest; confirm with the user. [ASSUMED]

### Pitfall 4: Old dashboard after poller upgrade
The old image subscribes `lan/#` and, with the new ACL, gets denied (SUBACK failure code) and shows nothing. Document deploying poller + mosquitto + dashboard together via full `podman compose down && up -d` (memory: single-container restart/stop breaks Checkmk egress on dmc-server).

### Pitfall 5: Last Will topic

### Pitfall 6: Unsafe-id tests share the string `lan/rogue`

### Pitfall 7: nginx and `$`/quotes in `/config.json`
No change to `dashboard-nginx.conf` logic is needed (`checkmkSite` already served); only comments change. The site regex already prevents quote/`$` injection.

### Threat Patterns
| Pattern | STRIDE | Mitigation |
|---------|--------|------------|
| Topic injection via site id or device id | Tampering | Regex validation; existing `is_publishable_device_id` |
| Cross-site read on a shared broker | Info disclosure | Templated ACL (exact site) rather than `sites/+/`; per-site users deferred |
| Template/sed injection from `CMK_SITE_ID` | Tampering | Regex guard before `sed`; fail container start if invalid |
| Legacy retained admin state replay | Tampering | Sweep clears `admin/faked`; admin/cmd already ignores retained delivery (`:1658`) |
| Silent publish drop by ACL | Denial of service | Smoke test verifies live; keep legacy grant until sweep complete |
