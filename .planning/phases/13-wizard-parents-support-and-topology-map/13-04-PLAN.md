<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Checkmk REST host_config labels → poller → retained MQTT | Operator/browser-written label text flows into a payload every viewer consumes |
| worker (admin automation user) → Checkmk user/role config | The provisioning script creates a credential that will later ship inside browser JS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-09 | Elevation of Privilege | topology_editor credential embedded in the browser bundle | mitigate | A dedicated role holding ONLY the 13-01 V-PERMS ids (host edit/add, all-folder write, activate own changes); excludes user management, rulesets, global settings and `wato.activateforeign`; never roles ["admin"] (acceptance-criteria greps). Residual risk (a LAN user extracting the secret can edit/add hosts and activate) is accepted under D-04's trusted-LAN, no-multi-user-accounts posture, the same class as WS_USERNAME/WS_PASSWORD, which is read-only by contrast |
| T-13-10 | Information Disclosure | provisioning script output | mitigate | The secret is printed once at creation only; the Authorization header is redacted via redact_auth_header (tested); an existing user is never re-keyed silently |
| T-13-11 | Tampering | label values in the MQTT payload | mitigate | map_position is regex-validated server-side (`^-?\d{1,6},-?\d{1,6}$`) before publishing; unmanaged is a strict `== "yes"` boolean |
| T-13-12 | Denial of Service | retained payload schema skew | mitigate | _normalise_restored_node backfills/type-checks the new keys (tested), preventing the documented 2026-09-11 crash-loop class |
| T-13-13 | Repudiation | edits made through the shared credential | accept | Checkmk's audit log attributes changes to `topology_editor`; single-operator deployment with no per-person accounts by design |
</threat_model>
