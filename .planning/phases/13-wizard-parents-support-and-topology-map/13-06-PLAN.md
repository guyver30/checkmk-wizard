Extend TopologyMap's props with `onEditSaved?: () => void` and `onEditFailed?: (failure: { title: string; body: string }) => void`. Keep the latest values in refs, since the vis callbacks are registered once.

Gating (D-02): a `useEffect` on `[editMode]` updates `editModeRef` and calls `network.setOptions({ manipulation: { enabled: editMode, initiallyActive: editMode, addEdge, editEdge, deleteEdge, addNode, deleteNode: false }, interaction: { dragNodes: editMode, hover: true } })`. Confirm option names such as `initiallyActive` against context7's vis-network manipulation docs.

Edge semantics (UI-SPEC Edge styling): an edge drawn from A to B means "A is B's parent", so it writes to host B.
- addEdge: reject self-loops and duplicates with callback(null). Otherwise await `updateParents(to, ps => [...ps, from])`. On success, call callback with `{ ...data, id: `${from}->${to}` }`, record an overlay add, and call onEditSaved. On failure, call callback(null) and onEditFailed with the "Couldn't save that connection" copy.
- editEdge: look up the old edge in the edge DataSet by `data.id`. If the endpoints are unchanged, callback(null). For the same child, make one `updateParents(child, ps => ps.filter(p => p !== oldFrom).concat(newFrom))`. For a different child, remove the parent from the old child, then add it to the new child, sequentially. On success, remove the old edge id from and add the new edge to the DataSet yourself, update both overlays, call callback(null) (the id changes, so vis must not apply it), then onEditSaved. On failure, show the same copy as addEdge.
- deleteEdge: for each edge id in `data.edges`, build the UI-SPEC confirm text from the node labels: "Remove this connection?", a blank line, then "This removes the parent/child link between {parentLabel} and {childLabel}. It won't take effect until you press Apply changes." If `window.confirm` returns false, callback(null). Otherwise call `updateParents(child, ps => ps.filter(p => p !== parent))`, then callback(data), record an overlay removal, and call onEditSaved. On failure, callback(null) plus the connection copy.

Positions (D-07): register `network.on("dragEnd", ...)` once. When `editModeRef.current` is true, for each dragged id read `network.getPositions([id])[id]` and await `setMapPosition(id, x, y)`. On success, call onEditSaved. On failure, call onEditFailed with title "Couldn't save that position" and body "Checkmk rejected the update. Check that the device still exists, then try again." UI-SPEC does not define this copy; this wording is planner discretion, modelled on the Copywriting Contract's connection error. Record it in the SUMMARY. After a successful save, set that node's `physics: false` in the DataSet so later syncs never move it.

Pending overlay: keep refs `pendingEdgeAdds: Map<edgeId, MapEdge>`, `pendingEdgeRemovals: Set<edgeId>` and `pendingNodeAdds: Map<id, node>` (the last filled by Task 2). In the 13-03 sync effect, treat model edges as `(model.edges minus pendingEdgeRemovals) plus pendingEdgeAdds`, and model nodes as model plus pendingNodeAdds. Prune an add entry once the model contains it, and a removal entry once the model no longer contains it. Explain in a comment that host-attribute PUTs only reach Livestatus, and so the poller's `parents`, after Activate Changes (RESEARCH Pitfall 3), so without the overlay a drawn edge would vanish on the next unrelated topology message.

Never call activateChanges here. Apply is a single batched action owned by 13-07 (RESEARCH Anti-Patterns).

Extend fakeVisNetwork.ts as needed: record every `setOptions` call, expose `lastManipulation()` returning the latest manipulation option object so tests can invoke addEdge/editEdge/deleteEdge/addNode directly, and record calls to `disableEditMode`. In the tests, mock `../lib/checkmkWrite` with `vi.mock` and stub `window.confirm`. Write the tests first (RED), then implement (GREEN).

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-13-08 | Tampering | stray drag/tap on a kiosk display | mitigate | manipulation and dragNodes are enabled only while editMode is true (D-02, tested); click-navigate is suppressed in edit mode; deletes require window.confirm; nothing goes live until an explicit Apply (13-07); an idle auto-exit is added in 13-07 |
| T-13-15 | Tampering / Injection | addNode name | mitigate | isValidHostName plus a duplicate-id check before any write (tested); checkmkWrite additionally encodes path segments |
