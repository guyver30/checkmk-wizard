## Deviations from Plan

1. [Rule 1 - Bug avoidance] Message handling runs on a dispatcher thread rather than in the paho callback (reason above). `on_message` handles inline when no queue exists, which keeps tests synchronous.
2. [Rule 2 - Correctness] ClickHouse-down cycles re-feed the previous trend/sustained candidates (restored needs seed this set at startup); otherwise two failed cycles would tombstone live needs.
3. [Rule 2] An empty `CLICKHOUSE_URL` disables fetch/insert with a startup warning (urllib raises ValueError on an empty URL, outside history's ClickHouseError normalization).
4. Process note: one early file edit used bare `python3` instead of `uv run`; no repository effect.

## Carry-over notes honoured

`smart_allowlist_warning` logged at startup; `missing_tables` result logged with `_MIGRATION_HINT` at startup and in the per-cycle insert warning; auto_reset rows built with `audit_row` (empty actor and command_id); retained triage deliveries ignored; need_id must exist in the tracker; dedup keys come from the recorders in UTC text form; `POLL_INTERVAL_SECONDS` is only consumed by the rollup.

## Known limitations

- Forecast topics orphaned by a restart (host vanished while the service was down) are not tombstoned; the in-process published set starts empty.
- Retained narrations are re-published once after a restart because the change signatures are not seeded from the retained payloads (harmless duplicate retained write).
