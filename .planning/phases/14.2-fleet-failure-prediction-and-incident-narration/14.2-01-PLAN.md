Step 0: `set -a; . ./.env; set +a`

Step 1 (ClickHouse version and part placement, admin user, read-only): `podman exec clickhouse clickhouse-client --user ch_admin --password "$CH_ADMIN_PASSWORD" --query "SELECT version()"` and `podman exec clickhouse clickhouse-client --user ch_admin --password "$CH_ADMIN_PASSWORD" --query "SELECT table, disk_name, count() FROM system.parts WHERE database='history' AND active GROUP BY table, disk_name ORDER BY table, disk_name"`.

Step 2 (metric catalog, last 2 days, grouped so per-filesystem and per-drive services collapse): `podman exec clickhouse clickhouse-client --user ch_admin --password "$CH_ADMIN_PASSWORD" --query "SELECT replaceRegexpOne(service, '^(Filesystem|SMART|Disk IO|Interface|NVMe) .*', '\\1 *') AS svc, metric, uniqExact(host) AS hosts, countIf(warn IS NOT NULL) AS with_warn, countIf(crit IS NOT NULL) AS with_crit, round(min(value),2) AS vmin, round(max(value),2) AS vmax FROM history.metrics WHERE ts >= now() - INTERVAL 2 DAY GROUP BY svc, metric ORDER BY svc, metric FORMAT PrettyCompactMonoBlock"`.

Step 3 (levels direction for SMART/NVMe and memory series, to see whether lower is worse anywhere): `podman exec clickhouse clickhouse-client --user ch_admin --password "$CH_ADMIN_PASSWORD" --query "SELECT service, metric, argMax(value, ts) AS last, argMax(warn, ts) AS warn, argMax(crit, ts) AS crit FROM history.metrics WHERE ts >= now() - INTERVAL 2 DAY AND (service LIKE 'SMART%' OR service LIKE 'NVMe%' OR service = 'Memory' OR service LIKE 'CPU%' OR metric LIKE '%realloc%' OR metric LIKE '%wear%' OR metric LIKE '%percentage_used%' OR metric LIKE '%spare%') GROUP BY service, metric ORDER BY service, metric LIMIT 200 FORMAT PrettyCompactMonoBlock"`.

Step 4 (90-day row volume for the candidate chart metrics; replace the IN list with the metric names from Step 2 that look like filesystem used %, CPU utilization, memory used % and SMART wear/reallocated): `podman exec clickhouse clickhouse-client --user ch_admin --password "$CH_ADMIN_PASSWORD" --query "SELECT count() FROM history.metrics WHERE ts >= now() - INTERVAL 90 DAY AND metric IN ('fs_used_percent','util','mem_used_percent')"`.

Step 5 (/ch-api/ typed parameter pass-through as dashboard_reader through nginx, proves D-20 / research A6): `curl -sG http://localhost:8090/ch-api/ --data-urlencode 'query=SELECT {x:UInt32} + 1 AS y FORMAT TSV' --data-urlencode 'param_x=41'` (expected output: `42`) and `curl -sG http://localhost:8090/ch-api/ --data-urlencode "query=SELECT count() FROM history.metrics WHERE host = {h:String} FORMAT TSV" --data-urlencode "param_h=<any real host name>"` (expected: a number, not an error).
