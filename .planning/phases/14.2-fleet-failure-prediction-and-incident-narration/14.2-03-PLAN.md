<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> broker (wstriage over WebSocket) | untrusted client publishes triage commands |
| any LAN client -> /triage-config.json | triage credential served openly |
| analytics container -> broker | new writer of retained topics under lan/ |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14.2-08 | Elevation of privilege | analytics ACL | mitigate | write limited to lan/needs/#, lan/forecasts/#, lan/incidents/+/narration; exact-grant unit test; live denial check on lan/incidents/+/status |
| T-14.2-09 | Spoofing | /triage-config.json open credential | accept | closed network (16 D-06..D-10, 14.2 D-24); wstriage can only write one topic; analytics validates and audits every command (plan 12); documented in plan 18 |
| T-14.2-10 | Information disclosure | cross-site leak on a shared broker | mitigate | every grant under sites/@SITE_ID@/; test_no_grant_on_bare_wildcard covers new users |
| T-14.2-11 | Information disclosure | secrets in tracked files | mitigate | passwords only in deploy/.env via init-env.sh; compose uses `:?` for broker passwords and `:-` for the ClickHouse one per the existing interpolation convention |
| T-14.2-12 | Tampering | /ch-api/ typed params | mitigate | smoke check proves `param_*` pass-through, so the chart never concatenates SQL |
</threat_model>
