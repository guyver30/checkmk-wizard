# Phase 14.2 — UI Design Contract

> Visual and interaction contract for the Needs pane, tier markers, triage controls (edit mode), the forecast line chart and narrated incident cards. Generated by bm-ui-researcher in --auto mode (no questions asked). Inherits the palette, spacing and type roles of Phases 11.1, 14 and 16 unchanged; only additions are specified here. Kiosk mode does not exist and is not designed for. Assumptions are marked `[assumed]` and listed at the end.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not used; no `components.json`) |
| Preset | not applicable |
| Component library | `kone-design-system` 0.1.0 (existing): `Badge`, `Button`, `Message` (incident card, unchanged), `Select`, `Tooltip`, `Menu`, `SegmentedControl`, `Snackbar`, `Banner`, `Table` (not required). The tab strip of the combined pane is a local element copying `SegmentedControl`'s classes (2026-10-05 (quick 261005-e7b)), because the design-system control has no disabled option, no keyboard navigation, no aria-controls/tabpanel linkage and string-only labels. No chart component exists; the chart is a hand-written SVG component (`ForecastChart.tsx`) using `d3-scale` for scales and ticks only. |
| Icon library | existing `icon-*` mask classes (`<span className="icon-… " aria-hidden />`). No new icon is required; use the nearest existing glyphs (trend/arrow, close, chevron) and verify names at execution. |
| Font | Inter (`--font-family-base`) |

Rules: every color in new components comes from Tailwind token classes (`bg-surface`, `bg-subtle`, `text-fg-primary`, `text-fg-secondary`, `text-fg-tertiary`, `text-warning`, `text-alert`, `text-brand`, `border-*`). SVG uses `stroke="currentColor"` / `fill="currentColor"` with a token text class on the element, so light and dark themes work with no hex and no theme branch. No hard-coded hex anywhere in this phase (the chart is SVG, not canvas).

## Spacing Scale

Multiples of 4, as Tailwind classes. Inherited scale; no new token.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`, `p-1`) | Gap between tier badge and confidence badge; tier marker inset on tree rows |
| sm | 8px (`gap-2`, `p-2`) | Gap between Needs rows; gap between triage buttons; chart legend item gap |
| md | 16px (`p-4`, `gap-4`) | Needs pane padding; chart container padding; chart header to plot gap |
| lg | 24px (`p-6`) | Chart dialog body padding |
| xl | 32px | Not used |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions: the chart plot margins are 48px left (value axis labels), 16px top, 16px right, 32px bottom (date axis labels); chart plot height is 240px; Needs row minimum height 56px; tier marker is a 8px dot or 16px chip (both multiples of 4).

## Color

Inherited light/dark token palette. Nothing is redefined.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-canvas` / `bg-surface` | Page, Needs pane, chart surface |
| Secondary (30%) | `bg-subtle` | Needs pane header, row hover, chart header strip, host-details Needs section |
| Accent (10%) | brand blue `--color-brand-default` | See reserved list |
| Destructive | `--color-alert-default` | Crit level line and crit crossing marker only; "Cancel need" is not red (it is reversible by recurrence, and not a delete) |

Accent reserved for (brand blue only):
1. Keyboard focus ring on Needs rows, triage controls and chart metric picker
2. Selected Needs row (left 4px bar plus `bg-brand-light`), same pattern as the selected tree row
3. The measured-history line in the forecast chart is NOT brand; it is `text-fg-primary` (see Chart). Brand is not used for data.

### Tier palette (new dimension; deliberately not red, not purple)

Tier (service-need urgency) is a third dimension, independent of device state (red/orange/green) and of business criticality (neutral/purple, Phase 14). To avoid being read as either, tier uses the warning hue family only, with escalating weight, and always carries a text label.

| Tier | `Badge` color | Variant | Label | Tree/map marker |
|------|---------------|---------|-------|-----------------|
| immediate | `warning` | `solid` | Immediate | 8px filled dot, `bg-alert` (red; amended 2026-10-05, was `bg-warning`) |
| urgent | `warning` | `soft` | Urgent | 8px filled dot, `bg-warning` (orange; amended 2026-10-05, was a ring) |
| standard | `neutral` | `outline` | Standard | 8px filled dot, fixed yellow `#facc15` (no design-system yellow token; amended 2026-10-05, was no marker) |

Rules: a tier marker never replaces or recolors the state badge or the map node border; it is a separate 8px element at the top-right of the tree row's right-side badges (tree) and as a small overlay dot at the node's top-right (map, `[assumed]` drawn through the existing node label/overlay mechanism; if vis-network cannot draw it, omit the map marker and keep the tree marker plus Needs pane). A host with several needs shows the worst tier.

### Confidence badge

`Badge` text "Confidence: low | medium | high" plus the history span as caption ("9 days of history"). Prominent per D-25: it is always visible on the row, never in a tooltip.

| Confidence | Badge |
|------------|-------|
| high | `neutral` `solid` |
| medium | `neutral` `soft` |
| low | `neutral` `outline`, and the row's date text is rendered `text-fg-secondary` instead of `text-fg-primary` |

Failure and sustained needs carry no confidence badge (they are observations, not predictions); they show the source label instead (see Copywriting).

### Forecast chart color roles (SVG, token classes)

| Element | Style |
|---------|-------|
| Measured history | solid 2px line, `text-fg-primary` |
| Warn level | 1px horizontal line, `text-warning`, solid, label "Warn {value}{unit}" at the right end, caption size |
| Crit level | 1px horizontal line, `text-alert`, solid, label "Crit {value}{unit}" |
| Today | 1px vertical line, `text-fg-tertiary`, dashed 2 4, label "Today" at top |
| Trend (clear trend only) | 2px dashed (6 4) line from fit-window end forward, `text-fg-secondary`; opacity 1 for medium/high, opacity 0.5 for low confidence |
| Fit window | a subtle `bg-subtle`-token fill band (fill `currentColor` at 0.08 opacity, `text-fg-secondary`) behind the fitted span, so the reader sees which history the trend used |
| Crossing markers | 8px circle at the intersection, `text-warning` (warn) and `text-alert` (crit), with a date label (caption) above, flipped below if it would clip |
| Gridlines | 1px `text-fg-disabled` at 0.4 opacity, horizontal only |

Color is never the only signal: every line has a text label, markers carry date text, and the dash pattern separates measured (solid) from projected (dashed).

## Layout and Interaction Contract

### Needs pane (D-25)
- Amended 2026-10-05 (quick 261005-e7b): the Needs pane is no longer a separate pane. It is the 'Needs' tab of one collapsible 'Incidents & needs' pane (tabs Incidents | Needs, each label with a count badge). The header shows the combined count in one badge coloured by the worst severity (danger incident, then warning incident or immediate need, then urgent need, then standard need); it stays visible when collapsed. Roles: `role="tablist"` (aria-label 'Incidents and needs'), `role="tab"` with aria-selected/aria-controls and roving tabIndex, `role="tabpanel"`; ArrowLeft/ArrowRight/Home/End move selection. The tab and collapsed state persist across reloads. The placement bullet below (side by side at 1280px) is superseded; the right column is no longer widened to 640px.
- Placement: beside the incident pane, in the same region `IndexRoute` already uses for `IncidentList` (`[assumed]` side by side at widths of 1280px and above; stacked below `IncidentList` under 1280px). It renders even when empty, with its own empty state, so layout does not jump.
- Header strip (`bg-subtle`, `p-2`): title "Service needs" (13px semibold), a count `Badge` (neutral soft), and a `SegmentedControl` filter: All | Immediate | Urgent | Standard (default All). Right side: "Updated {hh:mm}" caption from the newest `generated_at`; if the newest is older than 45 minutes (3 missed 15-minute cycles) show "Stale, last update {hh:mm}" in `text-warning` and a `Tooltip` "The analytics service has not published recently."
- Sort: tier (immediate, urgent, standard), then days to crit ascending (already critical first), then host name. Cancelled needs (D-23) are not listed.
- Row (56px min, `p-2`, `gap-2`, two lines):
  - Line 1: tier `Badge` · host name (13px semibold, truncates) · right-aligned date text.
  - Line 2: "what" (service/metric, 12px `text-fg-secondary`, truncates) · source label · confidence badge with history span (trend needs only).
  - Date text for trend needs: "Critical by {d MMM}" (the crit date; the warn date is secondary, shown in the chart and tooltip: "Warning by {d MMM}"). For failure needs: "Down since {hh:mm}". For sustained: "Critical for {duration}".
  - The one-line need narration (body 14px) is shown in a `Tooltip` on row hover/focus and in host details; rows themselves stay two lines.
- Click a row: selects the host (same effect as clicking the host in the tree, opens host details). For trend needs, a trailing `Button` (ghost, small) "View chart" opens the forecast chart for that need's metric without leaving the pane. Row click and "View chart" are separate targets (at least 32px high).
- Edit mode only (D-24; amended 2026-10-05 (quick 261005-e7b): shown in every mode, normal view, ?admin=1 and edit mode): each row gains a "Triage" `Menu` trigger (ghost icon-plus-label button "Triage") with items Downgrade, Upgrade to immediate, Cancel need. A triaged row shows an extra caption line "Downgraded from {computed tier} by {name}, {hh:mm}" (or "Upgraded…"), and its tier badge shows the effective tier. See Triage below.
- Amended 2026-10-05 (quick 261005-e7b): in topology edit mode the combined pane stays visible with the Incidents tab disabled and Needs forced; the prior tab is restored on exit. Original text: Needs pane must remain visible in topology edit mode. (Research: `IndexRoute` currently passes `undefined` for the incident pane and host details in edit mode; the Needs pane is the exception because triage is edit-mode only.) Host details and incident pane stay hidden in edit mode as today.
- No double counting (D-27): a failure need for a host covered by an open incident is not listed in the pane; the incident card shows the derived tier badge instead.

### Tier markers (D-26)
- Tree row: marker per the tier palette, placed after the state badge, with `aria-label="{Tier} service need"` and a `Tooltip` showing the worst need's one-line narration. Hidden when the worst tier is standard.
- Host details: new "Service needs" section (above the metric list), one entry per need for that host (tier badge, what, date, confidence badge, narration sentence, "View chart" for trend needs; no triage controls, since host details is hidden in edit mode and triage lives only in the Needs tab; amended 2026-10-05 (quick 261005-e7b)). Empty: section omitted entirely when the host has no needs.

### Narrated incident card (D-29, D-31)
- `IncidentCard` keeps today's `Message` mapping (status, title, icon, criticality badge) unchanged.
- The description area now shows the narration: headline as the card title replacement is NOT done; the existing root line stays as the title, and the narration headline is the first body line (14px, 600), then the 2 to 4 sentences as plain body lines (14px, 400, `gap-1`), no bullet list.
- A derived-tier `Badge` (per D-27) sits next to the criticality badge, using the tier palette; omitted when no tier is derived.
- Fallback: when the narration topic for the incident is missing, render today's consequence summary line and no placeholder, no skeleton, no error.
- Narration text is rendered as text (never as HTML).

### Triage (D-21 to D-24)
- Visible only in topology edit mode (D-24). Amended 2026-10-05 (quick 261005-e7b): visible in every dashboard mode.
- Menu items: "Downgrade" (disabled with tooltip "Already standard" when the effective tier is standard), "Upgrade to immediate" (disabled "Already immediate"), "Cancel need".
- Downgrade and Upgrade run immediately (reversible by the opposite action; no dialog). Cancel need opens a small confirm dialog (focus trapped, Escape and scrim = cancel, initial focus on Keep need) with an optional single-line note input "Reason (optional)". Downgrade and Upgrade also accept no note in v1 `[assumed]`; the optional note and name are carried in the payload only for Cancel.
- Feedback: no ack topic exists, so the visible effect is the republished need. Show a `Snackbar` on publish "Sent: {action} for {host} {what}" (never "confirmed"); if the need row does not reflect the change within 15 seconds, show the error Snackbar below (stays until dismissed).
- The triage broker login is fetched lazily on first use from `/triage-config.json`; if it is unreachable, the Triage trigger is disabled with tooltip "Triage login unavailable. Reload the page, or check the dashboard container configuration."

### Forecast chart (D-18 to D-20, D-19a)

**Entry points (three):** (1) host details: a "Trends" list of the host's chartable metrics, each row a ghost `Button` "{service} · {metric}" with the latest value and unit, status caption ("Trending", "Stable", "No clear trend") and, when trending with a crit date, the date; (2) a trend-need row's "View chart" in the Needs pane; (3) the Needs section in host details.

**Container:** a modal dialog (focus trapped, Escape and scrim = close, initial focus on the close button), width up to 880px, `bg-surface`, `p-6`; it keeps the page behind it unchanged. `role="dialog" aria-modal="true"`, labelled by the title.

**Header (`bg-subtle`, `p-4`):** title (20px semibold) "{host} · {service} {metric}"; second line: status badge(s) and history span caption. For a clear trend: confidence badge (see above) and caption "{N} days of history". Otherwise: a neutral outline `Badge` "No clear trend" or "Stable" and the same history caption. A `Select` "Range" sets the history window: 14 days, 30 days, 90 days (default: the fit window plus 7 days, rounded up to the nearest option `[assumed]`). Close `Button` top-right.

**Plot (SVG, 240px high, responsive width, `viewBox`-scaled):**
- X axis: time, history from range start to today, extended forward to the later crossing date plus 10% padding when a trend exists; when no clear trend, extends forward 10% of the range only (so the today line is not at the right edge). Ticks via `d3-scale` time ticks, labels `Intl.DateTimeFormat` (e.g. "12 Oct"), caption size. Amended 2026-10-08 (quick 261008-d9k): when zoomed the axis shows only the zoomed window; labels include the time when the window is 2 days or shorter.
- Y axis: linear, domain covers history, the warn and crit levels (when present), and the projected end; `nice()` ticks; unit suffix on the top tick only.
- Layers, bottom to top: gridlines, fit-window band, warn line, crit line, measured history, trend line, today line, crossing markers and labels.
- Measured history: hourly averages from `/ch-api/` (D-20). Lines break at gaps longer than 6 hours (no interpolation across gaps).
- Trend line (D-19a): drawn only when the forecast status is `trending` (the same gate the analytics service applied; the browser never refits and never second-guesses). It starts at the fit window's end value and extends forward to the later of crit date and warn date, capped at 90 days. Low confidence: opacity 0.5 plus caption under the plot "{N} days of history, low confidence". When status is `stable` or `no clear trend`: no trend line, no markers, no fit-window band; a centered-in-plot-top caption badge reads "No clear trend" or "Stable" and the dashed trend element is absent from the DOM.
- A clear trend moving away from the levels (receding): not drawn; status is `stable` per D-10, same treatment as above.
- Crossing markers: warn marker with label "Warning {d MMM}" and crit marker with label "Critical {d MMM}"; omitted individually when that date is null. If already past the level at today, no marker; the level line label gains "(breached)".
- Levels absent (no `warn`/`crit` and no fallback): no level lines; caption "No thresholds defined for this metric."
- Hover/focus: a vertical crosshair with a `Tooltip`-style readout "{date time} · {value}{unit}" for history points, and the projected value for trend points ("projected"). Keyboard: the plot is focusable; Left/Right moves the crosshair across history points; Escape blurs it.
- Amended 2026-10-08 (quick 261008-d9k): zoom and pan. The x axis only zooms, clamped to the full domain above and a 4 hour minimum. The mouse wheel zooms at the pointer (native non-passive listener, so the dialog and page do not scroll); dragging pans a zoomed chart; double-click resets. A toolbar (`role="toolbar"`, aria-label "Chart zoom") holds neutral `sm` Buttons with aria-labels "Zoom in", "Zoom out" and "Reset zoom" (zoom out and reset disabled at full view). Keys on the focused plot: `+` and `-` zoom, `0` resets, Shift+Left/Right pan; plain Left/Right still step the crosshair and the window follows it. At zoom the y domain is rescaled to the in-window history, the projection clipped to the window, and a level only when its crossing is in the window; a level line outside the y domain is not drawn. Plotted layers sit under a `clipPath` so nothing draws over the axes; markers and the today line outside the window are not rendered. State is local and resets when the range or metric changes and when the dialog is reopened.
- Legend row beneath the plot (caption, `gap-2`): Measured (solid sample), Trend (dashed sample, shown only when a trend line is drawn), Warn, Crit, Today.
- "As of {hh:mm}" caption (forecast `generated_at`), with the stale treatment of the Needs pane header when older than 45 minutes.

**States:**
- Loading history: skeleton plot area (`bg-subtle` rectangle, no spinner text), levels and today line absent until data loads.
- History fetch failed: the plot area shows `Message` status warning "Couldn't load history" (see Copywriting); the header and forecast numbers still render.
- No history rows for the range: caption "No history in this range." plus the Range select.
- No forecast message for this metric (analytics not yet run): header shows "No forecast yet" badge, history only, no levels.

### Reconnect and staleness
- Needs, forecasts and narration slices are cleared and rebuilt on every MQTT (re)connect (same as incidents). While the connection is down the Needs pane shows the existing connection indicator state, not a stale list without a warning: rows get `opacity-60` and the header shows "Reconnecting".

## Accessibility

- Tier is always text plus color plus (for tree markers) shape and an `aria-label`; confidence is always text.
- Needs pane is a labelled region (`role="region"`, `aria-label="Service needs"`); the list is a `ul`; rows are focusable and operable with Enter (select host); "View chart" and "Triage" are separate tab stops in that order.
- Header update/stale text is `role="status"`; triage Snackbar `aria-live="polite"`, errors `assertive` (same as Phase 16).
- Chart SVG has `role="img"` and an `aria-label` summarizing it ("{metric} for {host}: {latest value}{unit}, {status}, critical by {date}"), plus a visually hidden `<table>` (or `aria-describedby` text) is NOT required; the focusable crosshair with keyboard stepping and the readout is the accessible data path.
- Dialogs: focus trapped, Escape closes, targets at least 32px.
- Respect `prefers-reduced-motion`: no animations are specified, none added.

## Assumptions (auto mode, to confirm in checker or UAT)

1. Needs pane sits beside the incident pane at 1280px and wider, stacked below it narrower; it stays visible in topology edit mode while host details and the incident pane stay hidden there. (Superseded 2026-10-05 (quick 261005-e7b): one 'Incidents & needs' tabbed pane, visible in edit mode with Incidents disabled and Needs forced.)
2. Tier palette uses the warning hue family plus neutral so it cannot be mistaken for state red or criticality purple; orange overlaps the WARN state color, mitigated by always-present text labels and separate placement.
3. Map nodes get a tier marker only if vis-network can draw it cleanly through the existing overlay mechanism; otherwise the map has no marker and tree plus pane carry the tier (D-26 satisfied by the tree).
4. Downgrade and Upgrade need no dialog and no note; only Cancel need has a dialog and an optional reason.
5. Default chart range is the fit window plus 7 days rounded up to 14, 30 or 90 days.
6. A stale threshold of 45 minutes (three missed 15-minute cycles) for "Stale" treatment.
7. `Menu`, `SegmentedControl` and `Badge` prop names may differ from the usage above; the executor falls back to the nearest existing primitive with the same tokens.
8. The date format "d MMM" (for example "12 Oct") is acceptable; year is shown only when the date is in a different year.
