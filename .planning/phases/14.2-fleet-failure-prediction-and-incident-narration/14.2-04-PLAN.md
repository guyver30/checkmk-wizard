<feature>
  <name>Trend fit with quality gate, sharp-drop cut and crossing dates</name>
  <files>analytics/fit.py, tests/test_analytics_fit.py, analytics/__init__.py, pyproject.toml</files>
  <behavior>
    Points are (epoch seconds, value) bucket averages in ascending time order. "Higher is worse" for every metric; when warn and crit are both set and crit < warn, crossings are not computed (all crossing fields None) but status is still computed.
    - Steady ramp 50 -> 80 over 30 days (6 h buckets), crit 90, warn 85: status trending, slope_per_day ~1.0, value_at_end == last point value, crit_ts == fit_end_ts + (90 - value_at_end)/slope*86400 exactly, crit_date is that day in UTC, days_to_crit == (crit_ts - now_ts)/86400, confidence medium (30 days)
    - Same ramp over 10 days: confidence low; over 80 days with r2 >= 0.90: high; over 80 days with r2 0.75: medium
    - 80 days of input with a cleanup drop 5 days ago (fit window 5 days): history_days is 80 (available history, D-10), fit_start_ts is the first post-drop bucket, so the fit window and history_days differ
    - Uniform random noise (seeded, 40-60) over 30 days: status no_clear_trend, slope_per_day/confidence/crossings all None, history_days still reported
    - Constant series: status stable (must not raise StatisticsError from correlation)
    - Falling ramp: status stable, no crossings
    - Rise below min_rise_30d (e.g. 0.3 per 30 days with r2 high): stable
    - Ramp 40 -> 80, then a drop to 45 (cleanup), then ramp 45 -> 60: cut_after_last_sharp_drop returns only the points after the drop; fit_start_ts equals the first post-drop bucket
    - A 2-point wobble on a 90% disk (drop of 2 with range 10) is not a sharp drop (threshold = max(drop_min_abs, drop_range_fraction * (max - min)))
    - Fewer than min_buckets points or span < min_span_days after the cut: no_clear_trend
    - last_value already >= crit while trending: the crossing has already passed, so crit_ts None, crit_date None, days_to_crit 0.0; same rule for warn
    - Level None: matching crossing fields None
    - to_payload returns only JSON-serialisable types and includes service, metric, unit, status
  </behavior>
