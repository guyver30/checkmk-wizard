# Phase 14.2 Plan 14: Host details needs and trends Summary

Host details now shows a per-host "Service needs" section (with narration) and a "Trends" list that opens the forecast chart for any metric at any time.

## What was built

- "Service needs" section (omitted when the host has no visible needs): tier badge (shared `TIER_BADGE`), what, date text matching the Needs pane wording, confidence badge plus "N days of history" for trend needs, the narration as a React text node, and "View chart" for trend needs. Cancelled needs and other hosts' needs are excluded via `selectVisibleNeeds`. No triage controls.
- "Trends" list from `forecasts[id].fits` (omitted without a forecast): one button per fit labelled `service · metric`, latest value + unit, caption Trending / Stable / No clear trend, and "Critical by d MMM" for trending fits with a crit date.
- One local `{service, metric}` state drives `ForecastDialog` for both sections; closing refocuses the entry that opened it. Rendered in both the agent-host and the full view.

Both tasks touch the same two files and were committed together: e411e80.

## Deviations from Plan

- Plan said "ghost buttons"; the design system has no ghost variant, so `variant="tertiary"` (transparent) is used.
- `needDateText`/`formatDay` are duplicated locally (NeedRow does not export them and is off-limits this wave); `TIER_BADGE` is imported from `lib/needDisplay`, where it already lives, so no local copy was needed.
- A test fixture initially used an invalid need source and triage shape; fixed in the test only.
