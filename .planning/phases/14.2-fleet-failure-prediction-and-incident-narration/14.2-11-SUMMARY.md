## Deviations from Plan

**1. [Rule 3 - Blocking] AnalyticsConfig lacked `poll_interval_seconds`.** The rollup scales sample counts by it (`rollup_one_day`) and records it in the document; the plan assumed identical fields. Added field (default 15, env `POLL_INTERVAL_SECONDS`, in repr and `from_env`) to `analytics/config.py`, and added the env name to `ENV_NAMES` in `tests/test_analytics_config.py`. Follow-up for the deploy plan: the analytics compose service should set `POLL_INTERVAL_SECONDS` equal to the poller's (compose has 15 for the poller; the default matches).

**2. [Rule 3 - Blocking] `history._clickhouse_insert` only allows `ANALYTICS_TABLES`** and would reject `history.availability_daily`. Rather than widen that allowlist (it also drives `missing_tables`), rollup.py carries a local one-name-allowlist insert `_insert_availability_rows` built on `history._clickhouse_request`; two tests cover it (unlisted table refused without a request; one JSONEachRow POST).

**3. Worktree base was stale** (wave 1 commit); reset to the required base fe75cd2 before starting, per the startup protocol.
