## Deviations from Plan

**1. [Rule 3 - Blocking] Own menu instead of design-system `Menu`.** The design-system `Menu` has no disabled/tooltip support, which the spec needs for "Already standard"/"Already immediate". TriageMenu renders its own `role="menu"` popup with `role="menuitem"` buttons.

**2. [Rule 3] "ghost" Button variant mapped to `tertiary`** (the design system has no `ghost`).

**3. Login-unavailable handling.** `publishTriage` resolves false for both missing config and a failed publish, so a false result disables the Triage trigger with the spec tooltip and shows the same text as a persistent error. The trigger cannot be disabled before the first attempt because the config is fetched lazily.

## Known behaviour notes
- After a successful Cancel the need leaves the list, unmounting the row's TriageMenu, so the "Sent" snackbar and 15 s check live only as long as the row; this is acceptable because the disappearance is itself the visible effect. Downgrade/Upgrade rows persist and get the full check.
- Docs: no dashboard doc files describe the admin config flow, so none were updated; `/triage-config.json` serving is plan 03's scope.
