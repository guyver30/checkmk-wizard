Subscriptions (QoS 1, issued in on_connect so a clean-session reconnect resubscribes):
  lan/devices/+/status, lan/devices/+/services, lan/devices/topology, lan/events/recent, lan/incidents/+/status,
  needs/triage/cmd. Restore (once, at startup, before the first cycle): subscribe to lan/needs/+/status and lan/incidents/+/narration, wait a fixed 5 s for the retained replay (same idea as the poller's RECONCILE_TIMEOUT_SECONDS), read what arrived, unsubscribe. No other windowing.
Outputs: lan/forecasts/{host} (retained, each cycle), lan/needs/{need_id}/status (retained, every visible need republished each cycle with fresh generated_at; tombstone on resolve), lan/incidents/{id}/narration (retained; tombstone on close).
Forecast payload: {"host", "generated_at", "fits": [Fit.to_payload(service, metric, unit), ...]} for all chart_metrics series of that host.
Narration payload: {"id", "headline", "sentences", "tier": rules.tier_from_criticality(incident.worst_criticality) or null, "generated_at"}.
Root criticality for narration = topology node criticality of incident.root (D-29 example "(low criticality)").
Hourly window for sustained = config.SUSTAINED_WINDOW_HOURS (module constant) via history.fetch_recent_hourly. Fallback levels = config.FALLBACK_LEVELS; units = config.METRIC_UNITS; wear set = config.WEAR_METRICS (module constants, plan 07).
Thresholds: build fit.FitParams and rules.RuleParams from AnalyticsConfig in one helper `params_from_config(config)`.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broker -> analytics | all inputs (status, services, topology, events, incidents, triage commands) are untrusted JSON |
| analytics -> broker | retained outputs under the analytics ACL |
| analytics -> ClickHouse/MinIO | writer credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14.2-51 | Tampering | triage command path | mitigate | retained ignored, idempotent latest-wins per need_id, parse/validate (plan 12), need_id must exist in tracker, audit row before republish |
| T-14.2-52 | Denial of service | feedback loop on own topics | mitigate | specific filters only (never lan/#); own outputs read only in the restore window |
| T-14.2-53 | Denial of service | slow ClickHouse/cycle overlap | mitigate | monotonic scheduler, skip-not-overlap, ClickHouse timeout, failure needs still evaluated |
| T-14.2-54 | Tampering | topic injection via host names | mitigate | forecast topics only for is_publishable_device_id hosts; need ids hashed |
| T-14.2-55 | Information disclosure | secrets in logs | mitigate | masked config repr; ClickHouseError never includes the password |
| T-14.2-56 | Information disclosure | data leaving the tenancy | mitigate | only env-configured broker/ClickHouse/MinIO endpoints; no external call (D-05) |
