<objective>
Extend Phase 9's poller so each published device carries its Checkmk alias, and so its location/group label comes from Checkmk's own REST folder association instead of string-splitting the OMD filesystem path Livestatus reports.

Purpose: TAG-03, D-03, D-04, D-10. `derive_folder()` currently searches the Livestatus `filename` column for a literal `wato` segment — code-review finding WR-07 shows this breaks when the Checkmk site id is itself named `wato`, and PITFALLS.md Pitfall 10 shows the whole approach is fragile because it parses an on-disk layout with no schema guarantee. Reading Checkmk's own computed folder association removes the entire class of bug rather than patching one instance.
Output: an `alias` column end-to-end, a REST folder client with the poller's established single-choke-point error handling, and REST credential fields on `PollerConfig` with the secret redacted.

Two discretion calls CONTEXT.md left open, resolved here and recorded in-source:

1. **MQTT payload field name for the folder-derived label.** D-01 requires a generic field (`location`/`group`, explicitly not `vlan`). The Phase 9 contract already publishes this as `folder` on `lan/devices/{id}/status` and in each `lan/devices/topology` node. `folder` is already generic and already carries no VLAN semantics, so it is KEPT as-is. Renaming it would strand every retained payload currently on the broker and force a Phase 11 contract change for zero semantic gain. What changes is where the value comes from, not what it is called.
2. **REST client implementation.** Standard-library `urllib.request`, not `httpx`. `scripts/mqtt_poller.py`'s module docstring makes "standalone, dependency-light" an explicit design constraint, and `paho-mqtt` is its only non-stdlib import precisely because MQTT has no stdlib client. A single authenticated GET plus a JSON decode does not justify a second `pip install` line in the poller container's compose command.
</objective>
