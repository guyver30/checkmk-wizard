<objective>
Make plan 10-03's REST folder lookup actually work in the deployed stack: give the poller service its credentials, prove the enrichment reached the broker, and tell the operator how to provision the secret.

Purpose: TAG-03's end-to-end half. 10-RESEARCH.md Pitfall 2 identifies a gap CONTEXT.md did not cover — the poller has never had a REST credential, and there is no channel for the wizard-bootstrapped automation secret to reach it, because the poller runs in a separate container that must not touch `checkmk`'s filesystem. Without this plan, plan 10-03 is code-complete and non-functional: every folder silently comes back empty.
Output: compose environment entries, a smoke-test check that catches exactly that silent-empty-folder failure mode, and setup-doc coverage of both.

Trust model for the new secret follows the one this stack already documents for `MQTT_PASSWORD`, `CMK_PASSWORD` and `minioadmin`: a checked-in placeholder plus an explicit rotate-before-exposing-beyond-a-trusted-LAN instruction (IN-02). This resolves 10-RESEARCH.md Open Question 2 in favour of in-scope, manual, documented provisioning.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Checked-in `deploy/compose.yaml` -> git history | A real automation secret pasted into this file would be committed to the repository permanently |
| Compose environment -> poller container | The secret is delivered as a plain environment variable, readable by anything that can inspect the container |
| Smoke-test output -> operator terminal | The enrichment check prints retained payload contents |
