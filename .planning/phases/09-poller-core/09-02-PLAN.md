Add `reconcile_state(config) -> PollerState` implementing RESEARCH.md's resolved strategy. Open one short-lived `mqtt.Client(mqtt.CallbackAPIVersion.VERSION2)` — deliberately WITHOUT `will_set`, so this throwaway client's disconnect cannot publish an offline poller status — authenticate, register an `on_message` handler that stores payloads by topic, subscribe to `TOPIC_TOPOLOGY` (qos=1), `TOPIC_EVENTS` (qos=1) and `lan/devices/+/history` (qos=1), `loop_start()`, wait `config.reconcile_timeout_seconds` on a `threading.Event`-style bounded wait adapted from `smoke_test_broker.py::_wait_for_retained_payload`, then `loop_stop()`/`disconnect()` in a `finally`. Document the correctness argument in the function docstring, because it is the load-bearing design decision of this phase: only `previous_nodes` drives tombstone and topology-change decisions, and it comes from exactly one retained topic, so Mosquitto delivers exactly one message (or none, on cold start) right after SUBACK — there is no ambiguous "have all retained messages arrived yet" wait. The wildcard `lan/devices/+/history` subscription is best-effort cosmetic restoration only: a history array that arrives late simply gets rebuilt from the next transition onward, which is a bounded, self-correcting log gap and never a wrong tombstone or a wrong status. Per-device status is deliberately not reconciled at all — it is republished fresh from live Livestatus every cycle, so it has no "previous" value worth recovering. This is what satisfies "self-heals across restarts with no persisted state of its own" (PLR-02): the durable store is Mosquitto's `persistence true` from Phase 8, not a poller-owned file.

Add `run_cycle(client, config, state, snapshots)`. Order of operations per cycle: compute `now = utc_now_iso()`; publish a status message for every snapshot; compute `nodes = topology_nodes(snapshots)`; compute removed ids (`state.previous_nodes` keys minus current ids) and added ids (current ids minus `state.previous_nodes` keys); for each removed id call `publish_tombstone`, `pop` it from `state.last_status` and `state.history`, and append a `removed` event carrying its last known state as `from` and `None` as `to`; for each added id append an `added` event with `from` `None` and `to` the device's current state; for each snapshot whose id is present in `state.last_status` with a different value, append a `state_change` event and append a `{"timestamp", "from", "to"}` entry to that device's history via `append_bounded(..., config.history_max_entries)` and publish that device's history; publish `lan/devices/topology` only when `topology_signature(nodes) != topology_signature(list(state.previous_nodes.values()))` — on a cold start `previous_nodes` is empty so the first cycle publishes, and on a warm restart whose topology is unchanged it correctly publishes nothing; publish `lan/events/recent` only when at least one event was appended this cycle; publish the poller heartbeat with `device_count=len(snapshots)`; finally replace `state.previous_nodes` with `{node["id"]: node for node in nodes}` and `state.last_status` with the current id->state mapping.

Note explicitly in a comment why no "first cycle" suppression flag is needed: `state.last_status` starts empty, so a restarted poller mathematically cannot compute a false transition on its first cycle — the suppression RESEARCH.md calls for falls out of the data structure rather than needing a flag.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Broker -> poller (retained reconciliation payloads) | The retained topology/events/history payloads read at startup are untrusted input: they were written by a previous poller run, but a corrupt or hand-published payload must not crash the daemon |
| Poller -> broker (`mosquitto:1883`) | Authenticated publish path using the `poller` user provisioned in Phase 8; the topic strings are built from Checkmk-supplied host names |
| Process lifecycle -> broker | Liveness signalling depends on the broker delivering the configured will on ungraceful disconnect |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | publish helpers in `scripts/mqtt_poller.py` | mitigate | Topic strings are only ever built from ids that already passed `is_publishable_device_id` in `query_devices` (Plan 09-01); `run_cycle` never constructs a topic from a raw Livestatus name |
| T-09-05 | Tampering | `reconcile_state` / `parse_topology_payload` / `parse_events_payload` | mitigate | Retained payloads are parsed inside narrow `except (json.JSONDecodeError, ValueError, TypeError)` handlers that log and fall back to an empty baseline (cold start) instead of raising into a `restart: unless-stopped` crash loop |
| T-09-06 | Spoofing | `reconcile_state` short-lived client | mitigate | The reconciliation client deliberately omits `will_set`, so its normal disconnect cannot publish a false `{"status": "offline"}` for the running poller |
| T-09-02 | Information Disclosure | `build_mqtt_client`, `run_forever` logging | mitigate | Only host/port/username and paho reason codes are logged; `PollerConfig.__repr__` masks the password and no code path logs the raw config or environment |
| T-09-03 | Denial of Service | `run_forever` poll loop | mitigate | `LivestatusError` per cycle is logged and skipped (poll interval is the backoff); publish failures are caught in `_publish_json`; no bare `except Exception` |
| T-09-07 | Repudiation | `lan/poller/status` | mitigate | Birth message at connect plus a per-cycle heartbeat with a refreshed `last_poll` means "connected but stalled" is externally detectable, not silently indistinguishable from healthy (RESEARCH.md Pitfall C) |
| T-09-SC | Tampering | Package installs | mitigate | No package-manager install in this plan; `paho-mqtt` 2.1.0 is already vetted and pinned in `pyproject.toml` (RESEARCH.md Package Legitimacy Audit: Approved) |
</threat_model>
