<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Container image registry -> poller container | The `poller` service installs a Python package at container start; the install source and version are the supply-chain surface |
| Host filesystem -> poller container | The poller script enters the container through a bind mount; a wrong or missing mount path means either no script or an unintended one |
| Operator shell -> compose stack | The smoke test issues container lifecycle commands (restart/kill/start) supplied as CLI strings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-SC | Tampering | `poller` service `command` in `deploy/compose.yaml` | mitigate | `pip install --no-cache-dir paho-mqtt==2.1.0` pins the exact version audited in RESEARCH.md's Package Legitimacy Audit (Approved, Eclipse Foundation project, no `[ASSUMED]`/`[SUS]`/`[SLOP]` entries). No other package is installed and no new dependency is added to `pyproject.toml` |
| T-09-08 | Tampering | poller bind mount | mitigate | The script is mounted read-only (`:ro`) from the git-tracked `scripts/` directory rather than from the uncommitted `deploy/app/`, so the running code is exactly what is under version control and the container cannot rewrite it |
| T-09-02 | Information Disclosure | `poller` environment block | accept | `MQTT_PASSWORD` is a disposable Phase 8 default already committed in `deploy/mosquitto.passwd` and documented as such; rotation is via `deploy/gen-mosquitto-passwd.sh`. Accepted for a trusted-LAN stack, consistent with the existing `cmkadmin`/`minioadmin` defaults |
| T-09-09 | Elevation of Privilege | `scripts/smoke_test_poller.py` subprocess calls | mitigate | Lifecycle commands run through `shlex.split` + `subprocess.run(check=False)` with no `shell=True`, matching `scripts/smoke_test_broker.py`'s established convention, so an operator-supplied string cannot become a shell injection |
| T-09-10 | Tampering | `check_ghost_tombstone` retained-topology write | mitigate | The check writes only a synthetic `smoketest-ghost` node into the retained topology and relies on the poller's own next cycle to republish correct topology; it never writes to a real device's status or history topic |
| T-09-04 | Spoofing | Livestatus TCP channel | accept | Livestatus stays unpublished to the LAN and reachable only on the internal `cmk_net` bridge (setup doc §5); the poller adds no new exposure |
</threat_model>
