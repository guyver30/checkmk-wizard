# Phase 11.1 Plan 10: Event History (D-33/D-35) Summary

**Centre-bottom pane now shows a live, newest-first event feed (`EventHistory`) built on a middle-truncation helper (`middleTruncate`, D-35) and a per-row component (`EventRow`) that keeps the full device identifier one hover/title away even when every host shares a `192.168.0.x` prefix; the D-33 oldest-first-on-the-wire → newest-first-on-screen contract is pinned by a full-array-equality regression test on the consumer side.**

- **Duration:** ~35 min (environment setup: rebuilding the `design-system` tarball and `dashboard-react` node_modules from a fresh worktree checkout, then two TDD tasks with full-suite verification).
- **Tasks:** 2 of 2 completed.
- **Files modified:** 7 (5 created, 2 modified).

## Accomplishments

- Built `src/lib/truncate.ts`: `middleTruncate(value, maxLength)` keeps a head prefix and a tail suffix around a single `…` (U+2026), biasing the leftover character to the TAIL on odd budgets — the exact bias D-35 exists to protect, since the distinguishing octet of a `192.168.0.x` fleet lives at the end of the string.
- Built `src/components/EventRow.tsx`: ports `dashboard/js/render-shell.js`'s `eventRowElement()` data shaping (clock / device-name / from→to) into a component. Applies D-35's full rule for the device column — alias-first via `displayName()`, fall back to the raw `device_id`, then `middleTruncate` the result — and always exposes the untruncated identifier through both a `title` attribute and a `kone-design-system` `Tooltip`.
- Built `src/components/EventHistory.tsx`: reads `events`/`devices` from the store, renders `events.slice().reverse()` (exactly one reversal) into `EventRow`s inside a `role="log"` `aria-live="polite"` region, with an explicit "No recent events" empty state. Keys rows by `${device_id}:${timestamp}:${index}` so a reorder never reuses a row.
- Wired `EventHistory` into `IndexRoute.tsx`'s `centreBottom` slot, replacing plan 06's placeholder paragraph.
- Wrote a consumer-side regression test (`EventHistory.test.tsx`) asserting a full ordered `["c", "b", "a"]` device-label list from an oldest-first `[a, b, c]` store array — matching plan 11.1-02's producer-side assertion style — plus store-non-mutation, empty-state, unknown-device, malformed-entry, and live-update-ordering coverage.

## Decisions Made

- **`EventEntry.from`/`EventEntry.to` added to the shared type** — the plan's `<interfaces>` block documents the wire shape as `{ device_id, from, to, timestamp }` (confirmed by reading `scripts/mqtt_poller.py`'s `run_cycle()`), but the type only declared `state`. Rather than reading `entry.from`/`entry.to` through the index signature's implicit `unknown`, the two fields were added explicitly so `EventRow` can pass them to `StateBadgeForState` (which requires `state: string`) without a cast at every call site.
- **No `maxLength<=1` special case in `middleTruncate`** — the head/tail split formula (`Math.floor(budget/2)` head, remainder to tail) degrades cleanly to a bare `…` at `maxLength=1` on its own; only `maxLength<=0` needed an explicit guard (negative-index slicing bug otherwise).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Added `from`/`to` fields to the `EventEntry` type**
- **Found during:** Task 1, writing `EventRow.tsx`
- **Issue:** `dashboard-react/src/lib/types.ts`'s `EventEntry` interface only declared `device_id`, `state`, `timestamp` — no `from`/`to`, even though the plan's own `<interfaces>` section and a direct read of `scripts/mqtt_poller.py` (lines 1053-1098) confirm the poller publishes `from`/`to`, not `state`, on each event entry. Reading `entry.from`/`entry.to` without an explicit field falls through the type's `[key: string]: unknown` index signature, which would not type-check against `StateBadgeForState`'s `state: string` prop.
- **Fix:** Added `from?: string | null` and `to?: string | null` to `EventEntry`, with a comment citing the poller behavior.
- **Files modified:** `dashboard-react/src/lib/types.ts`
- **Verification:** `npm --prefix dashboard-react run typecheck` exits 0.
- **Committed in:** `e74713f` (Task 1 commit)
