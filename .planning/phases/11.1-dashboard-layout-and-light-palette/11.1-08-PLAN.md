<objective>
Build the custom device tree: a `treeModel` deriving group and device nodes from the store using
`grouping.ts`'s existing primitives, and `Tree`/`TreeNode` components that imitate
`Accordion.tsx`'s accessible button pattern without wrapping it.

Purpose: RESEARCH confirmed D-45's framing by reading `Accordion.tsx` directly — it holds a single
`openId` string (only one item open at a time), has no `className` prop, no depth awareness, and
no slot for a per-node severity. A device tree needs an arbitrary set of groups open simultaneously
and severity threaded per node, so `Accordion` is a pattern to copy, not a component to wrap.
Output: the left pane of the three-pane layout, populated and keyboard-operable.
</objective>

  <action>
Create `src/lib/treeModel.ts` exporting `type TreeGroupNode = { kind: "group"; key: string; label:
string; worst: string; worstRank: number; nonOkCount: number; total: number; hatched: boolean;
children: TreeDeviceNode[] }`, `type TreeDeviceNode = { kind: "device"; id: string; label: string;
state: string; stale: boolean; typeIcon: string; tagGroupMissing: boolean }`, and
`buildTree(devices: Record<string, DevicePayload>, mode: GroupingMode, nowMs = Date.now()):
TreeGroupNode[]`.

Build the group index with `buildGroupIndex` and take group order from `sortedGroupKeys`; roll each
group up with `rollUpGroup`. Do NOT write a second severity comparator or a second group-key
function here — `grouping.ts` already provides both, and D-32/D-43 name them explicitly as "port,
don't re-derive". This module's only job is shaping those results into renderable nodes.

`buildGroupIndex` takes a `Map`; the store holds a `Record`. Convert at this boundary with
`new Map(Object.entries(devices))` and note in a comment that the store deliberately uses plain
objects for Zustand selector equality while `grouping.ts` keeps the vanilla `Map` signature
unchanged, so this is the one intentional adapter point.

Sorting is derived here on every call, never cached in component state — D-32's binding constraint
is that sort order is computed from current state on each rebuild. Alphabetical is the default;
plan 09 adds the severity-ordered comparator as a parameter.

Write `treeModel.test.ts` covering every behavior bullet with a fixed `nowMs`.
