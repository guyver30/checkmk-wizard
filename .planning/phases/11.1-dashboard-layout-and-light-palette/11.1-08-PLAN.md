<objective>
Close the two follow-on defects Phase 11's live verification produced: stale flips that rebuild
structure instead of toggling a class (D-34), and event rows that cannot be told apart (D-35).

Purpose: D-34's premise is that a full rebuild on a stale flip was justified in-comment as "an
infrequent event" — and the 12-second clock made that premise false. D-35 is from a live
screenshot: at 280px of sidebar, every `.event-device-name` truncated to `1...` because every host
is `192.168.0.x` and the distinguishing part is at the END. Moving the event panel to the centre
widens it and largely fixes this **by accident — this plan does not rely on that.**
Output: a class-toggling stale path in two modules, a re-evaluated tick cadence, and an event row
that names its device.
</objective>

  <action>
Add `refreshStaleFlags()` to `render-shell.js`: a sweep that walks the existing tree DOM —
`container.querySelectorAll("[data-host]")` for rows and `.tree-group` for group headers — and for
each calls `classList.toggle("is-stale", …)` with the value from `isDeviceStale(payload)` /
`isPollerStale(...)` / the group's `rollUpGroup(...).hatched`. It creates no elements, replaces no
elements and reads no DOM state as truth — it only writes the class. Rows whose host is no longer
in `store.devices` are left alone; a membership change is a `"topology"` event and still legitimately
rebuilds.

Replace `renderPollerBanner()`'s `if (changed) { renderTree(); }` with
`if (changed) { refreshStaleFlags(); }` and rewrite the comment above it: the hatch is still derived
per-row/per-group from the flag, but deriving it no longer requires recomputing structure, because
`.is-stale` is a purely additive `background-image` layer that composes over whatever
`--state-*-fill` the row's state class already set (D-15). Keep that composability note — it is the
reason a class toggle is sufficient here and a full rebuild never was.

In `tick()`, replace the unconditional `renderTree()` call with `refreshStaleFlags()` plus an
in-place refresh of any time-derived text the tree renders (relative "last seen" strings, if the
row carries one — check `hostRowElement()` and patch the existing text node rather than rebuilding
the row). If, after reading, the tree turns out to render no time-derived text at all, say so
explicitly in the SUMMARY and let `refreshStaleFlags()` stand alone.

**Keep** `tick()`'s scroll and focus save/restore. It is now a safety net rather than a necessity
for the tree, because `tickListeners` still fan out to whichever view module is mounted — leave a
comment saying exactly that, so a future reader does not delete it as dead code and rediscover the
WCAG 2.4.3 focus-order failure the comment above `tick()` already documents.

**CLOCK_TICK_MS.** D-34 requires this be revisited now that a resizable, full-height tree means
more nodes per tick. Measure rather than guess: with the largest realistic device count available,
time one `refreshStaleFlags()` sweep (`performance.now()` around the call, or the DevTools
performance panel) and record the number in the SUMMARY. Then either keep 12000 with a dated
comment recording the measured cost and why it is comfortable, or change it — whichever the
measurement supports. An unmeasured "kept as-is" is not acceptable; an unmeasured change is worse.
