# Phase 11.1 Plan 06: Three-Pane Resizable/Collapsible Shell Summary

**Custom `Splitter` (full ARIA separator + keyboard contract) and `usePaneLayout` hook (guarded-storage-backed, clamped, in-memory-source-of-truth) drive a CSS-grid `ThreePaneLayout` — tree pane full-height left, map-placeholder centre-top, event-history centre-bottom — now wired into the index route.**

## Performance

- **Duration:** ~45 min of active work (dependency install/build of `kone-design-system` tarball, three TDD tasks, full-suite verification).
- **Tasks:** 3 of 3 completed.
- **Files modified:** 11 (9 created, 2 modified).

## Accomplishments

- Built `src/lib/guardedStorage.ts`: `readJson`/`writeJson` wrap every `localStorage` access in try/catch, matching the `render-shell.js` `groupingModeOverride` precedent that prevents a blocked-storage browser from taking down the whole shell.
- Built `src/components/Splitter.tsx`: a controlled `role="separator"` component with `aria-orientation`/`aria-valuenow`/`aria-valuemin`/`aria-valuemax`, full arrow-key + Home/End keyboard resize (clamped), and Pointer Events drag resize with `onResizeCommit` firing exactly once per drag.
- Built `src/hooks/usePaneLayout.ts`: owns tree-width and events-height as React state, lazily seeded once from guarded storage, clamping each persisted field independently into its bounds so one corrupt field never discards a good sibling; `commit()` ignores `writeJson`'s `false` return so a refused write never rolls back the in-memory value; collapsing a pane never discards its stored size.
- Built `src/components/ThreePaneLayout.tsx`: a CSS-grid shell composing `usePaneLayout` and two `Splitter`s, taking `tree`/`centreTop`/`centreBottom` as `ReactNode` props (D-31); each of the two resizable panes gets a real `<button aria-expanded>` collapse control whose collapsed state unmounts pane content and shows a narrow restore rail.
- Built `src/components/MapPlaceholder.tsx`: a container-sized (`h-full w-full`, no fixed pixel dimensions), labelled "Topology map — Phase 13" placeholder occupying the exact geometry Phase 13's real map will use (D-27).
- Rewrote `src/routes/IndexRoute.tsx` to render `ThreePaneLayout` with placeholder slots, each commented with the plan that fills it (07 for the stats strip, 08 for the device tree, 10 for event history).

## Decisions Made

- **Collapse controls scoped to tree + events only, not centreTop** — `usePaneLayout`'s Task-2-committed API (`collapsed: { tree, events }`) has no third key for the centre-top pane, and Task 2's own action text says centre-top "has no stored size of its own." The plan's `must_haves.truths` phrase "Each pane has a real `<button>` collapse control" is read in light of that literal, already-implemented hook contract as "each of the two collapsible panes." Adding an unbounded third collapse (no defined collapsed-rail geometry, no persisted size to restore to) would have been speculative configurability the CONTEXT explicitly warns against.
- **Splitter direction is a fixed, documented convention (right/down = increase), not a runtime option** — the plan's `SplitterProps` contract has no `invert` field, and only `ThreePaneLayout` consumes `Splitter` in this codebase, so no configurability was added for a case that doesn't exist yet.
