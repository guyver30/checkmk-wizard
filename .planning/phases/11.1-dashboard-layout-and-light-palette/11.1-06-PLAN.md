result through the guarded-storage pattern this codebase already established.

Purpose: D-26 is the operator's locked choice of "drag handles AND collapse buttons" with

splitters. Do not build a generic "make any two siblings resizable" abstraction.

Module-level state, never read back off the DOM (the `collapsedGroupKeys` precedent):
`var paneState = { sidebarWidthPx: …, bottomHeightPx: …, sidebarCollapsed: false,
topCollapsed: false, bottomCollapsed: false, preCollapse: { … } };`

Size model: set exactly ONE side of each split as an explicit size and let the other be `1fr`, so
the browser absorbs rounding instead of JS keeping two numbers consistent. Concretely
`--layout-sidebar-width` on `.shell` and `--pane-bottom-size` on `#centre` are the JS-settable
properties; the sidebar's neighbour and `--pane-top-size` stay `1fr`.

Three-part guarded accessors, one per persisted value (`sidebarWidthPx`, `bottomHeightPx`,
`sidebarCollapsed`, `topCollapsed`, `bottomCollapsed`). Use one `localStorage` key holding a small
JSON object (e.g. `dashboard.panes.v1`) or one key per value — either is fine (storage key names
and shape are Claude's Discretion) — but **every** read and **every** write is individually wrapped
in `try/catch`, and every read is validated before use: `parseInt(value, 10)`, then
`Number.isFinite`, then clamp into `[MIN_PANE_SIZE_PX, MAX]`. Never pass a stored string through to
`setProperty` unchecked — allow-list the value the way `groupingMode()` allow-lists
`"folder"`/`"device_type"` rather than trusting what came back. A corrupt or hostile stored value
must clamp, not propagate as literal CSS text.

`applyPaneState()` writes the current in-memory state to the DOM: `setProperty` on `.shell` /
`#centre` for the sizes, and `classList.toggle("is-collapsed", …)` on the three panes. Applying via
custom properties on the two stable wrapper elements is what makes a resize survive `tick()` for
free: `tick()` rebuilds `#sidebar-tree` and calls the view modules, but never touches `.shell` or
`#centre`, so the sizing lives outside every rebuilt subtree — exactly the reasoning that already
makes `collapsedGroupKeys` durable. **Verify this rather than assuming it** (see the acceptance
criteria); the risk is real only if sizing is accidentally attached to an element some render path
recreates.

`Panes.init()` is idempotent (a second call is a no-op, like `startClock()`'s `clockTimer` guard):
it reads the guarded state, calls `applyPaneState()`, then wires the handlers Task 2 adds.

Wiring: add `<script src="js/panes.js"></script>` to all three HTML pages, positioned **before**
`js/render-shell.js` in the existing script block, and add a single `Panes.init()` call inside
`render-shell.js`'s `init()` alongside the other control wiring, guarded with
`if (window.Panes && Panes.init)`. Do not modify `shell.js`.

Constants: `MIN_PANE_SIZE_PX` (~120–160), a collapsed-rail size (~32–40px), and the arrow-key step
(~16–24px) as module-level `UPPER_SNAKE_CASE`, matching `scanner.py`/`config.js` convention.

On `aria-orientation`: it describes the **separator's own axis**. The divider between the left and
right panes is `vertical`; the divider between the stacked centre panes is `horizontal`. Research
calls this a common point of confusion — confirm against the APG example before committing, and
leave a code comment recording the mnemonic you verified, not one you guessed.

**CSS.** `.splitter-track` sizes the divider as a real grid track (~5–7px) so the hit target comes
from CSS, not JS geometry. `.splitter` gets `cursor: col-resize` / `row-resize` by orientation,
`touch-action: none` (required, or the browser's own scroll gesture swallows `pointermove` on a
touchscreen), a `var(--color-border)` rule, a hover/active accent tint, and a `:focus-visible`
outline matching the file's existing accessibility rule — a splitter you can Tab to but cannot SEE
focused is still a failure.

**Pointer drag.** Use Pointer Events with `setPointerCapture`, not mouse events. On `pointerdown`:
`splitterEl.setPointerCapture(event.pointerId)`, record `startPos` (`clientX` for the vertical
splitter, `clientY` for the horizontal one) and the current pane size; attach `pointermove` and
`pointerup` **to the splitter element itself**, not to `document`. Capture guarantees a fast drag
cannot escape the element and land on a sibling, and `pointerup`/`pointercancel` release capture
automatically so there is no listener bookkeeping to leak. Clamp every computed size into
`[MIN_PANE_SIZE_PX, MAX]` and call `applyPaneState()`; persist (the guarded write) once on
`pointerup`, not on every move frame.

**Keyboard — mandatory.** On `keydown` on a focused splitter: ArrowLeft/ArrowRight adjust the
vertical splitter, ArrowUp/ArrowDown the horizontal one, each by the module's step constant;
Home/End jump to `aria-valuemin`/`aria-valuemax`. `preventDefault()` on the keys you handle so the
page does not also scroll, and leave every other key alone so `shell.js`'s `handleKeydown` is
untouched. Persist on keyup or after each step — either is fine, the write is guarded.

**ARIA sync.** `aria-valuenow`, `aria-valuemin` and `aria-valuemax` are set as the controlled
pane's size in px (not an abstract 0–100 slider value) and **updated on every resize, drag and
keyboard alike** — a stale `aria-valuenow` is worse than none, because assistive technology reports
a size the pane no longer has. Set them once in `applyPaneState()` so there is a single place that
can drift, rather than in each handler.

Cross-page: all three pages get identical splitter markup (D-21 keeps the shell identical).
  </action>

**Collapse is a distinct state from resized-to-minimum.** Dragging stops at `MIN_PANE_SIZE_PX` and
never silently collapses — a user dragging something small and a user clicking collapse are
different intents. Collapse applies an `.is-collapsed` class that sets the pane's grid track to the
collapsed-rail size (~32–40px, enough that the chevron stays visible and focusable) and hides the
pane's inner content. **Use the `.is-collapsed` class mechanism, not `element.hidden = true`** —
the `[hidden]`-vs-ID-specificity bug above was fixed once already with a global `!important` rule,
and the point of using a class here is to stay out of that specificity category entirely rather
than relying on that rule bailing the plan out a second time. Do not use `display: none` on the
whole pane, or the chevron that expands it disappears with it.

operator actually chose, not `MIN_PANE_SIZE_PX`. Persist collapse state alongside the sizes.

When a pane is collapsed, its splitter is not meaningfully draggable — set `aria-disabled="true"`
and skip the drag/keyboard handlers for that splitter while collapsed, rather than letting the
operator drag a collapsed pane to a size that is then immediately overridden.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → CSS custom property | A stored pane-size string is read back and written into a CSS custom property. Same-origin only, but the value must be parsed and clamped, never passed through. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.1-11 | Tampering | `localStorage` pane-size value → `setProperty` | mitigate | `parseInt(value, 10)` + `Number.isFinite` + clamp into `[MIN_PANE_SIZE_PX, MAX]` before any `setProperty`; allow-list the collapse booleans, mirroring `groupingMode()`'s `"folder"`/`"device_type"` allow-list rather than a passthrough |
| T-11.1-12 | Denial of Service (self-inflicted) | unguarded `localStorage` access | mitigate | Every read and write individually wrapped in `try/catch` — an unguarded access already took the entire shell down once in Phase 11; acceptance requires demonstrating a blocked-storage browser still renders |
| T-11.1-13 | Denial of Service (accessibility lockout) | splitter keyboard handling | mitigate | Arrow/Home/End handled with `preventDefault` scoped to the focused splitter only; every other key falls through so `shell.js`'s `handleKeydown` Enter/Space navigation is unaffected, asserted in acceptance |
| T-11.1-SC | Tampering | npm/pip/cargo installs | mitigate | No splitter library is vendored or installed; the ~150-line hand-roll keeps the audit surface at one reviewable file, and the repo has no package manager for frontend code |
</threat_model>
