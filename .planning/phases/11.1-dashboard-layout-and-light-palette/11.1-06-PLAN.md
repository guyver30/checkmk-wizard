contract, a `usePaneLayout` hook whose in-memory state is the session source of truth over guarded

constraint is satisfied structurally here: the layout takes pane contents as props, so later plans
fill slots without restructuring the grid.

map placeholder.
</objective>

  <behavior>
    - `readJson(key, fallback)` returns the parsed stored value, returns `fallback` when the key is absent, and returns `fallback` without throwing when `localStorage.getItem` throws.
    - `readJson` returns `fallback` when the stored string is not valid JSON.
    - `writeJson(key, value)` returns `true` on success and `false` (without throwing) when `localStorage.setItem` throws.
    - A `Splitter` renders an element with `role="separator"`, `aria-orientation` matching its prop, and `aria-valuenow`/`aria-valuemin`/`aria-valuemax` reflecting the current size.

    - ArrowUp/ArrowDown on a horizontal separator do the same.
    - Home/End call `onResize` with the min and max respectively.
    - A pointerdown → pointermove → pointerup sequence calls `onResizeCommit` exactly once, on pointerup.
    - Keyboard events that are not arrow/Home/End are ignored and do not call `onResize`.

Create `src/lib/guardedStorage.ts` exporting `readJson<T>(key: string, fallback: T): T` and
`writeJson(key: string, value: unknown): boolean`, both wrapping every `localStorage` access in
try/catch. Head the file with a comment recording WHY: `localStorage` access throws (it does not
return null) when site data is blocked, and D-26 makes the in-memory value the source of truth for
the session — storage is only how a value survives a reload, and a refused write must never break
the interaction. This is the same rule `dashboard/js/render-shell.js`'s `groupingModeOverride` fix
established in Phase 11.

Create `src/components/Splitter.tsx` as a controlled component with props
`{ orientation: "vertical" | "horizontal"; value: number; min: number; max: number; step?: number;
label: string; onResize: (next: number) => void; onResizeCommit?: (next: number) => void }`, where
`value`/`min`/`max` are pixel sizes of the pane the splitter sizes and `step` defaults to 16.
`orientation` follows the ARIA meaning: a separator between a left and a right pane is
`aria-orientation="vertical"`.

Render a single focusable `<div role="separator" tabIndex={0} aria-orientation={orientation}
aria-valuenow={value} aria-valuemin={min} aria-valuemax={max} aria-label={label}>` styled with the
design-system tokens (`bg-neutral-150 hover:bg-neutral-300 focus:shadow-focus`), sized 4px on its
thin axis with `cursor-col-resize` / `cursor-row-resize` and `select-none`. Write both cursor
classes literally in the source (a ternary picking between two whole literal class strings) so
Tailwind's content scanner finds them.

Keyboard: handle ArrowLeft/ArrowRight for vertical and ArrowUp/ArrowDown for horizontal, plus
Home/End; clamp every result into `[min, max]`, call `onResize`, then `onResizeCommit`, and
`preventDefault()` so the page does not scroll. Ignore every other key. Keyboard equivalence is
mandatory — without it this is a WCAG 2.1.1 failure and it would undo the keyboard work Phase 11
already did in `shell.js`'s `handleKeydown`.

Pointer: use Pointer Events with `setPointerCapture` on pointerdown so a fast drag that leaves the
element still tracks. During `pointermove`, call `onResize` on each move; on `pointerup`, release
capture and call `onResizeCommit` exactly once. RESEARCH recommends ref-driven DOM mutation during
drag with a single committed setState on release to avoid re-render thrash — keep the
`onResize`/`onResizeCommit` split so the consumer can choose that, but do not build any further
optimisation machinery in this plan.

Write `Splitter.test.tsx` with `@testing-library/react` + `@testing-library/dom`'s `fireEvent`

implement them) — note that stub in a comment so a future reader does not mistake it for a bug.

  <read_first>

  </read_first>
  <behavior>
    - On first mount with empty storage, the hook returns the default sizes (tree 320px, event pane 260px) and both panes uncollapsed.
    - On mount with a valid persisted record, the hook returns the persisted sizes.
    - On mount with a corrupt persisted value, the hook returns defaults without throwing.
    - On mount with a persisted size outside `[min, max]`, the hook clamps it into range rather than honouring it.
    - `setSize("tree", 480)` updates the returned size immediately (in-memory is the source of truth).
    - `commit()` writes the current record to storage; with `localStorage.setItem` throwing, `commit()` still leaves the in-memory size at its new value.
    - `toggleCollapse("events")` flips that pane's collapsed flag and persists it; collapsing does NOT discard the stored size, so restoring returns to the previous size rather than the default.
  </behavior>
  <action>
Create `src/hooks/usePaneLayout.ts` exporting `usePaneLayout()` returning
`{ sizes: { tree: number; events: number }, collapsed: { tree: boolean; events: boolean },
setSize, toggleCollapse, commit, bounds }`. Only two splitters exist in this layout: one vertical
(tree width) and one horizontal (event-history height); the centre-top pane takes the remaining
space, so it has no stored size of its own.

Use the storage key `"dashboard-react.paneLayout.v1"` holding
`{ treeWidth: number; eventsHeight: number; treeCollapsed: boolean; eventsCollapsed: boolean }`.
Version the key so a future shape change cannot be misread as a valid record.

Defaults: `treeWidth: 320`, `eventsHeight: 260`. Bounds: tree `[200, 640]`, events `[120, 600]`.
Read persisted state ONCE via `useState`'s lazy initialiser calling `readJson` (not in a
`useEffect`, which would flash the default first); clamp every persisted number into its bounds and
fall back per-field, so one bad field does not discard a good sibling.

React state is the session source of truth (D-26). `setSize` updates state unconditionally;
`commit` calls `writeJson` and deliberately ignores its `false` return — a refused write must never
break the interaction, and must never roll the in-memory value back. Put that rule in a comment at
the `commit` call site, not only in the header.

Note in the file header that D-26's "a resize must not be undone by the next tick" constraint is
satisfied structurally here: pane size lives in this hook's state, not in any time-derived render
path, so no clock tick can overwrite it.

Write `usePaneLayout.test.ts` using `@testing-library/react`'s `renderHook` and `act`, seeding
`localStorage` directly per case and restoring it in `afterEach`.
  </action>
