## Accomplishments

- Confirmed, by direct code reading, that `scripts/mqtt_poller.py`'s `run_cycle()` builds `events_this_cycle` via three `.append(...)` call sites in cycle order (tombstone/removed at line 1053, added-device at line 1064, state-change at line 1077) and concatenates it onto the END of `state.events` (line 1098: `state.events = (state.events + events_this_cycle)[-config.events_max_entries :]`) — i.e. the published `lan/events/recent` array is oldest-first.

- Added two regression tests to `tests/test_mqtt_poller.py` that assert the FULL array order (not membership, not `entries[-1]`):
