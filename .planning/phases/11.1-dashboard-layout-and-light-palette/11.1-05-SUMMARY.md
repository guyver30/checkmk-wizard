# Phase 11.1 Plan 05: Data Layer — Port, Store, MQTT Client Summary

**Ported the vanilla dashboard's `display.js`/`staleness.js`/`grouping.js` into typed, unit-tested pure modules, wired them into a Zustand store with wholesale-replace slices and defensive drop-on-malformed message routing, and added a module-level `mqtt.js` singleton that drives its own jittered exponential-backoff reconnect loop — all three layers reproduce the vanilla dashboard's behavior exactly, with 49 new tests and 0 new dependencies.**

## Accomplishments
- `src/lib/types.ts` declares the untrusted-JSON payload shapes (`DevicePayload`, `HistoryEntry`, `EventEntry`, `TopologyPayload`, `PollerStatusPayload`, `GroupingMode`) every other module in this plan builds on, every field optional by design.
- `src/lib/display.ts`, `src/lib/staleness.ts`, `src/lib/grouping.ts` are line-for-line behavioral ports of `dashboard/js/{display,staleness,grouping}.js`, keeping every defensive `null`/wrong-type guard, the locked icon-class-name tables, the D-12/D-17 staleness-factor reasoning, and the D-15 "stale never masks known-bad" roll-up rule — the only structural change is that `grouping.ts` imports `isDeviceStale`/`effectiveState` explicitly instead of relying on vanilla JS globals.
- `src/store/useAppStore.ts` is a `create<AppState>()` Zustand store with `devices`/`history`/`events`/`topology`/`pollerStatus`/`lastKnownPollerTimestamp`/`connection` slices, porting `state-store.js`'s `parsePayload`/`isPlainObject`/topic-routing verbatim: a zero-length `lan/devices/{id}/status` payload tombstones both the device and its history entry, malformed or wrong-shaped payloads are dropped without throwing, and every write uses Zustand's default merge (the replace flag is never passed at the top level).
- `src/store/mqttClient.ts` is a module-level singleton (not a hook, not an effect body) immune to React StrictMode's double-invoked effects, disabling `mqtt.js`'s fixed-interval `reconnectPeriod` in favor of its own `min(30000, 1000 * 2**attempt) * (0.5 + jitter*0.5)` backoff driven from the `close` event, with an injectable `{connectFn, randomFn, setTimeoutFn}` seam that makes the exact delay sequence unit-testable without a broker or real timers.
- 49 new tests (32 in `src/lib`, 9 in `useAppStore.test.ts`, 8 in `mqttClient.test.ts`) plus the 3 pre-existing tests from plan 04 — 52 total, all passing.
