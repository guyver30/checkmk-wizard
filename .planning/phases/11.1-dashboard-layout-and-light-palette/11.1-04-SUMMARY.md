## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `typecheck` script was a silent no-op; switched to `tsc -b --noEmit`**
- **Found during:** Task 3, running `npm run build` after `npm run typecheck` had already reported success
- **Issue:** The plan's literal script (`"typecheck": "tsc --noEmit"`) runs against the project's root `tsconfig.json`, which is a TypeScript *solution* file (`"files": []`, only `references` to `tsconfig.app.json`/`tsconfig.node.json`, no `include`). A bare `tsc --noEmit` invoked there has nothing to compile and exits 0 having checked zero files — it silently passed even with a real type error present (confirmed by injecting `const _x: string = 123` into `App.test.tsx`: the old script reported no error; `npm run build`'s `tsc -b` step, which *does* walk the project references, caught it immediately).
- **Fix:** Changed the script to `"typecheck": "tsc -b --noEmit"`, matching the build mode `npm run build` already uses. Re-verified with the same injected error (caught) and reverted the injection.
- **Also required:** `@testing-library/jest-dom`'s `expect().toBeInTheDocument()` augmentation lives at the `@testing-library/jest-dom/vitest` subpath, not the bare package export, and `vitest.setup.ts` (which imports it) sits outside `tsconfig.app.json`'s `include: ["src"]`, so the augmentation wasn't visible when `tsc -b` actually checked `src/App.test.tsx`. Added `"@testing-library/jest-dom/vitest"` to `tsconfig.app.json`'s `compilerOptions.types` to fix it directly, rather than moving `vitest.setup.ts` into `src/`.
- **Files modified:** `dashboard-react/package.json`, `dashboard-react/tsconfig.app.json`
- **Verification:** `npm --prefix dashboard-react run typecheck` now genuinely walks the project (confirmed both the pass case and, via a temporary injected error, the fail case), and `npm run build`'s own `tsc -b` step is unaffected (it always worked).
- **Committed in:** `7aaa06a` (Task 3 commit)

**2. [Rule 3 - Blocking] Switched all authored TSX/TS import strings to double quotes**
- **Found during:** Task 3, checking the plan's stated acceptance criterion `grep -q 'from "react-router"' dashboard-react/src/App.tsx`
- **Issue:** `npm create vite@latest` generates single-quoted, semicolon-free source by default; my first draft of `App.tsx`/`main.tsx`/routes/`config.ts`/`App.test.tsx` followed that style, which does not match the plan's literal double-quoted grep check.
- **Fix:** Rewrote those files using double-quoted strings + semicolons, matching `design-system/src/components/*.tsx`'s existing convention (the closest sibling package in this repo) as well as satisfying the acceptance-criteria grep exactly. `vite.config.ts` (scaffold-generated, not covered by any grep) was left in its original single-quote style to avoid unrelated churn.
- **Files modified:** `dashboard-react/src/{App.tsx,main.tsx,App.test.tsx,lib/config.ts,routes/*.tsx,vitest.setup.ts}`
- **Verification:** `grep -q 'from "react-router"' dashboard-react/src/App.tsx` succeeds; `npm test`/`npm run typecheck`/`npm run build` all still pass after the rewrite.
- **Committed in:** `7aaa06a` (Task 3 commit)

**3. [Rule 1 - Bug] Also deleted `public/icons.svg` (unreferenced after the demo body was removed)**
- **Found during:** Task 3, after rewriting `App.tsx` to drop the Vite/React counter demo body
- **Issue:** The plan's Task 2 action text names three files to delete (`src/App.css`, `src/assets/`, `public/vite.svg`), but this create-vite template version generates the demo icons at `public/icons.svg` (referenced only by the demo body's `<use href="/icons.svg#...">` tags, not named in the plan) rather than the `public/vite.svg` the plan expected (this template puts its Vite logo at `src/assets/vite.svg` instead, which the plan's `src/assets/` deletion already covers).
- **Fix:** Deleted `public/icons.svg` alongside the planned deletions once `App.tsx`'s rewrite made it fully unreferenced; confirmed via `grep -rn "icons.svg"` across `src/` and `index.html` that nothing pointed at it anymore before removing it.
- **Files modified:** `dashboard-react/public/icons.svg` (deleted)
