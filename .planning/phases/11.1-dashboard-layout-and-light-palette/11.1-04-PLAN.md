Create `scripts/contrast_audit.py` as a standalone `uv run` script (a `uv run --script` PEP-723
header is fine; it needs only `re`/`sys`/`pathlib` from the standard library, so add **no**
dependency and do not touch `pyproject.toml`).

Structure:

1. `_parse_root_tokens(css_text) -> dict[str, str]` — regex-extract every `--name: #rrggbb;`
   declaration from inside the `:root { ... }` block of `dashboard/css/dashboard.css`, resolved
   relative to the script's own location (`Path(__file__).resolve().parents[1] / "dashboard" /
   "css" / "dashboard.css"`) so it works from any cwd. Reading the real file is what makes the
   audit reproducible; never hardcode a transcribed palette.
2. `relative_luminance` / `contrast_ratio` exactly as in RESEARCH.md section 3.
3. A module-level `PAIRS` table of `(foreground_token, background_token, role, label)` where `role`
   is `"text"` (threshold 4.5) or `"mark"` (threshold 3.0). Build it by reading `dashboard.css` and
   enumerating every place a `color` is rendered against a `background-color`/`background` — the
   token pair, the parent/child pair, and the inline-styled pair. At minimum it MUST include:
   - `--color-text` on `--color-bg`, on `--color-surface`, on `--color-surface-raised`
   - `--color-text-muted` on `--color-bg` and on `--color-surface`
   - `--color-accent-text` and `--color-accent` on `--color-bg`
   - `--color-border` on `--color-bg` as a `mark`
   - ink `#141414` on each of the eight `--state-*-fill` tokens, as `text`
   - each of the eight `--state-*-ink` tokens on `--color-bg`, as `text`
   - each of the eight `--state-*` saturated tokens on `--color-bg`, as `mark` — these are the
     marks Phase 12/13 will place on a light surface
   - **`--state-down` (`#f51414`) on `--color-bg`** — research computed 4.21:1, the tightest colour
     in the whole palette. Assert it by name, do not let it hide in a loop.
   - **`--state-pend` (`#959595`, grayscale."300 disabled"`) on `--color-bg`** — exactly 3.00:1.
     Assert it by name; it clears `mark` and fails `text`, so it must be classified `mark`.
   - **the connection dot's RING**: `--color-border` against `--color-surface` (the topbar), role
     `mark`, labelled so the report says the ring is the contrast-bearing edge per D-39 — **not**
     `--state-ok` against the topbar, which is the fill D-39 deliberately keeps saturated.
   Aim for at least 20 pairs, matching the coverage CONTEXT.md describes.
4. `main()` — print a fixed-width table of `label | fg | bg | ratio | threshold | PASS/FAIL`,
   count failures, print a summary line, and `sys.exit(1)` if any pair fails, `sys.exit(0)`
   otherwise.
5. A module docstring explaining that this is a dev-time check never shipped to the browser, citing
   D-30, D-38 and D-39, and stating that the formula was validated against D-29's published
   numbers.

Add a self-check: assert at import/`main()` time that the computed ratios for `#1ed273`-on-white,
`#ffa023`-on-white and `#ffe141`-on-white are 2.00, 2.04 and 1.30 to two decimal places. If those
drift, the formula implementation is wrong and the whole report is untrustworthy — fail loudly
rather than reporting confidently wrong numbers.

Per CLAUDE.md, every invocation is `uv run`. Never bare `python`/`python3`.
