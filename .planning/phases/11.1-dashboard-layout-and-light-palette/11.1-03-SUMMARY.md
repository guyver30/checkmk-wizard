# Phase 11.1 Plan 03: Three-Tier Light Palette and Palette-Adjacent Defects Summary

Replaced the dashboard's dark KONE palette with the light palette as a strict CSS-only token
swap: eight saturated `--state-*` mark tokens kept byte-identical, seven new pale `--state-*-fill`
tokens for the `.state-*` background rules, and seven new d40 `--state-*-ink` tokens for the
`.icon.state-*` family — plus four palette-adjacent defects (stale hatch, brand-logo chip,
white-on-white raised surfaces, and the connection dot's sub-3:1 mark) fixed in the same file.
Zero JavaScript files touched.

## What Was Built

**Task 1 — Three-tier light token block and the seven `.state-*` re-points (D-28, D-29, D-38).**
Edited the `:root` block in `dashboard/css/dashboard.css`:
- Semantic surfaces re-derived to KONE's light set: `--color-bg: #ffffff`, `--color-surface:
  #f3f6fe`, `--color-surface-raised: #ffffff` (deliberately same as bg — made distinguishable by
  a border in Task 2), `--color-border: #d0d0d0`, `--color-text: #141414`, `--color-text-muted:
  #727272`, `--color-accent-text: #1450f5` (re-derived from blue.l40, which fails AA on white at
  2.82:1).
- The eight `--state-*` mark tokens are untouched, with a new comment explaining why they must
  stay saturated (read directly by `render-shell.js`'s inline connection-dot assignment today,
  and by Phase 12/13 consumers later).
- Seven new `--state-*-fill` tokens (pale l80-step backgrounds), including a derived
  `--state-warn-fill: #fff9d9` since KONE's yellow has no ramp — documented as an exact 20%
  yellow-on-white alpha blend (not the ~18% approximation research floated; recomputed and
  verified the exact blend that reproduces `#fff9d9`).
- Seven new `--state-*-ink` tokens (d40 shades) for state-as-text/state-as-icon rendering.
- The seven `.state-*` background rules re-point to `-fill`; the parallel (currently-unused,
  forward-compatible) `.icon.state-*` family re-points to `-ink`.
- `.overview-card[data-state]` deliberately left untouched (deleted by a later plan, 11.1-05).
- No hardcoded white text (`color: #fff`/`color: white`) exists anywhere in the file — grepped and
  confirmed absent, so the "ink beats white on every fill" requirement (D-29 fact 2) is satisfied
  automatically once `--color-text` becomes `#141414`, since `.state-label` (the only rule that
  renders text directly on a `.state-*` fill, verified by reading its two call sites in
  `render-devices.js` and `render-shell.js`) already reads `color: var(--color-text)`.

**Task 2 — Four palette-adjacent defects (D-29, D-39).**
- `.is-stale`'s hatch stop changed from `rgba(255,255,255,0.06)` to `rgba(20,20,20,0.08)` — still
  `background-image`-only, no `background-color` added, preserving D-15 composability.
- `.brand-logo`'s `background: #ffffff` / `padding: 4px 6px` / `box-sizing: content-box` removed
  entirely (chosen over a border-framed alternative) — the topbar is now `#f3f6fe`, 1.08:1 against
  pure white, so the logo's own baked-in white background reads fine unframed.
- `--color-surface-raised` consumers: `#tag-group-banner` and `.count-badge` gained `border: 1px
  solid var(--color-border)`; `#device-table tr:hover` re-pointed to `--color-surface` instead
  (a border would shift row heights on hover); `#poller-banner`'s `rgba(114,114,114,0.2)` tint was
  kept but also given a `border-bottom` (chosen over raising the alpha) since the blended tint
  alone is only ~1.28:1 against white and barely reads as a distinct row.
- `.connection-dot` gained `border: 1px solid var(--color-border)` plus `box-sizing: border-box`
  (keeping it 8px total) — the mark's saturated fill is untouched, satisfying D-39's explicit
  "ring, not desaturation" instruction.

**Note on `--state-warn-fill`'s derivation comment:** the plan/research text describes the yellow
alpha blend as "~18%". Recomputing the blend against the locked target hex `#fff9d9` shows the
exact value is 20% (both the G and B channels solve exactly to alpha=0.20), not ~18%. The comment
written into the CSS documents the precise 20% figure so the derivation is reproducible to the
exact hex, rather than transcribing the approximate figure from research. This is not a deviation
in the token value (still `#fff9d9`, the locked one) — only in the documented derivation math,
made more precise. Not logged as a Rule 1-4 deviation since no code behavior changed, only comment
accuracy.
