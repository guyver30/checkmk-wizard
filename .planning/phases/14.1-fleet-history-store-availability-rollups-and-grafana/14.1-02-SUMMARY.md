# Phase 14.1 Plan 02: Poller ClickHouse History Write Path Summary

**Poller writes per-cycle metric, host-state, and service-state rows to ClickHouse over a stdlib-urllib HTTP choke point, degrading to a logged warning (never a crash) when ClickHouse is unreachable.**

- **Completed:** 2026-09-30T10:07:29+08:00

## Accomplishments
- New `ClickHouseError` + `_clickhouse_request`/`_clickhouse_insert`/`_clickhouse_query`/`_clickhouse_command`: one normalized HTTP choke point for every ClickHouse call the poller (and future plan 14.1-05) makes, with header-based auth and a hard-coded table allowlist protecting the interpolated INSERT statement (T-14.1-08).
- `PollerConfig` gained `clickhouse_url`/`clickhouse_writer_user`/`clickhouse_writer_password`/`clickhouse_timeout_seconds`, env-sourced via `from_env()`; the writer password is masked in `__repr__` and never appears in any exception message (T-14.1-10).
- `build_history_rows()`: a pure, never-raising transform from one cycle's `DeviceSnapshot`/`ServiceSnapshot` lists into exactly the three history tables' row shapes (D-42/D-43), skipping non-finite `perf_data` values and never carrying `plugin_output` or any other non-contract field into a row.
- `write_history()`: inserts each of the three tables separately, catching `ClickHouseError` per table so one bad batch (e.g. a rejected metrics insert) still lets host/service state land — the failure degrades to a logged "gap reads as no data" warning (D-44/D-47), never an exception that could interrupt the poll loop.
- Wired into `run_forever()`'s poll loop and `main()`'s `--once` path, in both cases immediately after the existing MQTT publish call (`run_cycle(...)`), plus a startup info log stating whether history writes are enabled (never logging the password).
- 32 new tests (21 for the choke point/config, 11 for `build_history_rows`/`write_history`); full suite green (593 passed), ruff clean.
