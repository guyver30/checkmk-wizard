**GET-only nginx allowlist proxy to ClickHouse and MinIO rollup objects (envsubst template, two 404 catch-alls, credential-override guards) plus a 12-check standalone smoke test proving every write/admin/system path is refused and Grafana requires login**

## Accomplishments
- `deploy/dashboard-nginx.conf` now exposes exactly one read-only ClickHouse endpoint (`/ch-api/`) and two read-only rollup object shapes (`/availability/...`), with every other path under those prefixes 404ing and every non-GET method 403ing
- `deploy/dashboard.Containerfile` installs the config as an nginx envsubst template so `${CH_READER_PASSWORD}` and `${NGINX_LOCAL_RESOLVERS}` are substituted at container start rather than baked into the tracked file
- `scripts/smoke_test_history_proxy.py` gives the operator one command that proves the read path, the refusal of every write/admin/system-table/credential-override path, and Grafana's login gate (HIST-08, HIST-09, HIST-10)

## Files Created/Modified
- `deploy/dashboard-nginx.conf` - envsubst template; added server-level `resolver ${NGINX_LOCAL_RESOLVERS}`, `location = /ch-api/` (GET-only, forces `dashboard_reader` identity via `X-ClickHouse-User`/`X-ClickHouse-Key` headers, strips `Authorization`, rejects `?user=`/`?password=`), bare-prefix + catch-all 404s for `/ch-api`, a named-capture regex location for the two rollup object key shapes proxied to MinIO with no credential forwarded, and bare-prefix + catch-all 404s for `/availability`; existing `location /` and `location /checkmk-api/` blocks left byte-for-byte unchanged
- `deploy/dashboard.Containerfile` - config now installed at `/etc/nginx/templates/default.conf.template` instead of `/etc/nginx/conf.d/default.conf`, with a comment citing the verified entrypoint behavior
- `scripts/smoke_test_history_proxy.py` (new) - standalone, stdlib-only (`urllib`, `json`, `base64`, `argparse`, `datetime`/`zoneinfo`) live smoke test with 12 `check_*` functions and a `main()` that aggregates to an exit code; not pytest-collected

## Decisions Made
- Confirmed both official nginx-image entrypoint behaviors by fetching the actual scripts from `github.com/nginxinc/docker-nginx` (`entrypoint/20-envsubst-on-templates.sh` and `entrypoint/15-local-resolvers.envsh`) rather than relying on prior knowledge, per the task's explicit read_first/action instruction. `20-envsubst-on-templates.sh` builds its substitution allowlist (`defined_envs`) purely from `ENVIRON`, confirming nginx's own `$uri`/`$arg_*`/`$is_args`/`$args` variables are never substituted since they are not environment variables. `15-local-resolvers.envsh` confirms `NGINX_LOCAL_RESOLVERS` is exported from `/etc/resolv.conf` only when `NGINX_ENTRYPOINT_LOCAL_RESOLVERS` is set.
- `check_ch_write_over_get_denied` re-queries the table after the denied INSERT attempt and asserts the row count is still zero, rather than trusting the HTTP status code alone — matches the plan's explicit ask and this project's "don't trust a single signal for a security property" posture.
- No container runtime (`podman`/`docker`) or `nginx` binary was available in this worktree, so the Containerfile build and nginx syntax check named in the plan's acceptance criteria as optional ("if a container runtime is available... otherwise this is proven at plan 14.1-08") were not run here; this is consistent with the plan's own deferral to 14.1-08.
