## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (via nginx) → ClickHouse | dashboard_reader queries are attacker-controllable SQL text |
| Grafana → ClickHouse | analyst-authored SQL, not validated by Grafana |
| ClickHouse → MinIO/S3 | S3 disk uses the MinIO root credentials (D-56) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14.1-01 | Elevation of Privilege | dashboard_reader / grafana_reader | mitigate | Settings profile readonly = 1 (server-enforced, client cannot override), SELECT on history.* only, no system.* grants |
| T-14.1-02 | Tampering | history tables via reader users | mitigate | No INSERT/ALTER/DROP grants; readonly = 1 blocks writes and DDL even if a grant were mistakenly added |
| T-14.1-03 | Information Disclosure | S3 credentials and DB passwords | mitigate | from_env in s3-storage.xml; passwords only from container env (deploy/.env); script never echoes values |
| T-14.1-04 | Spoofing | weak or empty DB passwords | mitigate | 02-users.sh exits 1 on empty or quote/space-containing passwords before creating any user |
| T-14.1-05 | Denial of Service | heavy reader queries | mitigate | max_execution_time 30 s, capped at 60 s by a MAX constraint in history_reader_profile |
| T-14.1-06 | Denial of Service | metric key cardinality | mitigate | Keys limited to host/service/metric LowCardinality columns; no free-text columns (Pitfall 5) |
| T-14.1-07 | Information Disclosure | MinIO root creds on the S3 disk | accept | D-56 reuses root credentials by decision; they stay inside cmk_net and env vars |
</threat_model>
