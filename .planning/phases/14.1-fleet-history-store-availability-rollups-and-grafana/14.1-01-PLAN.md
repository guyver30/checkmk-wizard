<interfaces>
Metric contract (consumed by 14.1-02 and 14.1-05; names are fixed by this plan):
- checkmk_host_state{host, folder}: 0=UP, 1=DOWN, 2=UNREACH (mapped from DeviceSnapshot.host_state_raw values "UP"/"DOWN"/"UNREACH")
- checkmk_host_in_downtime{host, folder}: 1 if DeviceSnapshot.in_downtime else 0
- checkmk_service_state{host, service}: ServiceSnapshot.state_raw (0..3)
- checkmk_perf_value / checkmk_perf_warn / checkmk_perf_crit / checkmk_perf_min / checkmk_perf_max {host, service, metric}: one family per parse_perf_data() field, a sample only where the field is not None and is finite
- checkmk_poller_last_cycle_timestamp_seconds (no labels): unix time of the last successful cycle
Prometheus adds job="poller" and instance="poller:9200" at scrape time.

Existing code (scripts/mqtt_poller.py):
- DeviceSnapshot fields used: id, folder, in_downtime, host_state_raw ("UP"|"DOWN"|"UNREACH", see host_state_label())
- ServiceSnapshot fields used: host_name, description, state_raw, perf_data (dict[str, dict] from parse_perf_data(): keys value/warn/crit/min/max, float or None)
- PollerConfig: dataclass with defaulted trailing fields, __repr__ written by hand, from_env() using _env_int()
- run_forever(config): the `else:` branch after `snapshots = query_devices(...)` calls run_cycle(...); `services` is None when the services query failed this cycle
- Tests load the module via importlib spec (tests/test_mqtt_poller.py lines 1-22); run_forever tests patch module attributes with patch.object(poller, ...) and build configs with a _make_config() helper
</interfaces>
