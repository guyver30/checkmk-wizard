Server-level `resolver ${NGINX_LOCAL_RESOLVERS} valid=10s ipv6=off;` with a comment: the new upstreams are proxied through variables so nginx resolves clickhouse/minio per request; a stopped history container then yields 502 on its path instead of stopping the whole dashboard from starting (the existing /checkmk-api/ keeps its static proxy_pass and the depends_on it already has).

Comment: two independent read-only layers (nginx GET-only here; ClickHouse's readonly = 1 profile and HTTP-GET-implies-readonly server-side, verified via context7 ContextAccess.cpp); proxy_set_header replaces any client-sent X-ClickHouse-User/Key header; nginx's proxy_pass does not support user:password@ in the URL, which is why the headers carry the credential (ClickHouse HTTP interface docs).
3. `location = /ch-api { return 404; }` (bare prefix without trailing slash, otherwise it would fall through to the SPA's index.html with 200) and `location /ch-api/ { return 404; }` catch-all so /ch-api/play, /ch-api/ping, /ch-api/replicas_status, /ch-api/dashboard and anything else under the prefix never reaches ClickHouse (and never falls through to the SPA's index.html).
4. Regex location for the two rollup object shapes with a named capture: `location ~ "^/availability/(?<rollup_key>availability/[0-9]{4}/[0-9]{2}/[0-9]{4}-[0-9]{2}-[0-9]{2}\.json|availability_parquet/date=[0-9]{4}-[0-9]{2}-[0-9]{2}/availability\.parquet)$"` containing `limit_except GET { deny all; }`, `proxy_set_header Authorization "";`, `set $minio_upstream minio;`, `proxy_pass http://$minio_upstream:9000/fleet-availability/$rollup_key;`. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN browser → nginx /ch-api/ | untrusted method, path, query string, headers |
| LAN browser → nginx /availability/ | untrusted method and path |
| nginx → ClickHouse / MinIO | internal cmk_net hop carrying the reader credential |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14.1-16 | Elevation of Privilege | /ch-api/ | mitigate | GET only (limit_except), user/password args rejected, Authorization stripped, X-ClickHouse-User forced to dashboard_reader; server-side readonly = 1 is the second layer |
| T-14.1-17 | Elevation of Privilege | ClickHouse admin/UI endpoints (/play, /dashboard, /ping, /replicas_status) | mitigate | Exact-match location for / only plus catch-all 404 on the prefix (RESEARCH A1) |
| T-14.1-18 | Tampering | rollup objects | mitigate | GET only, only two key regexes proxied, no credential forwarded, bucket policy download-only |
| T-14.1-19 | Information Disclosure | reader password | mitigate | Injected from env at container start via envsubst; never in the tracked file or the browser; nginx adds it only on the upstream hop |
| T-14.1-20 | Information Disclosure | bucket listing | mitigate | Listing URLs match no allowed regex and hit the 404 catch-all |
| T-14.1-21 | Denial of Service | dashboard startup when history containers are down | mitigate | Variable-based proxy_pass with a resolver, so nginx starts without clickhouse/minio |
| T-14.1-22 | Denial of Service | expensive reader queries | accept | Trusted LAN (D-24); bounded by the 30 s (max 60 s) max_execution_time in history_reader_profile |
</threat_model>
