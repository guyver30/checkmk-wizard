### `scripts/mqtt_poller.py` (service, extended)

**Analog:** itself — this module's own established conventions (no external file needed; the new code must fit the same module, so its own patterns are the analog).

**Imports pattern** (top of file, `from __future__ import annotations` then stdlib-only imports — confirmed live this session, no `httpx`/`asyncio` anywhere in this file):
```python
from __future__ import annotations

import json
import logging
import os
import socket
import threading
import time
import urllib.error
import urllib.parse
import urllib.request
# new for this phase: import boto3 (rollup JSON writer), import zoneinfo (day-boundary math)
```
Follow this exactly: no `httpx`, no `clickhouse-connect` — RESEARCH.md's Standard Stack explicitly rejects both (stdlib `urllib.request` already covers the INSERT/query shape; adding a second HTTP-client convention violates CLAUDE.md's "no dependency for something a few lines of stdlib already does").

**Choke-point HTTP pattern** — copy `fetch_host_config()`'s exact shape (`scripts/mqtt_poller.py:1214-1265`) for the new `_clickhouse_insert()`/`_clickhouse_query()` functions:
```python
def fetch_host_config(base_url: str, username: str, secret: str, timeout: float) -> dict[str, HostConfigInfo]:
    url = f"{base_url}/domain-types/host_config/collections/all"
    try:
        request = urllib.request.Request(
            url,
            headers={
                "Authorization": f"Bearer {username} {secret}",
                "Accept": "application/json",
            },
        )
        with urllib.request.urlopen(request, timeout=timeout) as response:
            data = json.loads(response.read())
    except (
        urllib.error.HTTPError,
        urllib.error.URLError,
        OSError,
        TimeoutError,
        json.JSONDecodeError,
    ) as exc:
        raise RestError(f"REST host-config lookup to {url} failed: {exc}") from exc
    ...
```
The new `_clickhouse_insert()`/`_clickhouse_query()` (RESEARCH.md Pattern 1 and Code Examples) follow this identically: one `try/except` funneling every network failure into a single normalized `ClickHouseError(RuntimeError)` (new class, same style as `LivestatusError`/`RestError` at `scripts/mqtt_poller.py:285-294`), never leaking `urllib.error.HTTPError`/`OSError` to the call site.

**Config pattern** (`PollerConfig`, lines 325-405): every new runtime setting is env-var-sourced, added as a field with a default so no positional `PollerConfig(...)` call breaks, and appended to `from_env()`. Follow exactly for the new ClickHouse/rollup settings (e.g. `CLICKHOUSE_URL`, `CLICKHOUSE_WRITER_USERNAME`, `CLICKHOUSE_WRITER_PASSWORD`, `S3_ENDPOINT`/`S3_ACCESS_KEY`/`S3_SECRET_KEY` — reuse the exact same env var names the `worker` service already sets in `deploy/compose.yaml`, per D-56 — `AVAILABILITY_BUCKET`, `ROLLUP_TZ`):
```python
@dataclass
class PollerConfig:
    ...
    # Appended after existing fields so no positional PollerConfig(...) call site breaks.
    service_history_max_entries: int = DEFAULT_SERVICE_HISTORY_MAX_ENTRIES

    def __repr__(self) -> str:
        # T-09-02: never render secrets. New ClickHouse writer password and
        # S3 secret key fields must be added to this list, masked '***',
        # exactly like mqtt_password/cmk_rest_secret already are.
        ...

    @classmethod
    def from_env(cls) -> PollerConfig:
        return cls(
            ...
            service_history_max_entries=_env_int(
                "SERVICE_HISTORY_MAX_ENTRIES", DEFAULT_SERVICE_HISTORY_MAX_ENTRIES
            ),
        )
```
Reuse `_env_int`/`_env_float` (lines 297-322) for any new numeric env var — never `int(os.environ[...])` directly, since a typo must degrade with a warning, not crash-loop the container. The `PollerConfig.__repr__` override (lines 352-376) must be extended to mask the new `clickhouse_writer_password`/`s3_secret_key` fields the same way `mqtt_password`/`cmk_rest_secret` already are — this is a required edit, not optional, per T-09-02.

**Pure-function transform pattern** — `compute_daily_availability()` (RESEARCH.md Pattern 3) must be written the same way `compute_incidents()` (`scripts/mqtt_poller.py:778-940`) and `parse_perf_data()` (lines 1134-1178) already are: no I/O, deterministic, exhaustively documented with a decision-by-decision docstring, never raises (garbage/absent input degrades to a safe default, e.g. `state_rows == []` returns 100% no-data, not an exception). SQL fetch happens in a separate `_clickhouse_query()` call at the call site; the transform itself takes already-fetched rows as plain Python values (tuples/dicts), exactly like `compute_incidents(snapshots: list[DeviceSnapshot])` takes an already-built snapshot list rather than querying Livestatus itself.

**Per-cycle push pattern** (RESEARCH.md Pattern 1) — call `_clickhouse_insert()` from inside `run_cycle()`'s existing per-cycle block (`scripts/mqtt_poller.py:2233-2429`), immediately after the existing MQTT publish calls, wrapped the same way every other per-cycle enrichment failure already is (log and continue, never abort the cycle):
```python
try:
    _clickhouse_insert(clickhouse_url, "metrics", metric_rows, timeout=5.0)
    _clickhouse_insert(clickhouse_url, "host_state", host_state_rows, timeout=5.0)
    _clickhouse_insert(clickhouse_url, "service_state", service_state_rows, timeout=5.0)
except ClickHouseError as exc:
    _logger.warning("ClickHouse write failed this cycle; gap reads as no-data (D-47): %s", exc)
```
This mirrors the existing REST-folder-lookup non-fatal posture at `run_forever()`'s startup probe section (lines 2507-2545: "services only enrich... disables... until a restart re-probes", never treated as fatal to the whole poller) — D-44 requires the exact same "degrade, never crash" contract for the ClickHouse write path.

**Loop/scheduling pattern** — the midnight rollup + auto-backfill job (D-51/D-52, RESEARCH.md Pitfall 6) is scheduled inside `run_forever()`'s existing loop, which already owns `stop_event`/signal handling (lines 2561-2567) and the poll-interval sleep. Follow the existing pattern of computing a bounded retry/delay list as a module-level constant (`_STARTUP_RETRY_DELAYS_SECONDS`, referenced at line 2479) rather than inventing a new scheduling primitive — a simple "has local-midnight passed since last run, or is a backfill day missing" check each poll cycle is sufficient at 15s granularity; no new thread or async scheduler needed (matches D-44's "no separate retry queue, no on-disk state" and the module's existing single-threaded-plus-one-MQTT-loop-thread shape).

## Shared Patterns

### Single-choke-point error normalization
**Source:** `LivestatusError`/`RestError` classes (`scripts/mqtt_poller.py:285-294`) + `_livestatus_request()` (lines 1181-1203) + `fetch_host_config()` (lines 1214-1265)
**Apply to:** the new `ClickHouseError` class and both `_clickhouse_insert()`/`_clickhouse_query()` functions — every network failure funnels through exactly one `try/except` per function, normalized into one exception type, so call sites never need their own connectivity error handling.
```python
class RestError(RuntimeError):
    """Raised for any Checkmk REST network failure or malformed response.

    Single normalized failure type for the poller's REST calls, mirroring
    `LivestatusError`'s role for Livestatus.
    """
```

### Env-var-sourced config, never crash on a bad value
**Source:** `_env_int()`/`_env_float()` (`scripts/mqtt_poller.py:297-322`), `PollerConfig.from_env()` (lines 378-405)
**Apply to:** every new ClickHouse/S3/rollup setting — a typo in `deploy/compose.yaml`'s `environment:` block must degrade with a logged warning and a default, never crash-loop the container.

### Never-fatal enrichment failure posture
**Source:** the REST folder-lookup's documented non-fatal reasoning at `run_forever()` (`scripts/mqtt_poller.py:2463-2476`, `2507-2545`)
**Apply to:** the per-cycle ClickHouse write (D-44/D-47: an unreachable ClickHouse drops that cycle's rows, never aborts the poll cycle) and the midnight rollup job (a rollup failure logs and retries next cycle/next midnight, never crashes the poller).

### Secrets never rendered in logs or tracked files
**Source:** `PollerConfig.__repr__()` (`scripts/mqtt_poller.py:352-376`, explicit override masking `mqtt_password`/`cmk_rest_secret`); `deploy/.env.example`'s `CMK_REST_SECRET` entry (gitignored real value, `${VAR:-}` empty-default compose interpolation)
**Apply to:** the new ClickHouse writer/reader passwords and any S3 keys — extend `__repr__` to mask them, and add them to `deploy/.env.example` with the same "generate with `secrets.token_urlsafe`, gitignored, rotate by editing here + recreating the container" documentation style.

### Dated-amendment style for constraint/doc changes
**Source:** `.planning/PROJECT.md:51` / `CLAUDE.md:13` — `*(Revised 2026-09-21, Phase 11.1 D-40: ...)*`, chained a second time on the same line for a later phase's amendment
**Apply to:** the required PROJECT.md/CLAUDE.md "no new backend" amendment (HIST-11, D-24/D-54) — append a third dated parenthetical in the same chained style, do not rewrite the existing two.
