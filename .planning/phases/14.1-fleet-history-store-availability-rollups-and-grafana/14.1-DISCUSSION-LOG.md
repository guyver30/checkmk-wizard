## TSDB re-discussion (2026-09-28, after first planning pass)
User asked to compare InfluxDB 3, ClickHouse, TimescaleDB, Athena + DuckDB against the Prometheus + Thanos plans. Verified via context7:
- InfluxDB 3 Core: ~72 h query range (`--query-file-limit` 432), compaction Enterprise-only, retention immutable → fails D-21 in practice.
- TimescaleDB: S3 tiering only in Tiger Cloud; continuous aggregates TSL-licensed → fails D-23.
- DuckDB/Athena: embedded, no downsampling, Athena AWS-only → fails D-44/D-41.
- ClickHouse: S3 disk on MinIO/AWS by config, TTL TO VOLUME, TTL GROUP BY rollups, HTTP GET readonly → fits all locked decisions.

User follow-up: "what would be easier to implement and scale when moving everything to AWS (and eventually databricks)?" Answer: Prometheus + Thanos is quicker now (already planned); ClickHouse is better for AWS/Databricks (SQL end to end, ClickHouse Cloud, one-statement Parquet export to S3).
