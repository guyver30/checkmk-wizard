## Decisions Made
- Used the legacy `GRANT S3 ON *.* TO poller_writer` form instead of `GRANT READ, WRITE ON S3 TO poller_writer`, because the newer READ/WRITE source-privilege split is disabled by default in ClickHouse (`access_control_improvements.enable_read_write_grants`) and this stack does not enable it — the legacy grant is the one that actually takes effect on a default server
- Followed RESEARCH.md's resolved recommendation of two chained `TTL ... GROUP BY ... SET` rules per series table (5-minute then 1-hour) rather than a materialized view; documented the fallback (drop the 1-hour rule) directly in `01-schema.sql` since whether ClickHouse accepts two such rules on one table is proven only by plan 14.1-08's live verification, not by this plan
