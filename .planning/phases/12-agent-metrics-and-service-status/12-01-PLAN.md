Add two module-level helpers immediately after `extract_device_type()` (line ~437):

`_strip_uom(token: str) -> str` — strips a trailing unit-of-measure from a perfdata value token,
returning only the leading numeric portion (sign, digits, at most one decimal point, optional
exponent). Nagios permits `%`, `s`/`ms`/`us`, `B`/`KB`/`MB`/`GB`/`TB` and `c` as units
(nagios-plugins.org/doc/guidelines.html, Performance Data Format Specification); implement it by
scanning the leading numeric prefix rather than enumerating unit strings, so an unknown unit is
still handled.

`parse_perf_data(raw: str) -> dict[str, dict]` — parses a Nagios-format performance-data string into
`{label: {"value": float, "warn": float|None, "crit": float|None, "min": float|None, "max": float|None}}`.
Format: space-separated `'label'=value[UOM];[warn];[crit];[min];[max]` tokens, the label
single-quoted only when it contains a space. Rules, matching this module's existing skip-not-raise
posture (T-09-03): a token with no `=` is skipped; a value that does not parse as a float skips that
one token only; an empty or non-numeric warn/crit/min/max field becomes `None`; a non-string or empty
`raw` returns `{}`. It must never raise. Give it a docstring stating the format, citing
nagios-plugins.org/doc/guidelines.html, and stating the never-raise contract explicitly.

Add tests in `tests/test_mqtt_poller.py`: a Filesystem-shaped string
(`/=45.2;80.00;90.00;0;488281.25 fs_size=488281.25;;;;`) yielding `fs` labels with correct
warn/crit and `None` for the empty trailing fields; a CPU-shaped string (`util=42.5;80;90;0;100`)
yielding `{"util": {"value": 42.5, "warn": 80.0, "crit": 90.0, ...}}`; a percent-suffixed value
(`mem_used_percent=23.0%;80;90;;`) parsing to `23.0`; a quoted label with a space
(`'total used'=5;;;;`) parsing to label `total used`; a garbage token (`notametric`) being skipped
while a valid sibling token in the same string still parses; and `parse_perf_data("")` returning `{}`.
  </action>
