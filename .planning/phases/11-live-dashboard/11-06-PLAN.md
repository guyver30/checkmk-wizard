`renderTreeDevice(hostname)`, `renderEvents()` and `groupingMode()`.

Connection indicator (`#connection-indicator`): render a colored dot plus a text label, always
both — never dot-only. Map the four phases from `connection.onStatus` to UI-SPEC's table:
connecting → muted dot, "Connecting…"; connected → `--state-ok` dot, "Connected"; reconnecting →
`--state-warn` dot, a `<span class="icon icon-refresh">` with the spin animation, and the text
"Reconnecting in {N}s…" counting the delay down once per second from the delay the connection
module reports; disconnected → `--state-crit` dot, "Disconnected — retrying". The icon carries
`title`, `aria-label` and `role="img"`.

Poller banner (`#poller-banner`, D-13/D-14): shown whenever `isPollerStale(store.pollerStatus)`
is true. Text is the locked string with `{HH:MM}` from `formatClock(pollerOfflineSince(...))` and
`{N}` the whole minutes of data age. No dismiss control — it persists until the condition clears.
While it is shown, add `.is-stale` to every device-bearing element the shell owns, and expose a
`renderShell.pollerStale` boolean so the view modules can do the same for their own rows and
tiles. Last known values stay rendered and legible: the hatch marks them, it does not hide them.

Tag-group banner (`#tag-group-banner`, D-16): shown when any device has
`isTagGroupMissing(payload)`. Locked string, `.icon-info-filled` leading, dismissible via the
`.icon-close-cross` button; once dismissed, stay dismissed for the page's lifetime. Do not
persist the dismissal in localStorage — a reload should re-surface a still-broken site config.

Grouped tree (`#sidebar-tree`, D-05/D-06/D-07): read the mode from `localStorage` key
`dashboard.groupingMode`, defaulting to `"device_type"`; write it back when `#grouping-toggle`
is clicked, then re-render the tree. Build membership with `buildGroupIndex(store.devices, mode)`
and order with `sortedGroupKeys`. Each group row shows its name, a `--radius-pill` count badge of
non-OK children over total (D-06), the worst-of color class from `rollUpGroup`, and `.is-stale`
when that roll-up reports `hatched` — a group can be both red and hatched, and must render as
both (D-15). Each host row shows `displayName(payload)`, the state color class from
`stateClass(effectiveState(payload))`, and the DOWN marker as a
`<span class="icon icon-close-circle-filled">` prepended to the label when the effective state is
DOWN — never the `⛔` character, which UI-SPEC supersedes. In folder mode each host row also
carries its `deviceTypeIcon(device_type)`; in device_type mode the folder is not shown (D-07).

Event panel (`#sidebar-events`): render `store.events` newest-first with a `--font-mono`
timestamp, the device's display name, and a from→to transition rendered with the two state
colors. Show the locked empty-state string when there are none. This panel lives in the shell and
renders identically on all three pages — it must never be re-created during navigation, or its
scroll position is lost mid-incident, which is exactly what D-23 exists to prevent.

Sidebar toggle (`#sidebar-toggle`): toggles `.is-open` on `.sidebar` for the <900px breakpoint.

Hard rendering rules for this module and every later render module: build DOM with
`document.createElement` and set text with `textContent`; never assign `innerHTML` with an
interpolated string. Every value here (`alias`, `folder`, `device_type`, event text) originates
from Checkmk where an operator may type anything. Every icon-only element gets `title`,
`aria-label` and `role="img"`. Where a state is rendered, the color is paired with an icon or a
spelled-out label — color is never the only signal. DOWN and stale *text* must use the normal
text color, never `--state-down`/`--state-stale`, which both fall below 4.5:1 on the surface.

A per-device status change must patch only that host's tree row (`renderTreeDevice`) plus its
group's badge/color, not rebuild the whole tree.

Create `dashboard/js/shell.js`, the last script every page loads. It wires modules and routes;
it contains no rendering and no business logic of its own (the same "entry point composes
everything" value `wizard.py`'s `run()` already embodies in this repo).

Create the global `ViewModules` object at the top of this file (an empty object the render
modules populate as they load — note in a comment that script order guarantees they are loaded
before this file runs, per the 11-03 script block).

On `DOMContentLoaded`: call `renderShell.init()`, subscribe to every store slot and fan each
change out to both the shell and the active view module's `update(changeKind, arg)`, register a
`connection.onStatus` handler that calls `renderShell.renderConnection`, then call
`connection.connect()` exactly once. Guard so a second call can never open a second client.

Routing (D-21/D-23): derive the current view from `location.pathname`'s filename —
`devices.html` → devices, `details.html` → details, anything else (including `/`) → index. Parse
`?id=` with `URLSearchParams` for the details view. Intercept clicks on same-origin in-app
anchors and on any element carrying a `data-host` attribute: call `preventDefault()`, compute
the target view and params, `history.pushState` the new URL (for a host click that URL is
`details.html?id=<encodeURIComponent(hostname)>`), then swap the view in place. Handle `popstate`
by re-resolving the view from the URL so browser back/forward works. Swapping means calling the
outgoing module's `unmount()` and the incoming module's `mount(document.getElementById('main'),
params)` — the shell, the tree and the event panel are never touched, which is what keeps the
event history's scroll position across navigation.

Sanitize the `?id=` value before using it: strip any `+`, `#` or `/` character. The poller's
`is_publishable_device_id()` already rejects such names at publish time, so a crafted value can
only ever miss the store — but a URL is a more attacker-reachable input than a Livestatus-sourced
hostname, and this module must not hand it onward unfiltered. It is used for a store lookup only;
never interpolate it into a subscribe call.

If a page's own view module is missing from `ViewModules` (e.g. a script failed to load), log
once and leave the static markup in place rather than throwing — a partially loaded page should
degrade, not blank.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MQTT payload → DOM | Operator-typed alias/folder text and event descriptions are rendered |
| URL query string → application | `?id=` is the most attacker-reachable input on the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-16 | Tampering / Elevation of Privilege | DOM-based XSS via `alias` or event text | mitigate | `document.createElement` + `textContent` only; `innerHTML` assignment is forbidden and asserted by grep in both tasks |
| T-11-17 | Tampering | topic injection via `?id=` | mitigate | `+`, `#` and `/` stripped before use; the value is used for a store lookup only and never interpolated into a subscribe call (the poller's `is_publishable_device_id()` is the server-side half of this pair) |
| T-11-18 | Repudiation | stale data mistaken for live | mitigate | D-14's persistent banner plus the `.is-stale` hatch on every row/tile whenever the poller is stale — the values stay readable but cannot be read as current |
| T-11-SC | Tampering | npm/pip/cargo installs | mitigate | No installs in this plan |
</threat_model>
