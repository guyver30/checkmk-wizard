  <action>
Render the status-history strip into the existing `history-strip` container.

Data source: `Store.history.get(hostId)`, a bare array of at most `HISTORY_MAX_ENTRIES` (20)
entries shaped `{ timestamp, from, to }`, oldest first. The poller publishes the complete bounded
array every time it changes and bounds it server-side in `append_bounded()`, so this view performs
a wholesale replace of the strip on each `history` store event and never appends client-side.
Appending here would double-bound incorrectly and leak memory on a long-lived kiosk tab. Add a
comment saying so and pointing at `append_bounded()` as the place bounding actually happens.

Rendering:
- Exactly `HISTORY_MAX_ENTRIES` segments always, oldest to newest, left to right — the
  conventional uptime-monitor reading order.
- A segment for a known entry is filled from `stateClass(entry.to)`, the state the device
  transitioned into.
- Unfilled slots render as `--color-surface` placeholders rather than being omitted, so the
  strip's total width never jumps as history accumulates on a newly onboarded host. A strip that
  grows while the operator watches is harder to read than a fixed frame.
- Each filled segment carries a `title` attribute in UI-SPEC's format: the time followed by the
  state word. Set it with `setAttribute` on a `textContent`-only element; never interpolate the
  value into markup.
- Pad and truncate defensively: a payload with more than `HISTORY_MAX_ENTRIES` entries — from a
  poller configured with a different `HISTORY_MAX_ENTRIES` than `config.js` records, which is a
  real possibility since the two values are kept in sync by hand — renders the newest
  `HISTORY_MAX_ENTRIES` rather than overflowing the strip.
- An entry with a missing or unrecognized `to` value renders as an UNKNOWN-styled segment rather
  than an unstyled or blank one, so a malformed entry cannot leave a visual hole that reads as
  "no data at this time".

Handle the no-history case: a host that has never transitioned since the poller started has no
retained history topic at all, which is normal and not an error. Render the full run of
placeholder segments with a short explanatory label rather than an error string.

Only re-render the strip on a `history` event whose hostname matches the currently mounted id.
Ignore history events for other hosts.

Do not add any time-series chart, sparkline with interpolated values, or any aggregation beyond
these 20 discrete transition segments. Time-series graphing is permanently out of scope for this
project: there is no time-series database, and the poller publishes discrete transitions rather
than samples.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query string to the rendered panel and to an outbound link | The `?id=` value selects what is displayed and is interpolated into an anchor href |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-35 | Elevation of Privilege | DOM-based XSS via an alias or a malformed history entry | mitigate | Every dynamic string is set with `textContent` and every attribute with `setAttribute`; `innerHTML`, `outerHTML` and `insertAdjacentHTML` are absent, enforced by acceptance criteria. A history entry with an unrecognized state maps through `stateClass`'s lookup fallback rather than concatenating an attacker-influenced value into a class name |
| T-11-36 | Tampering | crafted `?id=` reaching the outbound href | mitigate | `shell.js` (plan 11-07) already rejects an id containing `+`, `#` or `/` or exceeding a hostname length limit before it reaches `params.id`, and this view additionally passes the id through `encodeURIComponent` before it enters the href. An unknown id resolves to the locked empty state rather than a partially rendered panel |
| T-11-37 | Spoofing | a silently wrong Checkmk link | mitigate | When `CHECKMK_BASE_URL` still holds the shipped `<HOST_IP>` placeholder, the CTA renders visibly unconfigured with a `title` naming the file to edit, instead of offering a link that 404s. A misconfiguration fails loudly at the point of use |
| T-11-38 | Spoofing | a stale panel presenting last known values as current | mitigate | Three independent signals mark a stale device: the `is-stale` hatch on the panel, the locked `(stale)` suffix on the state word, and a tooltip naming the age and the threshold. The marking is re-evaluated on `pollerStatus` events as well, because the global condition can change with no device message arriving |
| T-11-39 | Information Disclosure | window.opener access from the outbound link | mitigate | `rel="noopener"` is set when the link opens in a new tab, so the Checkmk tab cannot reach back into this page's window object |
| T-11-40 | Denial of Service | an oversized history payload overflowing the strip | mitigate | The array is sliced to `HISTORY_MAX_ENTRIES` before rendering, so a payload from a poller configured with a larger bound — the two values are synced by hand and can drift — cannot produce an unbounded run of DOM nodes |
| T-11-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs and no third-party code; the history strip is plain DOM elements rather than a charting library, consistent with the permanent out-of-scope status of time-series graphing |
</threat_model>
