# Phase 11 — UI Design Contract

> Visual and interaction contract for the static, backend-less live dashboard (`index.html`,
> `devices.html`, `details.html`). Originally generated by gsd-ui-researcher from `11-CONTEXT.md`
> (24 locked decisions), `11-RESEARCH.md`, and the two operator-supplied reference mockups
> (`docs/DMC-networkmap.png`, `docs/DMC-server.png` — layout language only, text is AI-garbled
> and non-binding). The original spec was checker-approved.
>
> **2026-09-13 KONE-brand revision.** The operator required the dashboard to carry KONE Design
> System branding: the KONE logo top-left on every page, and every color/font/icon sourced from
> `web_assets/kone-design-system-main/` rather than invented. This revision replaces the Design
> System, Color, Typography and Iconography sections and adds a Brand Masthead section and an
> Asset Vendoring Manifest. **It does not reopen the phase's layout, information architecture, or
> D-01–D-24 decisions** — those are load-bearing and are cited by number throughout, unchanged.
> Where a prior rationale is superseded by the new hard branding requirement (the old "no web
> font" rule, D-10's literal `⛔` glyph choice), that supersession is called out explicitly and
> narrowly, in the same spirit CONTEXT.md itself used when it revised D-03 and D-22 in its own
> second discussion session — the underlying *decision* (a non-color state signal must exist;
> no CDN/no-egress must hold) is preserved; only the literal token/asset changes.
>
> **Auto-mode note:** produced without user questions, following the operator's explicit written
> requirements and the authoritative local KONE token/font/icon files (read in full, not
> approximated). See "Auto-Mode Design Decisions" at the end for the discretionary calls this
> revision makes on top of those sources.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no framework, no build step, no bundler (hard constraint, unchanged; static HTML/CSS/JS only) |
| Preset | not applicable |
| Component library | none — hand-written semantic HTML + vanilla DOM (`document.createElement`/`replaceChildren`), per D-21. **Visual reference only** (not a dependency): `web_assets/kone-design-system-main/packages/kone-ds-webcomponents/src/components/**/*.scss` was read to source real KONE radius/spacing conventions (pill buttons at 100px, panels/banners at 8px) — see Radius Scale. The stencil.js package itself is never imported; it cannot be, per the no-build-step/no-bundler constraint. |
| Icon library | **Vendored KONE SVG icon set** — 25 individual monochrome SVGs copied from `web_assets/kone-design-system-main/packages/kone-ds-assets/icons/` into `dashboard/icons/`, applied via CSS `mask-image` (not `<img>` — see Iconography for why). This replaces the original spec's "native Unicode/emoji glyphs only." The 477-glyph `Kone-icons` webfont is deliberately **not** vendored — the operator's own example list named individual SVG files, and 25 hand-picked SVGs are far lighter than a 135KB+ icon font carrying 452 glyphs this phase never uses. |
| Font | **Self-hosted KONE Information + Inter**, vendored from `web_assets/kone-design-system-main/packages/kone-ds-fonts/src/fonts/`. Self-hosting (no CDN, no `@import`, no Google Fonts) fully satisfies the original no-internet-egress constraint — see "Superseded: the old 'no web font' rule" below. System-font stacks remain as the `font-display: swap`-free, always-present *fallback* chain in every `font-family` declaration, never as the primary face. |

**Superseded: the old "no web font" rule.** The original spec read "no web font — no internet
egress on the target LAN, no build step to self-host one." That conclusion does not survive this
revision: the *constraint* (no CDN fetch at runtime, because the monitoring LAN has no internet
egress) is unchanged and still hard — see `stack_constraints` in this revision's brief — but
"self-host one" turns out to be exactly as available as vendoring `mqtt.js` already was in D-03:
download/copy the font files once (on a machine with access to this repo checkout), commit them,
serve them from the same nginx `dashboard` service on port 8090 via `@font-face src: url(...)`
pointing at a same-origin path. No runtime fetch ever leaves the LAN. The rule this revision
actually keeps is "no CDN, ever" — not "no web font, ever."

Registry safety gate is **not applicable** — shadcn is not part of this phase's stack. The
vendored KONE fonts/icons/logo are internal company design-system files, not a public
package-registry dependency, so no legitimacy/safety audit applies to them (same treatment this
repo already gives `web_assets/KONE_logo.png` and any other checked-in image asset) — see
Registry Safety below for the one-line record of this.

## Brand Masthead (NEW — operator hard requirement)

**Every page (`index.html`, `devices.html`, `details.html`) shows the KONE logo in the top-left
of the persistent top bar**, inside the existing `#topbar` region (D-22's shell chrome), to the
left of the in-app nav links.

**Source file:** `web_assets/KONE_logo.png` (1000×1000 px, RGB — **no alpha channel**, flat white
background baked into the file; verified by direct inspection this session). The logo mark itself
(the four blue K-O-N-E blocks) occupies roughly the middle band of that square canvas with a wide
white margin on every side.

**Problem this creates and how the vendoring step resolves it:** the dashboard's dark theme means
placing the raw 1000×1000 file at any reasonable topbar height (48px, per `--layout-topbar-height`)
would render as a small logo lost inside a large accidental white square. This is a file-shape
problem, not a design decision — the fix is a one-time, mechanical whitespace crop of the *same*
unaltered logo file, exactly analogous to D-03's precedent of downloading `mqtt.js` once on a dev
machine and committing the resulting file rather than fetching it at runtime. No pixel of the logo
itself is redrawn, recolored, or approximated.

**Vendoring step (run once, commit the result — do not repeat at deploy time):**
```bash
# ImageMagick (preferred, one line):
convert web_assets/KONE_logo.png -trim +repage dashboard/images/kone-logo.png

# Equivalent PIL fallback if ImageMagick is unavailable:
python3 -c "
from PIL import Image
im = Image.open('web_assets/KONE_logo.png')
im.getbbox() and im.crop(im.getbbox()).save('dashboard/images/kone-logo.png')
"
```
Commit only the trimmed `dashboard/images/kone-logo.png`. Do not commit the untrimmed source a
second time under a different name — one vendored file, one purpose.

**Masthead markup and styling** (new DOM contract — not present in the pre-revision spec or in
plan 11-03 as executed; see "Plans Invalidated or Amended by This Revision"):
```html
<div class="brand-masthead">
  <img src="images/kone-logo.png" alt="KONE" class="brand-logo">
  <span class="brand-title">Live Network Dashboard</span>
</div>
```
```css
.brand-masthead {
  display: inline-flex;
  align-items: center;
  gap: var(--space-sm);
  height: 32px;
}
.brand-logo {
  height: 24px;                 /* natural aspect ratio preserved, width auto */
  width: auto;
  background: #ffffff;          /* KONE primary white token — the logo file's own background */
  border-radius: var(--radius-sm); /* 4px — see Radius Scale */
  padding: 4px 6px;             /* --space-xs; keeps the white chip visually intentional, not a stray box */
  box-sizing: content-box;
  display: block;
}
.brand-title {
  font-family: 'KONE Information', var(--font-sans);
  font-size: 14px;              /* Body size (see Typography's 4-size table) — the ki 2 token's
                                    own 16px is not one of this spec's four declared sizes, and a
                                    5th size is a hard block; 14px reads fine for a top-bar
                                    wordmark at this masthead height (32px) */
  font-weight: 400;             /* KONE Information ships one weight only — see Typography */
  letter-spacing: 0.8px;        /* ki 2 token value, transcribed exactly */
  text-transform: uppercase;    /* ki 2 token's own textCase: uppercase, applied via CSS to
                                    normal-case authored text — screen readers should not have
                                    to parse shouted markup */
  color: var(--color-text);
}
```
The white background on `.brand-logo` is the logo file's own baked-in background, deliberately
kept and framed as a small rounded chip (`--radius-sm`, 4px — see Radius Scale) rather than fought
with `mix-blend-mode` or a manufactured "dark" logo variant that does not exist in the provided
source. This is the only place in the dashboard a light surface appears inside the otherwise dark
shell, and it is intentional, bounded, and small.

`brand-title`'s copy ("Live Network Dashboard") is Claude's-discretion filler text, not an
operator-specified string — the operator's requirement was the logo's presence and placement, not
this label's exact wording. An operator may change it freely; it carries no locked meaning the way
the banner/CTA strings in Copywriting Contract do.

## Typography

Self-hosted KONE Information + Inter, vendored locally (see Asset Vendoring Manifest). No CDN, no
`@import` of a remote stylesheet — every `@font-face` `src` is a same-origin path served by the
`dashboard` nginx service. System-font stacks remain as the fallback tail of every stack so the
page is never unstyled while fonts load or if a font file 404s.

```css
@font-face {
  font-family: 'KONE Information';
  src: url('../fonts/kone-information.woff2') format('woff2'),
       url('../fonts/kone-information.woff') format('woff');
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}
@font-face {
  font-family: 'Inter';
  src: url('../fonts/inter-regular.ttf') format('truetype');
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}
@font-face {
  font-family: 'Inter';
  src: url('../fonts/inter-semibold.ttf') format('truetype');
  font-weight: 600;
  font-style: normal;
  font-display: swap;
}

--font-sans: 'Inter', -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif;
--font-mono: ui-monospace, "SFMono-Regular", "Consolas", "Liberation Mono", monospace;
```

**Why Inter ships only as `.ttf` here, not `.woff2`:** the KONE fonts package
(`kone-ds-fonts/src/fonts/`) only bundles `Inter-Regular.ttf` and `Inter-SemiBold.ttf` — no
woff2/woff build of Inter exists in this design system's own source. Vendoring exactly what the
source provides (rather than fabricating a woff2 conversion this spec did not verify) means Inter
loads as `.ttf` (format('truetype')), which is fully valid, self-hosted, and CDN-free — just
larger on the wire than a woff2 would be (~310KB/weight). `KONE Information` *does* ship woff2 —
that one is vendored as woff2+woff per the "vendor woff2 (+woff fallback), not all five formats"
instruction; its `.eot`/`.svg` legacy formats (IE9/old-iOS only) are dropped, matching this
project's stack (evergreen browsers on a modern monitoring LAN).

**No mono webfont exists in the KONE design system** — `kone-ds-fonts` ships no monospace face.
`--font-mono` therefore keeps the original system-stack fallback chain unchanged; this is a
documented gap, not an oversight, and not an invented brand asset.

| Role | Size | Weight | Line Height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Label | 12px | 400 | 1.5 | `--font-sans` (Inter) | table headers, timestamps, badge text, banner meta |
| Body | 14px | 400 | 1.5 | `--font-sans` (Inter) | device names, table cells, event rows, panel copy |
| Heading | 18px | 600 | 1.2 | `--font-sans` (Inter) | panel titles: "Device List", "Event History", detail panel host name |
| Display | 24px | 600 | 1.2 | `--font-sans` (Inter) | stats-strip counts on `index.html` |

Only 4 sizes (12/14/18/24), only 2 weights (400/600) — same rule as the original spec, now backed
by Inter's own two shipped weight files (Regular 400, SemiBold 600) rather than an arbitrary system
stack's approximated weights.

**Wordmark role:** `.brand-title` uses `'KONE Information'` at the existing **Body size (14px)**
and **weight 400** — both already declared in the table above, not new values. Only
`font-family`, `letter-spacing: 0.8px`, and `text-transform: uppercase` are added on top of that
existing size/weight pair (the KONE token file's own "kone info / ki 2" preset, transcribed
exactly for those three properties). This is the same font-family-swap-only precedent
`--font-mono` already set — no new size, no new weight. KONE Information ships a single weight
file, so it is never asked to render at 600 (which would force a browser fake-bold — avoided
because the wordmark uses 400, matching the font file that exists).

`--font-mono` is unchanged from the original spec, applied at the same size/weight tokens above
(hostnames, IPs, timestamps).

## Iconography (NEW — replaces "native Unicode/emoji glyphs only")

25 individual monochrome SVGs, hand-picked (not the full 207-icon set), vendored verbatim from
`web_assets/kone-design-system-main/packages/kone-ds-assets/icons/` into `dashboard/icons/`. Full
list, destination paths and per-icon usage: see Asset Vendoring Manifest.

**Why `mask-image`, not `<img src="...">`:** every vendored SVG hardcodes `fill="#141414"` (KONE
black) directly in its path data — confirmed by reading `good-filled.svg` and
`warning-triangle-filled.svg` this session; neither uses `fill="currentColor"`. An `<img>` tag
cannot be recolored by CSS (a raster/opaque-vector reference has no styleable internals from the
including document). Referencing these SVGs via `<img>` would therefore permanently render every
icon in KONE black regardless of the state color it needs to carry (green/amber/red/orange/grey),
which is wrong for this dashboard's entire state-color system. **Inlining** each SVG's markup into
the DOM was also rejected: it would mean either handwriting 25 near-duplicate icon partials across
multiple render modules, or fetching+`innerHTML`-inserting them at runtime — the latter directly
contradicts this phase's textContent-only DOM-writing rule.

The correct, minimal fix is **CSS `mask-image`**, which uses only the SVG's alpha shape and lets
`background-color` (or `background`) supply the visible color — no inlining, no innerHTML, no
per-render-module SVG duplication, and the same 25 files serve every color a given icon needs
across OK/WARN/CRIT/etc. without vendoring per-color copies.

```css

  display: inline-block;
  width: 16px;
  height: 16px;
  flex-shrink: 0;

  mask-repeat: no-repeat;
  -webkit-mask-position: center;
  mask-position: center;
  -webkit-mask-size: contain;
  mask-size: contain;
  background-color: currentColor;  /* icon inherits the surrounding text color by default */
```

discipline applies without exception. See Accessibility.

## Color

Dark theme throughout, per D-22 ("dark, dense, panel-based") — **unchanged decision**. Every hex
value below is now sourced directly from
`web_assets/kone-design-system-main/packages/kone-ds-tokens/input/design-tokens.json` (read in
full this session, 2987 lines) rather than the original spec's Tailwind-adjacent invented values.
D-11's locked hue-*meaning* mapping (OK green, WARN yellow, CRIT red, UNKNOWN/UNREACH orange, DOWN
red-family, grey reserved for the dashboard's own stale/no-data condition) is preserved exactly —
only the literal hex per hue changes, to a real KONE token.

```css
:root {
  /* 60% — dominant surface: KONE's own primary "black" token */
  --color-bg: #141414;

  /* 30% — secondary surfaces (panels, sidebar, cards, table rows):
     KONE blue-ramp d80/d60 — a blue-tinted near-black, not a neutral grey, because KONE's own
     token set has no separate "dark surface" ramp and its blue d20..d80 ramp is the closest
     KONE-authored answer to "a dark surface with brand identity." */
  --color-surface: #142041;         /* blue.d80 */
  --color-surface-raised: #142c6e;  /* blue.d60 — hover/active row, tile */
  --color-border: rgba(20, 56, 155, 0.35); /* blue.d40 (#14389b) as a hairline overlay, not a flat fill */

  /* 10% — accent, reserved list below: KONE Blue itself */
  --color-accent: #1450f5;      /* color.primary.kone blue / color.blue.base */
  --color-accent-text: #7296f9; /* color.blue.l40 — lighter variant for text/hover on dark bg */

  /* text: KONE's own primary white; muted text uses a blue-tinted light tone from the same
     ramp, rather than an invented grey, so it still reads as "KONE blue family" at low emphasis */
  --color-text: #ffffff;        /* color.primary.white */
  --color-text-muted: #a1b9fb;  /* color.blue.l60 */

  /* semantic state palette — D-11's hue meanings preserved exactly, hexes now KONE tokens */
  --state-ok: #1ed273;       /* color.green.base (= color.accent.accent - green) */
  --state-warn: #ffe141;     /* color.secondary.yellow */
  --state-crit: #ff5f28;     /* color.red.base (= color.accent.accent - red) */
  --state-down: #f51414;     /* color.accent."destructive text" — red family, same as CRIT per
                                 D-11's locked hue meaning, but NOT the identical hex CRIT uses
                                 (see "Noted deviation: D-11 red split" below); the icon (see
                                 Device-Type/State Iconography) still carries the primary
                                 DOWN-vs-CRIT distinction, not the hue alone */
  --state-unknown: #ffa023;  /* color.orange.base (= color.accent.accent - orange) */
  --state-unreach: #ffa023;  /* same orange as UNKNOWN, per D-11 */
  --state-pend: #959595;     /* color.grayscale."300 disabled" — Checkmk's own light PEND grey */
  --state-stale: #727272;    /* color.grayscale."200 inactive" — darker, distinct from PEND */

  /* destructive: not applicable — see Copywriting Contract */
}
```

| Role | Value | KONE token | Usage |
|------|-------|-----------|-------|
| Dominant (60%) | `#141414` | `color.primary.black` | Page background, main content area behind panels |
| Secondary (30%) | `#142041` (+ `#142c6e` raised) | `color.blue.d80` / `color.blue.d60` | Sidebar, panels, cards/tiles, table rows, top bar |
| Accent (10%) | `#1450f5` | `color.primary."kone blue"` / `color.blue.base` | **Reserved for:** active nav/tab underline, selected sidebar-tree row's left border + background tint, table sort-arrow on the active sorted column, link/hover state on the "View in Checkmk →" CTA, focus outline on all interactive elements |
| Destructive | not applicable | — | This phase has no destructive actions — read-only visualization, no forms, no deletes (see Copywriting Contract) |

Accent is never reused for state meaning — the semantic palette is fully separate, and KONE Blue
(`#1450f5`) does not collide with any of the six state hexes above, so a blue accent border can
never be misread as a status color.

## Accessibility

- **Color is never the only signal** — unchanged rule, now enforced through icons instead of
  emoji: every state rendering pairs a color with an `.icon-*` mask (or, for UNKNOWN/UNREACH/PEND,
  a spelled-out text label as before) or a texture (diagonal hatch for stale).
- **Contrast:** re-verify against the new KONE-sourced hexes specifically — `--state-warn`
  (`#ffe141`, a bright yellow) and `--state-unknown`/`--state-unreach` (`#ffa023`, orange) both sit
  on the dark `--color-surface` (`#142041`); both were chosen from KONE's own "base" tier (not a
  lighter `l20`/`l40` tint) specifically because the base tier is the tier KONE's own token set
  treats as the primary, most-legible expression of each hue. Verify with a contrast checker at
  implementation time exactly as the original spec already instructed — this revision changes the
  hex values under an unchanged verification obligation, it does not remove the obligation.
  **Also re-verify `--state-down` (`#f51414`) and `--state-stale` (`#727272`)** against
  `--color-surface` (`#142041`): measured this session at approximately 3.8:1 (`#f51414`) and
  3.3:1 (`#727272`) — both **below** the 4.5:1 AA threshold for normal text, though both clear the
  3:1 bar for large text and for graphical UI components (icons, badges, dots). **Contract rule
  (checkable acceptance criterion, not a suggestion):** DOWN and STALE state *labels* (the text
  strings "DOWN", "(stale)", and any other text run naming these states) must render in
  `--color-text` or `--color-text-muted`, never in `--state-down`/`--state-stale` directly. The
  state hue is reserved for the icon (`.icon-close-circle-filled`, hatch overlay), the status dot,
  or a badge/chip background — never for the text glyph color itself. Acceptance check: `grep` any
  rendered DOWN/stale label markup and confirm the text node's computed color resolves to
  `--color-text`/`--color-text-muted`, with `--state-down`/`--state-stale` appearing only in
  `background-color`, `border-color`, or `mask`/icon-fill contexts.
- **Focus visibility:** unchanged — `2px solid var(--color-accent)` (`#1450f5`, still a strong
  blue against the dark surfaces) on every interactive element's `:focus-visible`.
- **Icons need text alternatives — same rule the original spec applied to emoji, now applied to
  masked SVGs.** Every icon-only element (device-type icon, DOWN marker, banner icons, connection
  indicator's spinner, sidebar toggle, dismiss buttons) gets a `title` attribute and
  `aria-label`/`role="img"` naming the thing in words — e.g.
  `<span class="icon icon-close-circle-filled state-down" title="Down" aria-label="Down"
  role="img"></span>`. A `mask-image` icon is exactly as invisible to assistive tech as an emoji
  character was; nothing about switching the visual mechanism relaxes this requirement.
- **No `innerHTML` string interpolation of Checkmk-sourced strings** — unchanged, still enforced
  via `textContent`/`createElement`/`setAttribute`. Referencing a vendored, static, project-authored
  SVG file path in a class name or a `mask-image: url(...)` CSS rule is not "interpolating
  Checkmk-sourced data" and does not implicate this rule — the rule is about untrusted/dynamic
  strings (alias, folder name, event description), not about static asset references baked into
  the stylesheet at authoring time.
