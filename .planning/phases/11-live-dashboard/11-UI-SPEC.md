# Phase 11 — UI Design Contract

> Visual and interaction contract for the static, backend-less live dashboard (`index.html`,
> `devices.html`, `details.html`). Generated by gsd-ui-researcher from `11-CONTEXT.md` (24
> locked decisions), `11-RESEARCH.md`, and the two operator-supplied reference mockups
> (`docs/DMC-networkmap.png`, `docs/DMC-server.png` — layout language only, text is
> AI-garbled and non-binding). Verified by gsd-ui-checker.
>
> **Auto-mode note:** this spec was produced without user questions. Every item CONTEXT.md
> left to "Claude's Discretion" is resolved below with a documented rationale — see
> "Auto-Mode Design Decisions" at the end. CONTEXT.md's D-01–D-24 are load-bearing and are

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no framework, no build step, no bundler (hard constraint; static HTML/CSS/JS only) |
| Preset | not applicable |
| Component library | none — hand-written semantic HTML + vanilla DOM (`document.createElement`/`replaceChildren`), per D-21 |
| Icon library | none — native Unicode/emoji glyphs only (no icon font, no SVG sprite sheet to vendor); matches D-10's own reasoning for choosing `⛔` over a vendored icon |
| Font | system font stack only — no web font, no CDN (monitoring LAN has no internet egress per D-03's framing); see Typography |

Registry safety gate is **not applicable** — shadcn is not part of this phase's stack.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-xs` | 4px | Icon-to-text gaps, badge internal padding |
| `--space-sm` | 8px | Compact element spacing, table cell vertical padding |
| `--space-sm2` | 12px | Overview tile / card padding (dense layout, D-22) — still a multiple of 4 |
| `--space-md` | 16px | Default element spacing, panel internal padding |
| `--space-lg` | 24px | Section padding, gap between shell columns |
| `--space-xl` | 32px | Layout gaps between major page regions |
| `--space-2xl` | 48px | Reserved — not expected to be used at this density |
| `--space-3xl` | 64px | Reserved — not expected to be used at this density |

Exceptions: none beyond `--space-sm2` (12px), which exists because D-22 specifies a "dark,
dense, panel-based" layout — cards and table rows use 12px rather than 16px to fit more
fleet state on screen at once, still a valid multiple of 4. No touch-target exception is
needed this phase: this is a desktop/kiosk-display dashboard (mouse + keyboard), and
mobile-responsive polish is explicitly DASH2-01, deferred to v2 (`STATE.md` Deferred Items).

## Typography

No web fonts (no internet egress on the target LAN, no build step to self-host one) — system
font stacks only.

```css
--font-sans: -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif;
--font-mono: ui-monospace, "SFMono-Regular", "Consolas", "Liberation Mono", monospace;
```

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Label | 12px | 400 | 1.5 | `--font-sans` (table headers, timestamps, badge text, banner meta) |
| Body | 14px | 400 | 1.5 | `--font-sans` (device names, table cells, event rows, panel copy) |
| Heading | 18px | 600 | 1.2 | `--font-sans` (panel titles: "Device List", "Event History", detail panel host name) |
| Display | 24px | 600 | 1.2 | `--font-sans` (stats-strip counts on `index.html`) |

Only 4 sizes (12/14/18/24), only 2 weights (400/600) — declared exactly per spacing/typography
rules.

**Supplementary token (not a 5th size):** `--font-mono` is applied to hostnames, IP-like ids,
and timestamps at the *same* size/weight tokens above, wherever exact character alignment
helps fast scanning (device table's Host column, status-history strip tooltips, event
timestamps). This is a font-family swap, not a new size or weight.

## Color

Dark theme throughout, per D-22 ("dark, dense, panel-based" — `docs/DMC-networkmap.png` /
`docs/DMC-server.png` layout language).

```css
:root {
  /* 60% — dominant surface */
  --color-bg: #0b0d10;

  /* 30% — secondary surfaces (panels, sidebar, cards, table rows) */
  --color-surface: #16191d;
  --color-surface-raised: #1c2025;   /* hover/active row, tile */
  --color-border: rgba(255,255,255,0.08);

  /* 10% — accent, reserved list below */
  --color-accent: #3b82f6;
  --color-accent-text: #93c5fd;

  /* text */
  --color-text: #e5e7eb;
  --color-text-muted: #9ca3af;

  /* semantic state palette — D-11, mirrors Checkmk's own meaning exactly */
  --state-ok: #2ecc71;
  --state-warn: #f4c430;
  --state-crit: #ef4444;
  --state-down: #ef4444;      /* same red family as CRIT; D-10's ⛔ prefix, not a new hue, carries the DOWN-vs-CRIT distinction */
  --state-unknown: #f97316;   /* orange, per D-11 — NOT grey */
  --state-unreach: #f97316;   /* orange, same as UNKNOWN per D-11 */
  --state-pend: #a1a1aa;      /* Checkmk's own PEND grey (light) */
  --state-stale: #52525b;     /* dashboard's own stale/no-data grey (darker, distinct from PEND) — D-11, D-14 */

  /* destructive: not applicable — see Copywriting Contract */
}
```

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0b0d10` | Page background, main content area behind panels |
| Secondary (30%) | `#16191d` (+ `#1c2025` raised) | Sidebar, panels, cards/tiles, table rows, top bar |
| Accent (10%) | `#3b82f6` | **Reserved for:** active nav/tab underline (e.g. the SERVICES/HISTORY tab strip on `details.html`), selected sidebar-tree row's left border + background tint, table sort-arrow on the active sorted column, link/hover state on the "View in Checkmk →" CTA, focus outline on all interactive elements |
| Destructive | not applicable | This phase has no destructive actions — read-only visualization, no forms, no deletes (see Copywriting Contract) |

Accent is never reused for state meaning — the semantic palette above is fully separate so
a blue accent border never gets misread as a status color.

### State-color to meaning map (locked by D-11 — do not invent alternates)

| Checkmk/dashboard state | Color token | Distinguishing non-color signal |
|---|---|---|
| OK | `--state-ok` (green) | plain fill, no icon needed |
| WARN | `--state-warn` (amber) | plain fill |
| CRIT | `--state-crit` (red) | plain fill |
| DOWN | `--state-down` (red) | **`⛔` prepended to label** (D-10) — sidebar tree, overview tile, device table |
| UNKNOWN | `--state-unknown` (orange) | text label "UNKNOWN" always rendered alongside the badge, never a bare dot |
| UNREACH | `--state-unreach` (orange) | text label "UNREACH" always rendered alongside the badge (D-17/Pitfall 6: keyed off `host_state_raw`, never inferred from `state`) |
| PEND | `--state-pend` (light grey) | text label "PEND" |
| Stale / no-data (dashboard's own) | `--state-stale` (dark slate grey) + diagonal hatch texture | hatch pattern (below) + "(stale)" text suffix on the state label + tooltip with age |

**Stale hatch pattern** (D-14/D-15 — must be visually distinct from a flat grey fill, and
must be composable with a red/amber/orange fill underneath for the "red-and-hatched" case):

```css
.is-stale {
  background-image: repeating-linear-gradient(
    45deg,
    rgba(255,255,255,0.06) 0 6px,
    transparent 6px 12px
  );
}
```

Applied as an overlay on top of whatever state color is already present, not a replacement —
this is what makes D-15's "red-and-hatched" (CRIT + stale) renderable as one visual that
preserves both facts.

## Layout

Persistent shell, per D-21/D-22/D-23 — three real HTML files, one shared chrome, main area
swaps content without unmounting the sidebar.

```
┌──────────────────────────────────────────────────────────────┐
│ Top bar: logo/title · poller-offline banner (D-14, conditional)· connection indicator (D-05 spec) │
├───────────────────┬────────────────────────────────────────────┤
│ Grouped tree       │                                            │
│ (D-05 toggle:      │  Main area — swaps in place (D-23):        │
│  folder/device_type│   - index.html: stats strip + overview     │
│  default: type)    │   - devices.html: device table             │
│  ~58% of sidebar   │   - details.html: detail panel              │
│  height            │                                            │
├───────────────────┤                                            │
│ Event History      │                                            │
│ (always visible,   │                                            │
│  D-22/DASH-02)     │                                            │
│  ~42% of sidebar   │                                            │
│  height, own       │                                            │
│  scroll            │                                            │
└───────────────────┴────────────────────────────────────────────┘
```

```css
--layout-sidebar-width: 280px;
--layout-topbar-height: 48px;
--layout-sidebar-tree-fraction: 58%;   /* remainder goes to event-history panel */
```

```css
.shell {
  display: grid;
  grid-template-columns: var(--layout-sidebar-width) 1fr;
  grid-template-rows: var(--layout-topbar-height) 1fr;
  height: 100vh;
}
.sidebar {
  display: grid;
  grid-template-rows: var(--layout-sidebar-tree-fraction) 1fr;
  overflow: hidden;
}
.sidebar-tree, .sidebar-events { overflow-y: auto; }
```

**Recent-events panel placement:** lives in the persistent sidebar (shell-level, per D-22),
not a `devices.html`-only widget — it renders identically on all three pages. This is what
satisfies DASH-02's "recent-events panel" requirement without contradicting D-22's "always
on screen" framing: it's a shell fixture, and `devices.html` is simply the page whose
requirement text calls it out explicitly.

### Page-specific main-area contracts

**`index.html` (D-24, DASH-01):**
1. Stats-by-state strip: one compact stat per state (OK/WARN/CRIT/UNKNOWN/DOWN counts,
   `--font-display` 24px numerals + 12px label beneath), horizontal row, top of main area.
   Height ~72px. Updates in place per incoming `lan/devices/{id}/status` message by
   recomputing counts from the state store — never a full strip rebuild triggers a layout
   reflow of the tiles below it.
2. Grouped fleet overview beneath the strip: a responsive grid of group cards —
   `grid-template-columns: repeat(auto-fill, minmax(240px, 1fr))`, gap `--space-md`.
   Each card:
   - Header: group name (Heading role, 18px/600) + count badge (`N non-OK / total`,
     pill-shaped, D-06).
   - Left border (4px) or full-tile background tint = worst-of color (D-06); hatch overlay
     if `anyStale` for that group (D-15).
   - Body: compact chip grid of member hosts, each chip = device-type glyph + short name
     (D-18 display-name rule), colored by that host's own state, `⛔` prefix if DOWN (D-10).
     Clicking a chip opens the detail panel in place (D-23).
   - This slot is reserved for Phase 13's real topology map (D-24) — build it as a
     self-contained, swappable main-area module so that swap is a drop-in replacement, not a
     rewrite.

**`devices.html` (DASH-02):**
- Full-width sortable table, columns (default set, discretionary beyond DASH-02's minimum):

  | Column | Content | Notes |
  |---|---|---|
  | State | color chip + text label (+ `⛔` if DOWN) | not sortable by color alone — sorts by `SEVERITY_RANK` |
  | Host | `--font-mono`, D-18 display name (alias, else id) | sortable, default secondary sort key |
  | Type | device-type glyph + label | sortable |
  | Location | folder-derived label (D-07: shown only when grouping mode = folder; when mode = device_type, this column is hidden entirely, matching D-07's tree/overview rule extended to the table for consistency) | — |
  | Last Update | relative time (`--font-mono`), stale rows get the hatch class | sortable |
  | Flags | small icon badges for `in_downtime` / `acknowledged` (Phase 9 D-07 fields) | not sortable |

- Default sort: **State severity, worst-first**, secondary key Host ascending — the
  operationally useful default for a live ops table (surface problems first, not
  alphabetical noise). Per Pattern 2 in research: per-message updates patch one `<tr>` only;
  a user-initiated sort/column-click rebuilds the `<tbody>` (acceptable, ~21 rows).
- Recent-events panel: see shell-level contract above (already always visible).

**`details.html` (DASH-03, D-19):**
- Header: device-type glyph + D-18 display name (Heading, 18px) + hostname in `--font-mono`
  12px beside it if alias differs from id + current state badge.
- Status-history strip: horizontal row of exactly `HISTORY_MAX_ENTRIES` (20, Phase 9 D-05)
  equal-width segments, oldest→newest left→right (matches conventional uptime-monitor
  reading order). Segment: 12px wide, 24px tall, 2px gap, fill = that entry's state color,
  `title` attribute on each segment showing `HH:MM:SS — STATE`. Fewer than 20 known entries
  (new host) → remaining slots render as empty/`--color-surface` placeholders, not omitted,
  so the strip's fixed width never jumps as history accumulates.
- "View in Checkmk →" link/button: primary CTA of this page (see Copywriting Contract),
  built from `config.js`'s Checkmk base URL + site name (D-20) targeting that host's own
  page — accent-colored, right-aligned in the header row.
- Downtime/acknowledgement flags (Phase 9 D-07) rendered as labeled badges, not icon-only.

## Connection Indicator (DASH-05)

Top bar, right-aligned. Dot + text label together, always (never dot-only — accessibility
rule below).

| State | Dot color | Text |
|---|---|---|
| Connecting (initial) | `--color-text-muted` (grey) | "Connecting…" |
| Connected | `--state-ok` (green) | "Connected" |
| Reconnecting | `--state-warn` (amber) | "Reconnecting in {N}s…" — countdown from Pattern 3's computed backoff delay |
| Offline/disconnected | `--state-crit` (red) | "Disconnected — retrying" |

Reuse of green/amber/red hues here (same as the state palette) is intentional and safe: this
is a single, spatially isolated top-bar widget always paired with an explicit text label, so
it cannot be confused with a device/group state chip elsewhere on screen (accessibility
rule: color is never the sole signal, satisfied here by the text pairing).

**Poller-offline banner (D-13/D-14):** separate from the connection indicator — this
indicates the *MQTT WebSocket link* is down; the banner indicates the *poller process*
(upstream of MQTT) is down or its data is stale. Both can be true independently. Banner is a
full-width strip beneath the top bar, only rendered when `isPollerStale()` is true:

> **Poller offline since {HH:MM} — data is {N} minutes old**

Background `--state-stale` at 20% opacity over `--color-bg`, text `--color-text`, persists
until the condition clears (no dismiss button — this one is a live fact, not a one-time
notice).

**device_type tag-group-missing banner (D-16)** — separate, dismissible (has an "×" button,
`aria-label="Dismiss"`), re-appears on next page load since there's no backend to persist
the dismissal:

> **No device_type tag group on this site — run the wizard's tagging phase.**

## Responsive Behavior

Primary target is desktop/kiosk display (a NOC-style dashboard meant to stay open on a
monitor), per the reference mockups' fixed-panel layout and DASH2-01's explicit v2 deferral
of "mobile-responsive layout polish." This phase ships one minimal breakpoint so a narrower
browser window degrades gracefully rather than breaking outright — it is intentionally not
full mobile optimization.

```css
@media (max-width: 900px) {
  .shell { grid-template-columns: 1fr; }
  .sidebar {
    position: fixed; inset: var(--layout-topbar-height) 0 0 0;
    transform: translateX(-100%);
    transition: transform 150ms ease;
    z-index: 20;
  }
  .sidebar.is-open { transform: translateX(0); }
}
```

A hamburger button appears in the top bar below 900px to toggle `.sidebar.is-open`. Above
900px the shell is the fixed two-column layout described in Layout. No further breakpoints
are in scope this phase (DASH2-01 owns anything beyond "not broken").

## Accessibility

- **Color is never the only signal.** Every state rendering pairs a color with one of: an
  icon (`⛔` for DOWN, D-10), a text label (UNKNOWN/UNREACH/PEND always spell out the state
  word), or a texture (diagonal hatch for stale, D-14/D-15). The connection indicator always
  shows text beside its dot.
- **Contrast:** all state hex values (`--state-ok/warn/crit/unknown/pend/stale`) are chosen
  to read at ≥4.5:1 against `--color-surface` (#16191d) for text use and ≥3:1 for large-area
  fills/icons — verify with a contrast checker at implementation time if any token is
  adjusted.
- **Focus visibility:** every interactive element (tree row, table header, tab, sidebar
  toggle, "View in Checkmk" link, banner dismiss button) gets a visible `2px solid
  var(--color-accent)` outline on `:focus-visible`. The dashboard has no framework focus
  trap — native tab order must remain intact across the persistent shell and swapped main
  area.
- **Emoji glyphs need text alternatives.** Every device-type glyph and the `⛔` DOWN marker
  get a `title` attribute (and `aria-label` where the glyph is the only content of an
  element) naming the thing in words — e.g. `<span class="type-icon" title="E-link"
  aria-label="E-link" role="img">🔗</span>`. Screen readers must not be left with a bare,
  unlabeled emoji.
- **No `innerHTML` string interpolation of Checkmk-sourced strings** (alias, folder name,
  event description) — use `textContent`/`createElement`, per RESEARCH.md's Security Domain
  (V5 Input Validation) finding. This is both a security and an accessibility-adjacent
  correctness requirement (malformed markup from an unescaped alias could break the DOM tree
  a screen reader parses).

## Copywriting Contract

This phase has no create/edit/delete forms — it is read-only visualization. The "Primary
CTA" below is the phase's one clickable call-to-action; "Destructive confirmation" is
genuinely not applicable and is documented as such rather than invented.

| Element | Copy |
|---------|------|
| Primary CTA (`details.html`) | **"View in Checkmk →"** — links to `{config.js Checkmk base URL}/{site}/check_mk/view.py?view_name=hoststatus&host={id}`-style deep link per D-19/D-20 |
| Empty state — device table (no topology yet) | Heading: **"Waiting for device data…"** / Body: **"No devices have reported yet. Once the poller publishes topology, hosts will appear here automatically."** |
| Empty state — event panel (no events yet) | **"No events yet — state changes will appear here as they happen."** |
| Empty state — overview (no groups yet) | Same heading/body as device table (topology absence is the shared root cause) |

| Poller-offline banner (D-14, exact string — locked) | **"Poller offline since {HH:MM} — data is {N} minutes old"** |

| Destructive confirmation | **Not applicable** — no destructive actions exist in this phase (read-only dashboard; the D-16 banner's dismiss is non-destructive and simply re-appears on reload) |

## Device-Type Glyph Mapping (Claude's Discretion, resolved)

No icon library is vendored this phase (see Design System) — native Unicode/emoji glyphs
render identically across the three pages with zero additional vendoring, following the
exact reasoning D-10 already used to justify `⛔` over a sprite/icon-font for the DOWN
marker. Each glyph gets a `title`/`aria-label` per the Accessibility section.

| `device_type` value | Glyph | Rationale |
|---|---|---|
| `other` | ⬡ | Neutral hexagon — deliberately generic, avoids implying a real category for the "unclassified" bucket |
| `E-link` | 🔗 | Literal match to "link" in the name |
| `ACS` (access control system) | 🔐 | Lock — standard access-control association |
| `Multimedia` | 📺 | Screen/display — standard multimedia association |
| `NetworkDevice` | 🌐 | Globe/network — standard networking association |
| `GroupController` | 🎛️ | Control knobs — standard "controller" association |
| `unknown` (D-16: tag group absent site-wide) | ❔ | Distinct from `other`'s hexagon — this means "no tag group configured," a site-config warning, never a device category (matches `extract_device_type()`'s own docstring contract) |
