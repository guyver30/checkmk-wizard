<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN browser → nginx (8090) | Anyone on the LAN can fetch every file under `dashboard/`, including `config.js`; there is no authentication by design (PROJECT.md: broker-level ACL is the only access-control layer) |
| public CDN (unpkg/jsdelivr) → repo | `mqtt.min.js` is third-party code fetched once and then served to every browser; a substituted file executes with full page privileges |
| repo `dashboard/` → nginx container | Read-only bind mount; nginx must not be able to write back into the checkout |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-03 | Information Disclosure | `dashboard/js/config.js` WS credentials | accept (boundary made explicit) | The `wsreader` credentials are unavoidably readable by any LAN client that can load the page — this is an accepted, documented posture, not a leak, because `deploy/mosquitto.acl` grants `wsreader` only `topic read lan/#`: no publish, no other topic tree, no broker administration. Task 2 requires the header comment to state this boundary plainly and name `deploy/gen-mosquitto-passwd.sh` as the rotation path, matching Phase 8 D-09's disposable-default convention |
| T-11-04 | Tampering | vendored `dashboard/js/vendor/mqtt.min.js` | mitigate | Version pinned to 5.15.2 (not a floating range, not a runtime CDN load — D-03), SHA-256 recorded in `dashboard/js/vendor/README.md`, file committed to git so any later modification appears in a diff, and the file is never hand-edited. Runtime integrity comes from git + the read-only bind mount, not from a network fetch |
| T-11-05 | Elevation of Privilege | nginx container ↔ repo checkout | mitigate | Bind mount is `:ro,z`; nginx has no write path into the checkout and no `command:`/config override that could enable directory upload or CGI execution. No `depends_on` and no `environment:` block means no credential is passed into the container at all |
| T-11-06 | Spoofing | `nginx:alpine` moving image tag | accept | A moving tag could in principle change behavior between deploys. Accepted as identical to the risk profile this stack already carries for `eclipse-mosquitto:2`, `minio/minio:latest` and `checkmk/check-mk-raw:2.4.0-latest`; Task 3 records the tradeoff in a comment rather than silently diverging from the file's convention (RESEARCH.md Assumption A2) |
| T-11-SC | Tampering | npm/pip/cargo installs | mitigate | The only third-party artifact is `mqtt` 5.15.2, audited in RESEARCH.md's Package Legitimacy Audit with `slopcheck install mqtt --ecosystem npm` verdict `[OK]` and repo `github.com/mqttjs/MQTT.js`. Disposition **Approved** — no `[ASSUMED]`/`[SUS]`/`[SLOP]` package in this phase, so no blocking human legitimacy checkpoint is required. No package manager runs at deploy or runtime (the file is vendored, not installed) |
</threat_model>
