<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet CDN → repo | The one-time mqtt.js download brings third-party code into the checkout |
| LAN browser → mosquitto | `wsreader` credentials shipped in a publicly readable JS file cross this boundary |
| LAN → nginx :8090 | The dashboard is served unauthenticated to anything on the LAN |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-04 | Information Disclosure | `dashboard/js/config.js` WS credentials | accept | `wsreader` is `topic read lan/#` only (deploy/mosquitto.acl) — the exposure is read-only visibility of the device list on a trusted LAN; documented as a disposable default to rotate, per the existing project-wide convention (Phase 8 D-09). Task 3 requires that disclosure to be written into the file header |
| T-11-05 | Elevation of Privilege | nginx bind mount | mitigate | Mount is `:ro` — a compromised nginx container cannot write back into the repo checkout |
| T-11-06 | Spoofing | unauthenticated dashboard on :8090 | accept | Matches the project's locked posture (PROJECT.md: no multi-user accounts/login; broker ACL is the only access-control layer). Not revisited by this phase |
| T-11-SC | Tampering | npm/pip/cargo installs | mitigate | `mqtt@5.15.2` is the only third-party artifact; already legitimacy-audited in 11-RESEARCH.md with verdict [OK], vendored at a pinned version and committed, so the audited bytes are the deployed bytes. No package manager is invoked. KONE assets are internal company files copied from the checkout, not registry dependencies (UI-SPEC Registry Safety) |
</threat_model>
