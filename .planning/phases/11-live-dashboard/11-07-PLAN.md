In folder mode the chip shows the device-type icon; in device_type mode the folder is not shown

Create `dashboard/js/render-devices.js` registering `ViewModules.devices`.

Columns, exactly the locked set:
- State — a state color chip plus the spelled-out state text, with a
  `<span class="icon icon-close-circle-filled">` when the effective state is DOWN. Sorting this
  column sorts by `SEVERITY_RANK` of `effectiveState`, never by the color or the label string.
- Host — `displayName(payload)` in `--font-mono` (D-18: alias when non-empty, else hostname).
- Type — `deviceTypeIcon(device_type)` plus the type label.
- Location — the folder-derived label. Per D-07 this column is shown only while the grouping mode
  is `folder`; in `device_type` mode hide the column entirely, header included, so the table
  agrees with the tree and the overview about what classification matters.
- Last Update — `formatRelativeTime(timestamp)` in `--font-mono`; the row gains `.is-stale` when
  `isDeviceStale(payload)` is true, with a `title` carrying the locked stale tooltip text.
- Flags — small labelled badges for `in_downtime` (`.icon-pause-filled`) and `acknowledged`
  (`.icon-check-circle-filled`), rendered only when true, each with `title`/`aria-label`. Not
  sortable.

Default sort: state severity worst-first, secondary key Host ascending — problems surface at the
top of a live ops table rather than alphabetical noise. Clicking a `th[data-key]` sets that key
and flips direction when it was already active; the active header shows
`.icon-caret-up-small`/`.icon-caret-down-small` colored with `--color-accent` and sets
`aria-sort`.

The update split is the requirement, not an optimization: on a `"device"` change, locate
`tr[data-id="..."]` (escape the id with `CSS.escape`) and `replaceWith` a freshly built single
row; if no such row exists the device is new and a full rebuild plus re-sort is correct. On a
sort click, rebuild the whole `<tbody>` with `replaceChildren` — that is a user action at ~21
rows, not a streaming event. Never rebuild the tbody from a `"device"` message.

Apply `.is-stale` to every row when `renderShell.pollerStale` is true (D-14), keeping values
legible. Set `data-host` on each row so plan 11-06's router opens the detail panel in place.
Render the locked empty-state copy when `store.devices` is empty. `createElement`/`textContent`
only; no `innerHTML` assignment.
