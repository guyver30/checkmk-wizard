<objective>
Extend the Phase 9 status payload with the two fields D-17 locked: Checkmk's authoritative
`staleness` value, and a real host state that tells DOWN and UNREACHABLE apart.

Purpose: this is the one deliberate exception to Phase 11 being a pure MQTT consumer. The
dashboard's DASH-04 staleness logic prefers Checkmk's own value over timestamp-age arithmetic,
and D-11's palette needs UNREACH separately renderable in orange — neither is possible from the
current payload, because `compute_overall_state()` collapses raw host states 1 and 2 into the
single string `"DOWN"`.

Output: two additive keys on the existing `lan/devices/{id}/status` topic. No new topic, no
renamed field, no removed field — every existing subscriber and every already-retained payload
stays valid.
</objective>
