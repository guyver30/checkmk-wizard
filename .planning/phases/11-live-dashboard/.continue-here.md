## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Trusting the UI-SPEC's "see the original sections' surviving text" pointer | `11-UI-SPEC.md`'s *Page-specific main-area contracts* section says the device-table columns, default sort, history-strip segment sizing and overview grid values are "unchanged — see the original sections' surviving text". **That text does not survive on disk.** It exists only at git `12830c1`. | advisory | Already resolved: the planner recovered those values and inlined them concretely into 11-03/11-07/11-08, and the plan-checker confirmed they are present. Read the PLAN, not the spec pointer, for those four values. Do not go looking in git. |
| Broad `TBD`/`placeholder` grep produces false "incomplete" hits | The pause-work false-completion scan flags files across Phases 9/10/10.1 — all legitimate. The grep matches the literal string in normal prose (e.g. the shipped `<HOST_IP>` config sentinel). Phases 9/10/10.1 are Complete with verification passed. | advisory | Treat that scan as a pointer, not a verdict. Check a file's actual status before reporting it incomplete. |
| Forcing a code analog onto files that have none | This phase is the repo's first HTML/CSS/JS. 13 of 19 files have **no in-repo analog**, and `11-PATTERNS.md` says so explicitly, pointing them at UI-SPEC/RESEARCH contract sections instead. A wrong analog is worse than none because the executor copies it. | advisory | If a frontend file has no analog, follow the cited UI-SPEC/RESEARCH section. Do not hunt for a Python file to imitate. `docs/src/mqtt_notify.py` and `mqtt_publisher_changes.py` are explicitly **disqualified** as analogs — the poller's own module docstring says so. |
| `11-PATTERNS.md`'s UI-SPEC section references are stale | PATTERNS.md was produced 2026-09-12, before the KONE UI-SPEC revision. Its *code analog* mappings (which repo file to imitate) are still valid — that part is about Python/repo structure. But where it points a frontend file at a UI-SPEC section number, that reference may be to the superseded spec. | advisory | Use PATTERNS.md for analogs. Use the current `11-UI-SPEC.md` (by section name, not number) for anything visual. The 9 plans already did this correctly. |
| Bare `python3`/`python` instead of `uv run` | Slipped in an earlier session. CLAUDE.md's uv-only rule is unconditional — it covers throwaway scratch heredocs, not just project code. | advisory | Use `uv run python` (or `sed`) even for scratch text edits. 11-02 Task 2 specifies `uv run --with pillow python -c ...` for the logo trim and explicitly says to **stop and report** rather than fall back to a bare `python3`. |
| Following the UI-SPEC's PIL snippet literally for the logo trim | ImageMagick is **not installed** here, so the spec's preferred `convert -trim +repage` cannot run. Worse, a bare `Image.getbbox()` returns the full canvas on this RGB-no-alpha source — a naive follow of the spec's PIL snippet silently produces an *uncropped* copy that looks like success. | advisory | 11-02 Task 2 already specifies the correct uv/Pillow path. Follow the plan, not the spec snippet. |
