## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| `phase.add` writes a stub outside `## Phase Details` | `bm-sdk query phase.add` appended the new `### Phase N` section *after* the `## Progress` table rather than alongside the other phase sections, and left `Goal: [To be planned]`. Happened on both Phase 12 and Phase 13 in this session. | advisory | After any `phase.add`, run `grep -n "^### Phase\|^## " .planning/ROADMAP.md` and confirm the new section sits above `## Progress`. Move it if not. Also add the missing `## Phases` checklist line and Progress table row — `phase.add` writes neither. |
| `phase.add` infers a wrong `Depends on` | It wrote `Depends on: Phase 12` for Phase 13 purely from sequence. Phase 13 actually depends on Phase 11 and is independent of Phase 12. | advisory | Always set `Depends on` by hand after `phase.add`, from the real dependency, not the phase number. |
| Prose in the `**Requirements**:` line is parsed as requirement IDs | Writing `Requirements: DASH-07 (the half split out of DASH-01...)` made `init.plan-phase 13 --pick phase_req_ids` return the whole sentence as the ID list. | advisory | Keep `**Requirements**:` to a bare comma-separated ID list. Put explanation on a separate `**Requirements note**:` line. Verify with `bm-sdk query init.plan-phase N --pick phase_req_ids`. |
| Broad `TBD`/`placeholder` grep produces false "incomplete" hits | The pause-work false-completion scan flagged 18 files across Phases 9/10/10.1, all of which are Complete with verification passed — the grep matches the literal string `TBD` appearing in normal prose. | advisory | Treat that scan as a pointer, not a verdict. Check the file's actual status before reporting it as an incomplete summary. |
