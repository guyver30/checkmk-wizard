<decisions>
## Implementation Decisions

### Retag entry point
- **D-01 (LOCKED):** The retag flow is **detection-driven, not a menu or a CLI flag.** During a
  normal wizard run the wizard checks whether already-onboarded hosts carry no device type (tag
  absent) or the neutral default, and if any are found it asks the operator whether to retag
  them. Declining is a first-class outcome: those hosts simply stay at the neutral value. The
  per-host prompting reuses the same flow already used when tagging newly created hosts, so the
  operator sees one consistent interaction rather than a second, separate tagging UX.
  - Operator's words: *"the wizard should check if existing hosts don't have any tag (or just
    have unknown tag) and ask user if wants to retag them. Same flow like creating new hosts and
    then ask to tag them (or not, which means they will get unknown or other tag)"*
  - Explicitly rejected during this decision: a startup `questionary` menu branch, and a
    `--retag` CLI flag. Both were offered and both were turned down in favour of detection.
  - Consequence the planner MUST handle: this touches the Phase 4 classification prompt
    sequence, which `tests/test_wizard.py` drives with hardcoded answer iterators. Phase 10-04
    already had to repair every one of these when it added the device-type prompt; the same
    blast radius applies here and must be planned for, not discovered during execution.

### Terminology (inherited from Phase 10, binding)
- **D-02 (LOCKED):** The neutral device-type value is **`other`**, listed first in the tag
  group's choice list (Phase 10 decisions D-06/D-07). `unknown` is NOT the untagged value — in
  `scripts/mqtt_poller.py` it means the tag group itself is missing. Detection for D-01 must
  therefore match **device_type absent OR device_type == `other`**, which is what the operator
  meant by "don't have any tag (or just have unknown tag)".

### Retag scoping
- **D-03 (LOCKED):** Folder scoping is **exact-match only** — retagging a folder touches only
  hosts whose folder is exactly the one selected, never hosts in sub-folders. Rationale: a
  single confirmation must never rewrite tags on hosts that were not displayed to the operator.
  Nested folders are handled by selecting each one.

### Claude's Discretion
- Where precisely in the phase sequence the detection check runs (start of Phase 4 vs. after
  Phase 3 discovery), and how thecandidate list is presented (table, per-host prompt, or
  select-many) — provided D-01's "same flow as new hosts" constraint holds.
- Whether the retag path issues one REST call per host or batches, and how it reports partial
  failures — subject to the codebase's existing best-effort/graceful-degradation convention.
- OPS-03's concrete retry values and backoff shape.
- Test structure for the new flow.

</decisions>
