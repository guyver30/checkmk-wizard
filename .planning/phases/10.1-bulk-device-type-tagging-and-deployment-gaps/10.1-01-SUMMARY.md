**What the operator must do**, from the deployment host with the real stack running:

1. Get the automation user's secret: Checkmk UI → Setup → Users → `automation` → Automation secret, or on the checkmk host/container read `/omd/sites/dmc/var/check_mk/web/automation/automation.secret`.
2. Run the probe. From inside the worker container (reaches `checkmk:5000` on `cmk_net`):

   ```
   cd <checkout>/deploy && podman compose exec -e CMK_REST_USERNAME=automation -e CMK_REST_SECRET='<secret>' worker python3 /app/checkmk-wizard/scripts/probe_host_attribute_merge.py
   ```

   Or from the host if port 5000 is published:

   ```
   cd <checkout> && CMK_REST_HOST=localhost CMK_REST_PORT=5000 CMK_SITE_ID=dmc CMK_REST_USERNAME=automation CMK_REST_SECRET='<secret>' uv run python scripts/probe_host_attribute_merge.py
   ```

3. Before pasting anything back, confirm the automation secret does not appear anywhere in the printed output (the script is written not to print it).
4. Paste back the full `[P1]`..`[P7]` output, especially the `VERDICT:` line, the P5 removed/changed/added key sets, the `ECHO-PUT:` line (plus rejection body and rejected key names if `REJECTED`), and P7's delete status.
