# Phase 10.1 Plan 02: Deployment and Observability Gaps Summary

**Worker container gets REST credentials, the wizard shows its generated automation secret on both deployment paths, and the poller survives a container-restart race with a bounded retry plus a startup log line.**

## Performance

- **Duration:** 12 min
- **Started:** 2026-09-12T03:31:00Z (approx, first read)
- **Completed:** 2026-09-12T03:43:46Z
- **Tasks:** 3
- **Files modified:** 4

## Accomplishments
- `worker` service in `deploy/compose.yaml` now carries the same four `CMK_REST_*` variables the `poller` service already had, so a wizard re-run or `scripts/probe_host_attribute_merge.py` executing inside the worker container needs no hand-pasted secret
- The wizard prints the generated `automation` user's secret with `deploy/.env`/`CMK_REST_SECRET` instructions at the moment it's created, on both the container-mode branch and the previously-broken host-native `_create_fresh_site` path (which used to discard the secret entirely)
- The poller's one-time startup Livestatus column probe now retries up to 3 times (5s/10s/15s backoff) before failing, so a Checkmk container restart racing the poller's start no longer kills it — a real failure mode observed live during Phase 10's own verification run
- A permanently unreachable Livestatus site still fails loudly after all 4 attempts, and the deliberate asymmetry with REST's non-fatal posture is documented in-source as considered-and-rejected
- A healthy poller now logs `Poller started: site=... poll_interval=...s broker=host:port` at INFO level, distinguishing it from a hung one in `podman logs`

## Files Created/Modified
- `deploy/compose.yaml` - added `CMK_REST_HOST/PORT/USERNAME/SECRET` to the `worker` service's environment block (additions only, no deletions)
- `src/checkmk_wizard/wizard.py` - added `_print_automation_secret_created()` helper; wired it into both the container-mode branch and `_create_fresh_site` (which now returns the secret instead of discarding it, `-> str | None`); the `else` branch call site now builds `site.SiteCredentials` from the returned secret
- `scripts/mqtt_poller.py` - added `_STARTUP_RETRY_DELAYS_SECONDS = (5, 10, 15)`, `import time`, a bounded retry loop around the startup `available_host_columns`/`select_host_columns` probe in `run_forever`, updated its docstring, and an OPS-04 `_logger.info("Poller started: ...")` line right after the probe succeeds
- `tests/test_mqtt_poller.py` - patched `poller.time.sleep` into the existing fatal-startup test (previously incurred real backoff delay), added `test_run_forever_startup_probe_retries_then_recovers`, `test_run_forever_startup_probe_retry_exhausted_is_fatal`, and `test_run_forever_logs_startup_success`

## Decisions Made
- Kept the retry as a plain module-level tuple iterated inline (no retry decorator, no backoff library), mirroring `wizard.py`'s existing `_DISCOVERY_RETRY_DELAYS_SECONDS` convention rather than introducing a new pattern.
- Factored the OPS-02 secret-display message into one shared helper function so only one literal needs reviewing for the secret-handling constraint (T-10.1-07), rather than duplicating the f-string at both call sites.
