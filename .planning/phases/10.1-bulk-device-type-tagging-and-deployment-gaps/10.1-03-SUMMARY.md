## Decisions Made
- Followed the plan's REPLACE-branch instruction literally: comment at the PUT-body construction site cites `scripts/probe_host_attribute_merge.py`, its 2026-09-12 run date, and the verdict word `REPLACE`.
- Used `respx` + a real `CheckmkClient` for every new flow test instead of `unittest.mock.AsyncMock`, since that is this file's exclusive existing convention (grep confirmed zero prior `AsyncMock`/`MagicMock` usage) — simpler and more consistent than introducing a new mocking style for one plan.
- Test-writing revealed the "blank alias omits the key" instruction needed nuance: because the PUT body is the host's *full* attribute dict (REPLACE, not a two-key partial), a pre-existing `alias` key is naturally preserved unchanged when the answer is blank — it is not "omitted" from a full dict that already contains it. Split this into two assertions: no alias key is invented when the host had none, and an existing alias key survives untouched when the host had one. Both are still faithful to D-09's intent (blank means keep current alias).
- Renamed the wiring-regression test's local variable from `scanned` to `scan_results` at its call site (`phase4_classification(scan_results)` instead of `phase4_classification([scanned])`) so the new test would not collide with the acceptance-criteria grep counting exactly 7 pre-existing `phase4_classification([scanned])` occurrences — a cosmetic naming choice with no behavioral difference, since it's the same one-item list either way.

## Post-checkpoint revisions (D-10 through D-13)

Task 3's `human-verify` checkpoint did not just approve the implementation —
it produced four operator decisions that replaced the prompt layer this plan
specified. Everything above describes Tasks 1-2 as originally built; this is
what actually shipped. The plan's Task 1 step (f) and its detection rule are
superseded, not merely reinterpreted.

| Decision | Supersedes | What changed |
|----------|-----------|--------------|
| D-10 | Plan Task 1 step (f) prompts | Per-host `questionary.select` replaced by a numbered legend + single-digit entry, with an "N will be retagged, M unchanged" summary gated behind one default-No `Apply?` confirm. Rationale: 20 hosts cost 40 interactions, and "a few of each type" is the normal case. |
| D-11 | Plan Task 1 step (f) alias prompt | Alias left the per-host loop and became an opt-in second pass: one confirm, a checkbox over the just-retagged hosts, then a text prompt per checked host. D-09 still governs the body — blank omits the key rather than clearing it. |
| D-12 | **D-02** | Every onboarded host is a retag candidate regardless of its current device type. The "absent or `other` only" rule left a host tagged *wrongly* unreachable through the wizard. `_untagged_host_candidates` renamed `_retaggable_hosts`; it now filters only on `exclude_names`. |
| D-13 | **D-10's per-host prompt** | A folder is edited in one full-screen `prompt_toolkit` list: Up/Down moves a clamped cursor, a digit assigns that type to the row under it, `[A]` applies and exits, `[D]` discards and exits. Apply writes the folder then asks about the next; discard restarts the entire flow from its first prompt and re-fetches the host list. |

Two further fixes came out of the same live run and are not in the plan at all:

- **Phase 3's network scan is now optional.** Re-running the wizard against an
  already-built-out site forced a full sweep that staged every live IP as a
  duplicate placeholder, when the operator had only come back to retag.
  Declining returns an empty `scan_results`, which Phase 4 already handled.
- **`README.md` and `docs/WIZARD-OPERATION.md` documented host-native mode
  only**, so the container-mode invocation
  (`podman exec --interactive --tty automation-worker ...`, including why
  `uv sync` belongs in it) had to be rediscovered every run. Both now carry it.

### Structural consequences

- `_prompt_device_type_number` was added by D-10 and orphaned by D-13; removed.
- `_write_host_attributes` was extracted once the type write and the alias
  write both needed the GET-merge-PUT path, keeping the REPLACE-verdict
  handling and the fresh-per-host ETag in one place rather than duplicated.
- `RetagSelection` exists because a full-screen `prompt_toolkit` application
  cannot be driven by the prompt-stubbing every other test in this file uses.
  The cursor and assignment rules live there as pure state and are unit-tested
  directly; the key bindings are covered separately by driving the real
  `Application` through `create_pipe_input` + `DummyOutput`. Without that
  second layer the bindings would have had zero coverage — a broken key would
  still have passed every other test in the suite.
