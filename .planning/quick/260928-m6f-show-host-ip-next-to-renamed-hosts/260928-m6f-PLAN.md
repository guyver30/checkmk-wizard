Operator decisions (locked 2026-09-28). They are referenced below as OD-1..OD-5:
- OD-1 Rule: show the IP whenever displayName(device) (the trimmed alias if set, otherwise the id) is not equal to the host's address.
- OD-2 Show no IP when the address is empty or missing (unmanaged switches, or payloads from an older poller). Old payloads must render exactly as they do today.
- OD-3 Device tree: IP as a hover tooltip on the host name (`title` attribute).
- OD-4 Incident cards (root label and the "View devices" names), topology map node labels and event history rows: `name (ip)`, e.g. `router (192.168.0.1)`.
- OD-5 Host details pane header: planner's call. Decision: show `name (ip)` there too, for consistency.

Planner decision (the operator left this open: "status payload and/or topology node"): carry `address` ONLY on the per-device status payload (`lan/devices/{id}/status`). Rationale: every dashboard name site already reads the status payload through `displayName(devices[id])`. The map's `buildMapModel` falls back to the topology entry only when no status exists yet, and it will show the bare name there, as today. Leaving `address` off the topology node avoids widening `topology_signature()` and `_normalise_restored_node()`, and avoids a forced topology republish on upgrade. Do NOT add `address` to `topology_nodes()`, `topology_signature()` or `_normalise_restored_node()`.

| T-m6f-01 | Denial of Service | query_devices address parse | mitigate | try/except (IndexError, TypeError) plus an isinstance-str fallback to "", so a malformed row cannot crash the poll cycle |
| T-m6f-02 | Tampering | dashboard rendering of address | mitigate | displayAddress type-guards to a string; the value is rendered as React text or a title attribute (auto-escaped), never as HTML |
