## Planner choices (Claude's discretion, record in SUMMARY)

- Spacing: `MAP_SNAP_SPACING = GRID_SPACING / 3` (= 50) in topologyLayout.ts. GRID_SPACING (150) is the
  auto-layout spacing, so every auto-layout slot sits exactly on a grid intersection, while 50px gives
  enough resolution to line hosts up (nodes are size 16; a 150px snap would be too coarse to arrange a
  dense map). The drawn grid uses the same 50px spacing so what you see is what you snap to.
- Theme: the map does NOT use theme tokens today -- NETWORK_OPTIONS hard-codes hex colours
  (`#111114`, `#96969f`, `#1450f5`) and the canvas container is a fixed `bg-white`; grep of
  `dashboard-react/src` finds no dark theme. So the grid uses one hard-coded faint neutral hex
  constant (`GRID_LINE_COLOR = "#ececef"`, a light neutral close to the container border tone)
  beside NETWORK_OPTIONS, consistent with how the map already colours itself. No theme plumbing.
- Hint placement: inside TopologyMap (absolutely positioned overlay, bottom-left of the canvas, so it
  does not collide with vis-network's manipulation toolbar at the top), rather than TopologyToolbar.
  This keeps it next to where edges are actually drawn and testable in TopologyMap.test.tsx. It is
  rendered only when `editMode` is true (the map only renders its canvas when hasNodes, so the hint
  belongs in the canvas branch of the JSX, not the empty state).
