<objective>
Fix the live-verified 401 "There are changes from other users and foreign changes are not
allowed in this API call" failure that aborts activation in Phase 6 and Phase 7.

Root cause (confirmed by reading the code, no investigation needed): Phase 1's container-mode
branch creates/updates the `automation` and `agent_registration` users while authenticated as
**cmkadmin** through the GUI session-cookie flow, producing pending WATO changes attributed to
cmkadmin. Phases 2-5 then run as the **automation** REST user. When
`_activate_pending_changes()` (`src/checkmk_wizard/wizard.py:1682-1698`) activates as
`automation`, Checkmk sees cmkadmin's leftover changes as foreign and rejects the whole
activation, because the call omits `force_foreign_changes` and `CheckmkClient.activate_changes()`
(`src/checkmk_wizard/api.py:270-286`) defaults it to `False`.

Purpose: cmkadmin (bootstrap only) and `automation` (everything else) are two accounts acting
for the *same* operator in the *same* wizard run — there is no other real operator to protect
against, so forcing the activation through is the correct behavior, not a workaround.

Output: one-keyword change at the single wizard call site, a stale comment in `api.py` brought
back in line with the new behavior, and a regression test.

Scope guard: do NOT add a CLI flag, config option, env var, or interactive prompt to control
this. It is unconditional. Do NOT change `CheckmkClient.activate_changes()`'s signature or its
`False` default — the API layer is already correct and its `force_foreign_changes` body key is
live-verified; other callers (the cmkadmin self-activation inside `bootstrap_automation_user`)
must keep `False`.
</objective>
