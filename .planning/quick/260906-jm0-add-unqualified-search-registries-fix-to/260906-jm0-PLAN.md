<factual_content>
<!-- Ground truth for the new text. Do not embellish beyond this. -->

Symptom (verbatim error the reader sees at §4):
    Error: short-name "checkmk/check-mk-raw:2.4.0-latest" did not resolve to an alias
    and no unqualified-search registries are defined in "/etc/containers/registries.conf"

Which images fail: `checkmk/check-mk-raw:2.4.0-latest`, `eclipse-mosquitto:2`,
`minio/minio:latest` — all three services fail. `python:3.12-slim` (the `worker`) is the
only one that succeeds, because Podman ships a built-in shortname alias for it in
`/etc/containers/registries.conf.d/shortnames.conf`; the other three have no such alias.

Why it happens: a fresh Podman install has no `unqualified-search-registries` configured
anywhere, and rootless Podman deliberately refuses to guess a registry for an unqualified
short name rather than risk resolving to a typosquatted image. This is a default, not a
bug or a broken install.

Note also: §1.1's own verify step already uses the fully-qualified
`docker.io/library/hello-world`, which is why the install verifies clean and the failure
does not surface until §4.

The fix — create the rootless per-user override, which takes precedence over any
system-wide `/etc/containers/registries.conf`:

    mkdir -p ~/.config/containers
    cat > ~/.config/containers/registries.conf <<'EOF'
    unqualified-search-registries = ["docker.io"]
    EOF

Recovery: just re-run `podman compose up -d`. No cleanup is needed — the three failed
services never got as far as creating a container object (they failed at the `podman run`
step itself, exit code 125), and any volumes or the `cmk_net` network that podman-compose
already created are reused as-is on retry.
</factual_content>
