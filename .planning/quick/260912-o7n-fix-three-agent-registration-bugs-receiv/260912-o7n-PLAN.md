<objective>
Fix three agent-registration bugs diagnosed live on 2026-09-12 against a containerized
Checkmk site (Podman, REST/GUI published on host port 8080) while registering the Linux
host `agent-test`:

1. `cmk-agent-ctl register --server` carried no port, so the agent tried to auto-discover
   the agent receiver port via the Checkmk REST API on 80/443 and failed.
2. In container mode the registration address defaults to the container-internal DNS name
   `checkmk`, which no LAN target can resolve — the existing loopback guard did not catch it.
3. Printed manual Linux registration instructions omitted `sudo`, so a copy-paste of them
   fails.

Purpose: registration must work on the deployment the operator actually runs, and the
manual fallback text must match what the automated path really does.
Output: surgical fixes in `remote.py` + `wizard.py`, plus regression tests in both test files.
</objective>

  <action>
    Add `import ipaddress` to remote.py's stdlib imports (needed only for the IPv6
    disambiguation below).

    Add a module-private helper `_server_with_receiver_port(server: str) -> str` next to
    the register-command builders. Logic, in order:
      1. If `server` parses via `ipaddress.ip_address(server)`: an IPv6 address returns
         `f"[{server}]:{AGENT_RECEIVER_PORT}"`, an IPv4 address returns
         `f"{server}:{AGENT_RECEIVER_PORT}"`. (This branch is what stops a bare `::1`
         from being read as "host `::` port `1`".)
      2. Else if `server` starts with `[`: return it unchanged when it already has `]:`
         followed by digits, otherwise append `:{AGENT_RECEIVER_PORT}` after the `]`.
      3. Else `rsplit(":", 1)`: if there are two parts and the second is all digits,
         return unchanged (an explicit port is already present).
      4. Otherwise append `f":{AGENT_RECEIVER_PORT}"`.
    Keep it that small — do NOT make the port configurable (CLAUDE.md §2); the existing
    `AGENT_RECEIVER_PORT` constant is the single source of truth and is already used by
    the port probe and the ufw rule.

    Give the helper a docstring recording *why* it exists, in the repo's established
    citation style: when `--server` carries no port, `cmk-agent-ctl` first queries the
    Checkmk REST API to discover the agent receiver port over http then https; on a
    deployment whose REST/GUI is published on a non-standard port (observed: host port
    8080 under Podman) that discovery fails with
    `Failed to discover agent receiver port from Checkmk REST API, both with http and
    https`. The documented remedy is to specify the port explicitly to bypass discovery —
    cite `docs.checkmk.com/latest/en/agent_linux.html`, section "Network environment for
    registration". Include a `Bug fixed 2026-09-12` post-mortem line following the
    precedent at src/checkmk_wizard/site.py:191-202.

    In `linux_register_command`, wrap the server value:
    `--server {shlex.quote(_server_with_receiver_port(server))}` — the quoting must stay
    on the OUTSIDE so it covers the appended port. Do the equivalent in
    `windows_register_command` with `_ps_quote`.

    Bug 3 (remote.py's share): in `register_agent_linux`, change the manual string to
    `f"Run on the target host: sudo {register_cmd}"`; in `install_agent_linux`, change
    step 3 to `f"3. Run on the target host: sudo {register_cmd}"`. Add a short comment at
    one of the two sites noting the automated path already elevates via `_run_sudo()`,
    so sudo belongs in the printed fallback text only — baking it into
    `linux_register_command()` would double-elevate. Do NOT touch
    `windows_register_command` for sudo.

    Per repo convention, each new regression test gets a comment naming the real bug it
    guards (precedent: tests/test_wizard.py:80-92).
  </action>
