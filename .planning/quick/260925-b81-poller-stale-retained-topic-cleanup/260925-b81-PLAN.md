<objective>
Make the MQTT poller clean up retained `lan/devices/{id}/*` topics that have no matching Checkmk host, so rebuilding the Checkmk site no longer also requires wiping the Mosquitto volume. Then update the Podman doc (section 8.5 and the topic contract) to match.

Purpose: the dashboard reads only retained MQTT messages. Today the poller tombstones a device only when the id is in `state.previous_nodes` (seeded from the retained `lan/devices/topology`) and missing from the current snapshot. Per-device topics whose id is NOT in the retained topology are never cleared. That happens when the topology message was overwritten, when `reconcile_state` timed out before the topology arrived, or when a tombstone publish failed. Those topics become permanent ghosts.
Output: poller sweep with a safety gate, tests, updated docs.
</objective>

2. `reconcile_state`:
   - Add subscriptions for `lan/devices/+/status` and `lan/devices/+/services` next to the existing history/service_history wildcards.
   - Reorder so all four per-device wildcard subscriptions are sent BEFORE `TOPIC_TOPOLOGY`, which is subscribed last. Rationale for the comment: Mosquitto queues a subscription's retained messages when it handles that SUBSCRIBE. Packets on one connection are handled and delivered in order. So once the topology message arrives, the earlier wildcards' retained messages have already been delivered, and the existing `topology_received.wait` becomes a sufficient barrier for them too. Label this in the comment as an assumption about broker ordering that has not been verified live.    - Pass `retained_ids=retained_ids` into the returned `PollerState`.
   - Add one short sentence to the docstring about the new collection.

3. `run_cycle`:
   - Add a keyword parameter `allow_stale_sweep: bool = False`. Existing callers and tests keep today's behavior.
   - After the existing removed_ids loop, if `allow_stale_sweep` is true, compute `stale_ids = state.retained_ids - current_ids - previous_ids`. Subtracting previous_ids avoids a double tombstone, because the removed loop already handles those ids.

   - Then set `state.retained_ids = set()`. The sweep runs once per process; after that, `previous_nodes` takes over tracking.
   - When the gate is off, leave `state.retained_ids` untouched so a later cycle can sweep.
   - Extend the docstring with the gate contract.

4. The gate itself, answering "how is an intentionally empty site told apart from a failed query":

So it is only trusted when this cycle's REST `fetch_host_config` succeeded AND returned an empty dict, which independently confirms there are zero configured hosts.

   - Comment the gate with the reasoning above. Also note that when `CMK_REST_SECRET` is unset, REST always fails, so an empty site simply never sweeps. That is the safe direction.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broker -> poller (reconcile) | Retained topic names and payloads are read from Mosquitto, and any client with publish rights could have written them (ACL limits publishing to the `poller` user) |
| Livestatus/REST -> poller | Host list used to decide deletion; outages or partial startup can return misleading results |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-q260925-01 | Denial of Service | run_cycle stale sweep | mitigate | Sweep runs only when snapshots are non-empty, or when REST succeeded this cycle with zero hosts. A LivestatusError skips the cycle, so a transient outage cannot wipe the dashboard (tested) |
| T-q260925-02 | Tampering | reconcile_state id parsing | mitigate | Only exact 4-segment `lan/devices/{id}/{status,history,services,service_history}` topics with a non-empty payload and an id passing `is_publishable_device_id` are collected; the tombstone targets only the four fixed per-device topics |
| T-q260925-03 | Denial of Service | sweep deletes a live host | mitigate | `stale_ids` subtracts current snapshot ids; if the subscribe-ordering assumption fails, an id is merely missed, never wrongly removed |
