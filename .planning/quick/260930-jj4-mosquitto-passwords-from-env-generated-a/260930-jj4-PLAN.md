eclipse-mosquitto:2 image (source: github.com/eclipse-mosquitto/mosquitto, branch master,
docker/2.0-openssl/Dockerfile + docker-entrypoint.sh; VERSION=2.0.22, alpine:3.23):
- No USER directive: the container starts as root. User/group `mosquitto` = uid/gid 1883
  (addgroup -S -g 1883 / adduser -S -u 1883).
- /mosquitto/config, /mosquitto/data, /mosquitto/log are created in the image and chowned
  to mosquitto; only /mosquitto/data and /mosquitto/log are VOLUMEs. /mosquitto/config
  itself is an ordinary image-layer dir (compose bind-mounts only the individual
  mosquitto.conf / mosquitto.acl files into it), so a root process in the container can
  create /mosquitto/config/mosquitto.passwd in the writable container layer.
- ENTRYPOINT ["/docker-entrypoint.sh"], CMD ["/usr/sbin/mosquitto", "-c",
  "/mosquitto/config/mosquitto.conf"]. docker-entrypoint.sh (#!/bin/ash, set -e): if
  `id -u` is 0 it runs `chown -R mosquitto:mosquitto /mosquitto || true`, then `exec "$@"`.
- mosquitto_passwd ships in the image (the old deploy/gen-mosquitto-passwd.sh ran
  `podman run --rm --user 0:0 ... eclipse-mosquitto:2 mosquitto_passwd -b -c <file> <user> <pw>`
  then `mosquitto_passwd -b <file> <user> <pw>`).

Mosquitto 2.0.22 password-file checks (source: tag v2.0.22):
- src/mosquitto.c: drop_privileges() (line ~526) runs BEFORE mosquitto_security_init()
  (line ~556), so the password file is opened as uid 1883, not root.
- common/misc_mosq.c mosquitto__fopen(restrict_read): warns "File ... has world readable
  permissions. Future versions will refuse to load this file. To fix this, use
  `chmod 0700`" when (st_mode & S_IRWXO) != 0, and warns "File ... owner is not
  <user>" when st_uid != getuid(). Therefore the file must be owned by mosquitto (1883)
  and have no "other" bits: chown mosquitto:mosquitto + chmod 0700.

Compose conventions already in deploy/compose.yaml:
- Inline shell uses `$$VAR` so compose passes a literal `$VAR` to the container shell
  (see minio-init `command:` and grafana `entrypoint:` list form ["/bin/sh","-c", >- block]).
- The grafana comment (around line 195) explains the repo has so far AVOIDED
  `${VAR:?}` because compose interpolates the whole file before selecting services, so a
  missing value blocks every service (10-REVIEW CR-01). This plan deliberately uses
  `${VAR:?}` per the user-approved design (see Task 1); the comment must say so.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git repo -> deployment host | tracked files are public to anyone with the repo; per-machine secrets must not be tracked |
| deploy/.env -> containers | compose interpolates secrets into container env (visible via `podman inspect` to the host user) |
| LAN -> mosquitto 1883/9002 | unauthenticated network clients attempt broker login |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-jj4-01 | Information disclosure | deploy/mosquitto.passwd tracked with default creds | mitigate | git rm the file and the gen script; passwords generated per machine by init-env.sh (32 chars urandom) into the 0600 .env |
| T-jj4-02 | Spoofing | broker login with known default poller/poller or wsreader/wsreader | mitigate | `${VAR:?}` on mosquitto/poller/dashboard removes every compose-level default; operator live check confirms poller/poller is refused |
| T-jj4-03 | Information disclosure | password file inside the mosquitto container | mitigate | umask 077, chown mosquitto:mosquitto, chmod 0700 (no world bits), in the container layer only, never on the host |
| T-jj4-04 | Information disclosure | secrets in container env (`podman inspect`) | accept | same exposure as every other secret in this stack (CMK_REST_SECRET, CH_*); only the host user who owns rootless podman can inspect |
| T-jj4-05 | Tampering | shell injection via password value in the start-up command | mitigate | values are quoted "$$VAR" in the container shell and gen_secret emits only [A-Za-z0-9_-]; .env.example keeps the allowed-characters warning |
| T-jj4-06 | Denial of service | missing .env value blocks the whole `compose up` (incl. checkmk) | accept | user-approved design; error message names deploy/init-env.sh, which is the documented first step |
</threat_model>
