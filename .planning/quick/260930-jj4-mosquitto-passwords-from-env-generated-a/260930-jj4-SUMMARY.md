# Quick Task 260930-jj4: Mosquitto Passwords From deploy/.env Summary

**Both Mosquitto broker passwords (`poller`, `wsreader`) moved out of the tracked `deploy/mosquitto.passwd`/`deploy/gen-mosquitto-passwd.sh` into `deploy/.env`, generated by `deploy/init-env.sh`; the `mosquitto` container now builds its own password file from those two variables at every start, and `compose up` refuses to start without them.**

## Performance

- **Duration:** ~55 min
- **Tasks:** 3 completed
- **Files modified:** 12

## Accomplishments

- `deploy/init-env.sh` generates `MQTT_POLLER_PASSWORD` and `WS_PASSWORD` alongside the stack's other secrets, never overwriting a value already set.
- `deploy/compose.yaml`'s `mosquitto` service has a new `entrypoint:` that runs `mosquitto_passwd -c`/`-b` for the `poller`/`wsreader` users from the two env vars, `chown mosquitto:mosquitto` + `chmod 0700`s the result, then `exec`s the image's own `/docker-entrypoint.sh` + CMD -- the password file lives only in the container's writable layer, never bind-mounted, never on the host.
- `mosquitto`, `poller` and `dashboard` all read `MQTT_POLLER_PASSWORD`/`WS_PASSWORD` via `${VAR:?run deploy/init-env.sh}`, so a missing value fails `compose up` with a message naming the fix, rather than silently falling back to `poller`/`poller` or `wsreader`/`wsreader`.
- `deploy/mosquitto.passwd` and `deploy/gen-mosquitto-passwd.sh` are removed from git; nothing creates the former on the host any more, so no `.gitignore` entry was added.
- `scripts/smoke_test_broker.py`/`scripts/smoke_test_poller.py` default their password CLI flags from the same two environment variables (falling back to the old dev values only when unset).
- `dashboard-react/src/lib/config.ts`, `dashboard-react/README.md` and `deploy/dashboard-nginx.conf` comments updated -- production `WS_PASSWORD` now comes from `deploy/.env` via `/config.json`; the dev-only `DEFAULT_WS_*` fallback in `config.ts` is unchanged.
- `docs/DEPLOY-NEW-MACHINE.md`, the Podman setup doc, and `docs/WIZARD-OPERATION.md` all updated: new required-variable table rows, an existing-machine migration note (`git pull` -> re-run `deploy/init-env.sh` -> full `down`/`up`), rotation instructions, and a troubleshooting line for the generated password file's ownership/mode.
- Repo-wide grep gate confirms no tracked file outside `.planning/`/`PROMPT_LOG.md` still names `gen-mosquitto-passwd`, `deploy/mosquitto.passwd`, `poller/poller`, `wsreader/wsreader`, or `-P poller`.
